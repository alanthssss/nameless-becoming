# 花间一着：游戏方案与完整短章

2026-10-19。Alan 在原始需求回溯后说“不限玩法 你出一个游戏”，授权 Codex 选择玩法。**Codex 选择回合制生态冒险并制作完整短章；最新反馈为“感觉没啥意思”，当前体验未通过，停止扩展并复议核心。** 以下保留方案及实验记录，不作为继续扩产的依据。唯一执行状态仍见[制作规格 §0.11 Now](solar-term-campaign-production-spec.md#011-2026-09-09-核心循环实验与矩阵细化)。

## 这个游戏

你在梦中成为一只蜂。世界变成花叶、草茎和动物生活的巨大迷宫。你不知道自己属于什么角色，先学会在这个世界行动：看懂风、找到落脚处，利用别的动物各自的习惯，把堵住自己的局面变成新路。

**卖点：用自己的下一步，改变对方下一步的结果。** 一张场景就是一次完整遭遇；玩家看得到危险的意图，但决定用什么办法通过。停下来思考很轻松，作出一个漂亮的判断会有成就。角色的脾气和处境体现在它如何行动、占据什么地方、留下什么变化，而不是长篇独白。

工作名《花间一着》用于区分新实验。保留 Godot、单机、中文、四季生态与主角见闻作为创作基础。具体正式游戏的篇幅、售价、平台包与排期未在本轮承诺；原全年规划留作历史，不把这份短章默认为正式游戏全部内容。

## 玩家具体做什么

观察已锁定的动物动作与风 → 选择飞行、栖停或等待 → 看见动物动作打开通路／破坏落脚处、风改变位置 → 利用新局面继续前进。

| 行动或规则 | 得到什么 | 付出与选择 |
| --- | --- | --- |
| 飞行到附近一个位置 | 跨过空隙、离开危险、接近脆枝诱导下一次动作 | 这一拍悬空，动物先行动，随后受风推动；飞得远不总是安全 |
| 在当前叶片栖停 | 固定位置、躲到叶荫下，画眉啄扫会被遮住 | 用掉这一拍，不能同时移动；油葫芦仍能压下薄叶 |
| 保持姿态等一拍 | 等待动物动作、风向和通路变化 | 悬空仍受风；等待可能失去叶片，不是无条件安全按钮 |
| 把下一次啄扫／跳落引到脆枝附近 | 动物动作真正破坏障碍，出现新路线 | 要先接近并把握下一拍的退路；也可保留障碍从旁边绕过 |
| 撤回与重开 | 试验不同办法，理解规则 | 不收取资源，也不把失败变成重复刷取 |

所有动物按预告结算。界面直接显示锁定范围，悬停预览与执行共用规则。行动顺序固定；身体被碰到和被风推向边界会损失体力，体力耗尽可撤回。到白花时仍须活着，不能靠最后一击穿过失败状态。

核心乐趣假设是“看懂对方的行动，再让它为自己的路线创造机会”。这只是设计假设。若玩家持续无脑向出口飞就足够、或每关只有一个照抄答案，核心不成立；故事、美术、装备和更多关卡不能补救。

## 第一次完整体验：四段连续遭遇

| 段落 | 玩家遇到什么 | 可感知的进展 |
| --- | --- | --- |
| 风会送你一程 | 从叶片醒来，试飞并观察同样的动作如何被风改变 | 能预判风的落点，亲自抵达第一朵白花 |
| 油葫芦的跳台 | 油葫芦不断练跳，压下叶片，也会折断脆枝 | 可借它打开近路，也能走原来的绕路；一次选择改变地形 |
| 画眉在看哪里 | 啄扫、抖翅、停顿依次发生 | 学会利用叶荫，并把下一次啄扫引向挡路脆枝 |
| 花地就在那边 | 画眉、油葫芦和风共同构成局面 | 可以保留脆枝走下方，也可打开近路；老师傅跟随主角进入新花地，短章结束 |

这四段使用同一组动作，复杂度来自组合而非连续发新按钮。当前短章没有计时压力、装备数值、采集背包、运输配额、每日交差或长距离返回。实际游玩时长等待真人测量，不用“十五天”或估计分钟数冒充内容量。

画眉的目标是通过它占据的花枝，并不要求打掉血条或净化动物。它仍按自己的习惯活动。油葫芦在路被打开后继续练跳，不转化为负责发任务的 NPC。对白短，结果必须先由玩家操作产生。

## 如果这套玩法成立，正式游戏怎样从头到尾展开

以下是同一游戏的候选结构，不是已生产内容或新增待办队列。

| 章节 | 故事变化 | 同一套玩法如何变化 |
| --- | --- | --- |
| 春：学会看路 | 从跟随别人的新蜂，到首次发现花地 | 读懂个体动物与风，学会利用局面；建立角色的习惯与生活场所 |
| 夏：各有各的地方 | 花源热闹，原来顺畅的路开始与其他生命交错 | 多个动物意图互相影响；一条路打开可能关闭另一条，需要安排顺序 |
| 秋：为后来留下什么 | 花期变化，熟悉的角色各自为寒冷作准备 | 场景中此前保留的枝叶与通路产生后续用途；选择改造哪里、保留哪里，不以善恶分数结算 |
| 冬：在蜂群里面 | 活动转入蜂巢，主角不再独自找路 | 将位置、节奏和让路用于蜂群协作，温暖来自实际相互依赖；走到下一次春日，主角已经能带别人行动 |

四种原始动物角色继续作为创作素材，但不强行给每一季分配一个“邪恶 Boss”。不把工蜂升级成蜂王当作成长；成长优先表现为玩家掌握了什么、看懂了谁，以及其他角色怎样回应这些行动。未知身份可以成为开端，结尾无需靠天选身世或主题独白证明价值。

章节之间需要可探索的短连接场景与角色相遇，具体密度由短章实玩决定。每个新场景必须带来可说明的新局面或剧情后果，不能只扩大格子、提高血量或增加走路距离。先以紧凑场景成立为前提，尚未决定全面开放地图、随机生成或成长经济。

## 原始需求如何进入这次取舍

- 身份、角色见闻与有温度的动物来自[需求底稿 S13–S16](original-requirements-recovery-20261019.md)；回合制是 Codex 此次提出的解法，不伪称原始指定类型。
- S17 的“具体玩法、以角色为核心、生态与趣味共同成立”落实为可操作规则；低操作负担通过停下来思考和无限撤回实现，不靠取消所有挑战。
- “主要赶路、搬东西、没有期待”的直接反馈，落实为每场遭遇的局面变化与明确收束。
- 温暖与主题依靠角色生活、行动结果和短回应表达；正式四季结构保留内容发展的空间，当前先验证一段完整经历。

## 自然依据与艺术抽象

工蜂采集花蜜／花粉以及通过舞蹈传达花源信息可参阅 [UF/IFAS 蜜蜂项目资料](https://ask.ifas.ufl.edu/publication/4H419)与 [NC State 蜂舞介绍](https://content.ces.ncsu.edu/honey-bee-dance-language)。本轮仅用作题材边界，不将蜂舞编为远程控制其他蜂的魔法。

回合、攻击预告、固定步幅、叶荫免伤、动物折断脆枝与风的周期都是游戏抽象，未声称符合某物种精确行为。本原型没有蜂刺普攻、蜂王浆药水、授粉后瞬间开花或把所有蜂类生命周期混用。以后增加具体生态规则，应逐项核查来源。

## 实现与验证边界

独立工程：[prototypes/flower-step](../../prototypes/flower-step/README.md)。引擎实测为 Godot `4.6.2.stable.official.71f334935`。规则模型与 UI 分开；预览、执行与自动搜索使用相同状态转移。旧商业启动场景、旧存档与导出路径保持独立。

首版规则／路径检查通过 119 项断言；场景流程检查通过 104 项断言，覆盖开场、四关、结尾与失败恢复，但通关飞行直接调用 `act()`，**没有证明方向键能通关**。终章保留脆枝的绕路为 12 拍，破枝近路为 8 拍；两条都从真实起点用同一状态转移重放，仅证明模型存在可行路径，不声称最优解。已完成独立 macOS 应用导出、临时签名和包内启动检查；首次打包漏带规则脚本的问题已修复并重测。当前采用程序绘制的简化画面与系统中文字体；尚无成品美术、配乐、正式存档、外部玩家证据或商业发行包。本地 Mac 应用用于本轮试玩，可独立运行，不需打开旧工程。

### 首轮试玩：第二关键盘阻断（2026-10-19）

- **玩家陈述：** Alan 反馈“我自己过不了第二关”，随后确认主要用“方向键”。这是创作者本人一场试玩反馈，不是独立外部样本；没有完整操作录像、时长或尝试次数。
- **技术事实：** 基线 `c250849` 的方向键每按一次立即提交四向一格，而鼠标可选模型允许的两格及斜向飞行。第二关蟋蟀每拍锁定蜂的位置，红十字覆盖中心与四个相邻格。穷尽“方向键＋栖停＋等待”的全部 65 个存活状态，胜利为 0，最多存活至第 3 拍、最远 x=3；搜索自然耗尽，无回合或节点截断。相同规则下，鼠标动作集存在 6 拍全程 3 点体力的解。
- **判断与修复决定：** 这是阻断进程的输入缺陷，不能把本次失败归因于玩家能力。Codex 负责先恢复键鼠等价能力：方向键仅移动目标方框，Enter 确认一次飞行；选点不消耗回合，与鼠标共用合法范围和结果预览。确认非法目标不耗回合，撤回／重开／换关及结算后重置方框。保留关卡、敌人、体力和风的规则，隔离输入变量。
- **回归边界：** `ui_verify.gd` 改为通过方向键与 Enter／W 实际入口走完四关，第二关采用全程无伤路线；另覆盖全棋盘选点、非法确认、动画锁、键鼠结果一致和恢复状态。修复后的场景检查通过 360 项断言；原生 Mac 窗口以实际按键走完第一关和第二关，第二关结果为 6 拍、余 3 点体力，并检查了撤回与重开。导出包启动、临时签名校验和专用 CI 通过。自动检查是技术证据，不能证明新版难度、易懂程度或乐趣已经合适。
- **修复交付时的复查计划（已由下节反馈替代）：** Codex 已完成原生键盘操作检查与独立 Mac 修复包，并提供直接从第二关开始的入口，避免重复第一关。当时的下一检查点是 Alan 从第二关继续整体体验；若仍难以理解或缺少期待，再复议教学与玩法，不能用本次输入修复宣布核心成立。日期未约定，行动状态只见 Now。

### 后续反馈：缺少吸引力（2026-10-19）

- **玩家陈述：** 在键盘修复交付之后，Alan 反馈“感觉没啥意思”。准确游玩版本、已完成关数、时长及具体失去兴趣的时刻未确认；不能把消息顺序当作已验证新版完整通关。当前只有一位创作者的反馈，不外推所有玩家，也不推导 Alan 排斥所有回合制游戏。
- **已知实现与分析：** 四场遭遇均以抵达出口收束；当前主要动作是选落点、栖停和等待，动物按固定规则攻击，角色回应主要发生在过关文本。Codex 的判断是：玩家主动行动的目的和可探索结果过窄，通关后的期待不足，动物的个性尚未通过互动成立。这些是基于实现的解释候选，尚未确认是本次无趣感的全部原因。输入可达性修复和自动测试不能反驳体验反馈。
- **制作决定：** Codex 按既有停止条件，将本实验标为当前体验未通过，停止扩关、扩写四季与表现层打磨；保留代码及修复包作为实验记录，不删除旧成果。没有批准新的类型或另一个完整项目。本轮仅更新反馈、状态与后续判断依据，不改关卡数值或再交付局部修补。
- **下一次决策需要什么：** 用一个具体的乐趣参照校准，而不是凭空换类型；已向 Alan 询问最近觉得有意思的一款游戏及其中一个想继续玩的时刻。此前“风影响飞行直观、带着小蜂有意思”和甲虫帮助的正评仍是局部证据，不能重新推成搬运日常已成立。Codex 负责据现有需求与该参照提出一个有具体行动、变化和收尾的后续体验候选；缺少新增参照时保留不确定性，不替用户补偏好。新候选与实现范围在下一次方向决定时评审，不要求 Alan 逐项审阅操作和参数。

**本轮结论是当前体验未通过，制作进入核心复议。** Alan 保留产品取舍；Codex 承担下一候选的设计判断，日期未约定。行动状态只在既有 Now 更新。
