# 实际美术落地标准 v0.4

状态：**2026-08-26 当前没有通过的正式画风候选。** v3 因暗脏、低色差、线噪和构图被否决；v4／v5 又因明暗两极、色彩脏、半照片转手绘、无情感、无合理抽象、细节过载、跨画面风格断裂、角色旧设定缺失和生态误读被否决。下一轮停留在前置设计，不生成完整地图或海报。

## 决策

本作不转为像素风。2026-08-24 的“缝制布艺贴花主体 + 毛毡微缩体积”只保留为已验证失败与历史生产假设，不再冒充已通过的最终画风。

当前只保留两类事实：

- **已锁定技术边界**：1280×720 高分辨率、严格俯视的连续旋转角色、独立透明交互层、低噪背景、轮廓与动作共同表达状态；剪纸、像素滤镜、毛毡玩偶、儿童布书和贴纸拼装不进入生产；
- **仍成立的产品目标**：扩大地图／时间、蜂巢承担类似篝火的作用、现实生态基础上的拟人化／个性化、可形成周边识别的 IP、世界内信息和最小查询界面。它们没有自动批准任何一张现有概念图。

候选比较、否决记录和证据边界见 [`LAUNCH_ART_PRODUCTION_PLAN.md`](LAUNCH_ART_PRODUCTION_PLAN.md)。角色继承以 [`character-visual-canon.md`](character-visual-canon.md) 为准。Alan 明确通过前置设计与代表帧之前，不据此批量替换资产。

概念样图只回答投影、轮廓、有限色、细节预算、局部体积与情绪，不能直接裁切成资产。每个实际资产必须有透明背景、固定视角、明确显示尺寸和状态要求，并进入 Godot 实机验证。

## 前置设计七道硬门禁

### G1 · 生态来源

每个液体、粒子和负载先标“来源—动作—持续时间—落点”。花蜜在蜜囊内，由口器交接；腹部末端不得出现蜜滴、金色液体或装饰性排液。当前授粉花粉是胸腹体表松散散粉，不得用后足花粉筐替代。任何看起来像排泄的液体一票否决；受击洒落若保留，只能从碰撞点短促发生，永不上主海报。

### G2 · 角色继承

主角、老师傅、蜂群分工和四位失律者先完成“旧设定必须继承／可以转译／明确废止”三栏表。每个核心角色至少有一个独占轮廓和一个独占动作；只剩普通动物剪影即失败。未经 Alan 确认，不得静默删除地主蚊子、三弦鸟精、油葫芦容器怪等旧参考中的人格符号。

### G3 · 单一渲染母版

先只做一张春季代表帧：主角、蚊、蜂巢和两类花。锁定六项：外轮廓、形状抽象、明暗档数、纹理方法、投影方向、有限色票。实机、地图图解、角色立绘和海报并排时必须共享这六项；一个像明亮手游地图、一个像暗色电影概念画，直接失败。

### G4 · 色彩

干净不等于更亮。干净指色相分离、稳定中间调、有限高彩、没有全屏脏色罩染、主次边缘清楚。首张样板暂以 60%—75% 中间调、近黑与近白各不超过约 10%、高饱和面积不超过约 15% 为守栏；这些比例是开发启发式，样板通过后再校准。禁止全屏蓝橙对冲、褐灰滤镜、整图高曝或大片闷黑。

### G5 · 艺术抽象与细节

所有动植物和地形先做有意形状归纳，再进入纹理与光影；禁止把照片／写实素材只处理到“像手绘”的中间状态。一张图只有一个视觉主句、一个主焦点、最多两个支持形。每个细节必须服务角色、生态、路线、动作或情绪之一，否则删除；背景高频边缘密度不得超过主焦区的一半。

### G6 · 情感

每张图开始前写唯一情绪与唯一关系动作，例如“家在等我，但远花仍诱惑我”。三秒盲看时，观察者应能说出相近的情绪／关系；若只得到“很亮、很暗、很忙、像照片或挺漂亮”，即失败。感情色彩来自角色关系、姿态、留白和色彩节奏，不靠体积光滤镜制造。

### G7 · 生产顺序

严格按“角色继承表 → 黑白剪影 → 三档明度缩略 → 有限色平涂 → 同一渲染母版 → 100% 实机动态 → 地图图解／海报派生”推进。任何一步未通过，都不得制作全季、全地图或群像宣传图；生成式精修不能跳过前四步。

## 为什么不选像素风

当前工程使用 1280×720 高分辨率布局、连续旋转移动、矢量中文 UI 与程序化粒子。转像素风不是“给现有图加滤镜”，而是必须同时重定逻辑分辨率、整数缩放、摄像机、角色尺寸、动画帧率、字体、HUD、粒子与全部敌我资产。它会丢弃现有候选图价值，却不会自动降低总工作量。

像素风只有在团队明确愿意整体重做视觉管线，并先完成一张原生低分辨率实机切片后才可重新讨论；当前不进入生产。

## 资产技术标准

| 项目 | 标准 |
| --- | --- |
| 工作格式 | 优先可编辑分层源文件；可使用 SVG 或透明高分辨率位图模块，最终必须能拆出轮廓、明暗、蜂蜡反馈和动画状态 |
| 视角 | 可连续旋转的移动单位使用严格俯视；真正三分之四视角只用于不旋转建筑，或在另行批准 4／8 向角色帧后使用 |
| 玩家显示尺寸 | 约 58×42 px；主体在 100% 游戏缩放下必须一眼可辨 |
| 普通花显示尺寸 | 花冠约 28–36 px；高价值花通过轮廓和动作而非仅换色区分 |
| 普通敌害 | 24–48 px；轮廓必须先说明追击、偷取、跳跃或压迫行为 |
| Boss | 普通敌害至少 1.8 倍，并有独立蓄力、失律、恢复轮廓 |
| 纹理 | 小尺寸不画绒毛、密集针脚或写实微纹理；场地中心／边缘生态／交互物按约 1∶2∶4 分配细节 |
| 描边 | 当前无已通过颜色；代表帧需锁定统一外轮廓与边缘软硬，内部线只保留解释结构与动作的少数组，不使用蚀刻、排线、点描和满屏颗粒边 |
| 阴影 | 代表帧先锁定有限明暗档与同一投影方向；禁止地图使用扁平软影而海报改用半写实体积光 |
| 状态可读性 | 颜色之外还需形状、缩放、动作或粒子反馈 |
| 信息构图 | 携带在蜂身、目标在同形实体／寻迹、蜂巢状态在蜂巢、结果在交互处优先表达；顶部／右侧不得用大块常驻文字重复世界已经说清的信息，但全部结算条件必须从开局可查询 |
| 地图视口 | 1280×720 不再等于未来完整地图；路径与生态延伸出屏外，单位保持真实尺寸，离屏危险必须预告，常驻 UI 目标占屏不超过约 8% |
| 角色 IP | 每个稳定角色必须先通过黑色剪影、有限色缩略、32 px 图标和软周边四项识别；个性必须继承其已有文化／性格符号和玩法动作，不能只套通用角色公式 |
| 拟人化 | 具体尺度由逐角色继承表决定；不得再用“禁止服装／道具”一条通则删空既有设定，也不得退化为人脸贴昆虫。哪些元素保留、转译或废止须由 Alan 确认 |
| 生态特效 | 花蜜不从腹端滴落；授粉散粉不等于后足花粉筐；任何体液、负载或粒子必须通过 G1 来源审查 |
| 跨画面统一 | 地图、实机、立绘和海报共享外轮廓、抽象程度、明暗档、纹理、光源与色票；仅改变镜头和构图，不另换一种绘画类型 |

## 首个垂直切片顺序

1. 玩家蜂：飞行锚点与全项目材质尺度；
2. 一朵普通花和一朵高价值花：验证采集目标层级；
3. 蜂巢与卸蜜反馈：验证安全区和资源归属；
4. 教学蚊虫：验证敌我轮廓与危险距离；
5. 春季地表模块：最后铺环境，防止背景先抢走交互物层级。

每一步必须在游戏实际截图中检查 100% 缩放、运动、季节色和 UI 同屏效果。通过后才生产同类批量资产。

## 首轮生成验证结论

- 毛毡高细节玩家蜂：像商品玩偶，缩小后绒毛、腿与缝线成为噪声，否决；
- 简化布艺位图玩家蜂：轮廓方向正确，但输出把透明棋盘格烘进图片，不能作为生产文件；
- 因此采用“生成图提供造型参考 + 可编辑 SVG/分层文件负责最终资产”的混合流程。

## 引擎切片 v1（2026-08-24）

![冬至实际引擎截图](screenshots/textile-art-slice-winter-v1.png)

截图由 `godot/tests/art_snapshot.gd` 加载真实 `main.tscn`、进入冬至首关并从游戏视口保存，不是概念图或后期合成图。

已验证：

- 玩家蜂在约 58×42 px、持续旋转条件下仍能辨认朝向；
- 蜂巢入口与实际安全区边界对齐，开始具备“家”的空间锚点；
- 普通花从程序化圆形替换为有花冠、蜂蜡花心、茎叶结构的独立资产；
- 透明织物覆盖层能保留节令底色，同时减少纯渐变占位感。

仍未通过最终品质：

- 地表仍缺少前中后景模块与局部生态聚落，画面较空；
- 小尺寸花的织物质感弱，普通花与高价值花需要在同屏运动中继续验证；
- 蜂巢尚无卸蜜、呼吸、衰弱动画；敌虫仍是程序化占位；
- 该图只作为 v1 视觉回归基线，不作为 Steam 商店截图。

运行快照：

```bash
godot --path godot --script res://tests/art_snapshot.gd -- --output=/tmp/nameless-art-snapshot.png
```

快照需要可用显示驱动，不能使用 `--headless`。
