## 0. 摘要 / Summary

**中文**：敌人已按物候钟差异化分布（见 `enemy-phenology.md`），但花朵仍为同质蜜量容器、蜜蜂活动仍为"飞→采→回"的固定循环。本设计将花朵重建为**六种花型 × 四季物候窗口**，蜜蜂活动按季增加**差异行为**——全部从已确认的生态机制和"被需要的四季"哲学中长出，不新增操作键，不推翻搜打撤骨架。核心原则：**花遵循真实植物物候出现在正确的季节；蜜蜂与花的互动方式随"被需要"的方向变化——春被花需要（照料）、夏被巢需要（争夺）、秋被来年需要（取舍）、冬被彼此需要（冒险）。**

**English**: Enemies already follow a phenological calendar (see `enemy-phenology.md`), but flowers remain homogeneous nectar containers and bee activity is the same "fly→harvest→return" loop every term. This design rebuilds flowers into **six types × four-season phenological windows**, and adds **seasonal bee behaviors** — all growing from confirmed ecological mechanisms and the "Four Seasons of Being Needed" philosophy, with no new keybinds and no overturning of the search-harvest-extract skeleton. Core rule: **flowers follow real plant phenology; the bee's interaction with flowers shifts with what needs it — spring: tending (needed by flowers), summer: contesting (needed by the hive), autumn: choosing (needed by next year), winter: risking (needed by each other).**

## 1. 设计原则 / Design Principles

1. **花有物候，不是蜜量容器 / Flowers have phenology, not just nectar.**  
   每种花型对应真实植物类群的物候行为：早春花量少但授粉后进入结籽（投资性），盛夏花蜜丰但引来竞争（暴露性），秋末花凋不重生（有限性），冬花罕见且隐蔽（藏匿性）。花型差异改变的是**采集决策**，不是数值大小。

2. **蜜蜂活动的差异 = 被需要方式的差异 / Bee behavior shifts = how it's needed shifts.**  
   春：蜜蜂是花与花之间的桥梁（花粉传递）→ 被花需要。夏：蜜蜂在采蜜和守门间切换（巢口轮值）→ 被巢需要。秋：蜜蜂在采蜜和留种间取舍（选择采收）→ 被来年需要。冬：蜜蜂在觅食和保温间冒险（侦察寻花）→ 被彼此需要。不增加新操作键，而是改变现有操作的季节语义。

3. **跨季因果链 / Cross-season causal chain.**  
   春季授粉形成结籽成果 → 后续花田密度 → 秋季可采花量 → 秋季种子投入 → 来年春季花田基础 → 冬季储备余量。授粉的后续影响不得在当前关抽象成“立即开花或生蜜”。一季的采集方式影响后续花田状态，让"为来年投资"成为可感知的前置→后果链，而非文案比喻。

4. **花蜜守恒不破 / Nectar conservation intact.**  
   所有新花型遵守花蜜总量守恒：授粉的直接结果是柱头受粉后进入结籽，不是花立即开放、新生或恢复花蜜；连环花若保留采集加成，必须定义为路线熟练带来的采收效率，不得冒充授粉产蜜；残花不重生但蜜量本就低；冰封花的体温代价不是蜜量损失。返蜜花机制不受影响。

5. **授粉因果必须可见 / Pollination causality must be visible.**
   唯一已批准链路是：**已开放的花药 → 蜜蜂身上松散可见的花粉 → 同一可见花型的可接受柱头 → 结籽**。给粉花和受粉花都必须预先可见；兼容的花瓣／花型保持同一身份，而开放花药与可接受柱头必须有不同的器官轮廓、姿态与状态反馈。

6. **完成条件不得隐藏 / Completion conditions must not be hidden.**
   所有会阻止关卡结算的条件都要从关卡开始起展示各自进度。若结籽是必做项，显示“结籽 `x/y`”；若不是必做项，则不得暗中拦截结算。

7. **未经 playtest 的数值标 [PLACEHOLDER] / Unplaytested values are [PLACEHOLDER].**

> **证据边界（2026-08-25）**：上述纠偏来自 Alan 对旧构建的直接反馈，不是独立外部玩家证据。新模型已进入代码并通过开发者回归；是否在真实运动中无需解释即可读懂，仍待 Alan 与独立玩家复核。

### 1.1 授粉生态依据与游戏化边界

- 授粉者的有效工作可操作化为从花药移走花粉，并把花粉沉积到可接受柱头；这支持“花药 → 蜂体 → 柱头”的核心链，而不支持“花粉打开花苞”：[pollinator effectiveness field study](https://pmc.ncbi.nlm.nih.gov/articles/PMC11940143/)。
- 蜜蜂胸腹等体表的松散花粉会参与柱头接触；后足花粉筐内压实、湿润的花粉主要用于运回巢内，不能把它简单等同于最有效的授粉表面：[honey-bee body and corbicular pollen study](https://pmc.ncbi.nlm.nih.gov/articles/PMC12942308/)。
- 授粉常会触发花朵衰老或关闭相关过程，而不是让未开放花苞立即盛开；种子／果实形成也发生在后续时间尺度：[pollination-induced flower senescence](https://pmc.ncbi.nlm.nih.gov/articles/PMC2826652/)、[orchid post-pollination development](https://pmc.ncbi.nlm.nih.gov/articles/PMC4243647/)。
- 游戏中的“同一可见花型”是对同种／相容花粉的可读性近似，并不声称所有同种个体必然相容；真实植物还可能存在自交不亲和、雌雄阶段和品种差异。若未来引入这些限制，必须同步给出可见形态，不得退回隐藏编号。

## 2. 六种花型档案 / Six Flower-Type Profiles

### 设计逻辑

敌人设计用"五种威胁动词"区分小怪；花型设计用"六种采集决策"区分花朵——每种花改变的是玩家在采集瞬间**做的决定**，不是蜜量大小。

| 花型 | 决策动词 | 核心性格 | 生态原型 |
|------|---------|---------|---------|
| **蜜花 Nectar Bloom** | 采就走（基线） | 稳定给蜜，无特殊行为 | 盛花期标准花 |
| **初花 First Bloom** | 投资 | 蜜少但触发花田生长 | 早春先花（梅/桃/油菜） |
| **连环花 Chain Bloom** | 路线规划 | 连采同型花，同次动作多取现有花蜜 | 花序植物（紫藤/油菜花序） |
| **盛花 Peak Bloom** | 贪与避 | 蜜多但引来蚊虫 | 盛夏大花 |
| **残花 Fading Bloom** | 取舍 | 采了不重生，每朵是最后一次 | 秋末凋花 |
| **藏花 Hidden Bloom** | 搜索 | 不可见，需侦察发现 | 冬花（蜡梅/山茶） |

> 另有两种变体——**籽花 Seed Bloom**（秋季，蜜少但产出种子）和**冰封花 Frozen Bloom**（冬季，需消耗体温解冻）——作为季节专属花型在第 3 节详述。

---

### 2.1 蜜花 · Nectar Bloom —— 基线 / Baseline

- **现实生态 / Real ecology**：盛花期标准蜜源植物，花蜜稳定分泌，对传粉者无特殊门槛。
- **机制 / Mechanic**：标准蜜量（`3 × nectar_scale`），无特殊行为。现版花朵即为蜜花。
- **决策 / Decision**：无——基线参考。其他花型的决策价值通过与蜜花对比产生。
- **窗口 / Window**：全季（作为其他花型的对照组，始终占最大权重）。

### 2.2 初花 · First Bloom —— 投资型 / Investment

- **现实生态 / Real ecology**：早春先花植物（梅花、桃花、油菜花）花量少、单花蜜量低且花期早，是蜜蜂出冬后的第一批食物。花粉从开放花药转移到兼容柱头后，植物进入受精与结籽过程，不会当场开出一朵新花或新增花蜜。
- **机制 / Mechanic**：蜜量低（`1–2 滴`）；同一可见初花变体中同时配置预先可见的给粉花和受粉花。给粉花以已开放花药掉落散粉；蜜蜂身上带散粉接触同型花的可接受柱头后，受粉花进入可见结籽状态。该状态不增加当前花蜜。
- **决策 / Decision**：是否为同型花完成“取粉 → 传粉 → 结籽”的可见路线，用当前采集时间换后续繁殖成果；还是直接找蜜多的蜜花？春季核心张力。
- **窗口 / Window**：冬至 → 惊蛰（春季前半段，花田建立期）。

### 2.3 连环花 · Chain Bloom —— 路线规划型 / Route Planning

- **现实生态 / Real ecology**：花序植物（紫藤、油菜、紫云英）同株多花顺序开放，蜜蜂沿花序顺序访问效率最高——这是蜜蜂"花序学习"行为的真实基础。
- **机制 / Mechanic**：采完一朵连环花后，`2 秒`内采相邻（≤120px）同型花，同一次采集可从目标花的**现有库存**多取 `1 滴`，每条路线最多触发 `3 次` [PLACEHOLDER]。目标花只剩一滴或蜜囊只剩一格时不触发；超出窗口或采异型花则重置。该奖励缩短采收时间，但不会补回或创造花蜜。
- **决策 / Decision**：花时间规划连环花路线（高效率但固定路线=可预测=敌人可伏击），还是就近散采（灵活但效率低）？
- **窗口 / Window**：立春 → 谷雨（春季中后段，花田成熟期）。

### 2.4 盛花 · Peak Bloom —— 争夺型 / Contest

- **现实生态 / Real ecology**：盛夏大花（荷花、木槿）蜜量丰富，但丰富的花蜜也吸引大量竞争者——蚊虫在盛夏达到种群峰值，与蜜蜂竞争同一蜜源。
- **机制 / Mechanic**：蜜量高（`5–6 滴`），但采蜜时吸引蚊虫——半径 `200px` 内的蚊虫转向该花 [PLACEHOLDER]。若该区域无蚊虫，有概率生成 1 只 [PLACEHOLDER]。
- **决策 / Decision**：贪盛花的高蜜但引来蚊虫（暴露），还是避开盛花找低蜜但安全的蜜花？
- **窗口 / Window**：清明 → 大暑（夏季全程）。

### 2.5 残花 · Fading Bloom —— 取舍型 / Finite

- **现实生态 / Real ecology**：秋末花凋，花蜜分泌渐止且不再新生。秋季植物转向结籽，花朵本身进入不可逆的衰退期。
- **机制 / Mechanic**：蜜量低（`1–2 滴`），采完不重生。秋季当前关不生成新开花朵，花田只减不增；这是秋季物候规则，不再与授粉的结籽结果混为同一个即时重生开关。
- **决策 / Decision**：每一朵花都是不可再生的稀缺资源。采还是留给"模拟蜂群"（不存在的其他工蜂）？走远路采晚蜜花还是就近采残花？
- **窗口 / Window**：小暑 → 寒露（秋季全程）。

### 2.6 藏花 · Hidden Bloom —— 搜索型 / Search

- **现实生态 / Real ecology**：冬花极少且隐蔽——蜡梅在枯枝中开放、山茶藏在常绿叶间。冬季觅食的蜜蜂需要靠经验（侦察蜂的摇摆舞信息）才能找到这些零星蜜源。
- **机制 / Mechanic**：初始不可见。需触角寻迹（U 键）才显示位置，显示后可正常采蜜。蜜量低（`1–2 滴`）。
- **决策 / Decision**：花时间和寻迹冷却去找藏花（高时间成本），还是在可见的低蜜花间挣扎，还是直接归巢抱团保温？
- **窗口 / Window**：寒露 → 大雪（冬季全程）。

## 3. 季节专属花型 / Season-Specific Variants

### 3.1 籽花 · Seed Bloom（秋季专属 / Autumn-only）

- **现实生态 / Real ecology**：秋季结籽植物花蜜少，但种子是来年植物种群的基础。蜜蜂采集时携带花粉/花蜜回巢，是植物繁殖和蜂群未来的双重投资。
- **机制 / Mechanic**：蜜量 `1 滴`，采完获得 `1 颗种子`。归巢时种子可投入"花田"（增加下一轮春季基础花量 `+1`）或"储备"（增加冬蜜 `+2`）[PLACEHOLDER]。种子 = 储备分配面板的第三选项。
- **决策 / Decision**：采籽花（低蜜但有种子=来年投资）还是采残花/晚蜜花（高蜜但无种子）？种子投入花田还是储备？
- **窗口 / Window**：立秋 → 霜降。

### 3.2 冰封花 · Frozen Bloom（冬季专属 / Winter-only）

- **现实生态 / Real ecology**：霜冻后部分花朵蜜汁在花蕊冰层内凝结，理论上需温度升高才能采集。游戏中抽象为"消耗体温解冻"。
- **机制 / Mechanic**：蜜量 `3 滴`，但需先消耗 `20 体温`解冻才可采 [PLACEHOLDER]。体温不足则无法采。
- **决策 / Decision**：体温够不够支撑解冻+采蜜+归巢？这是冬季最硬的成本计算——体温是有限资源，花蜜也是。
- **窗口 / Window**：霜降 → 冬至。

### 3.3 暖花 · Warmth Bloom（冬季专属 / Winter-only）

- **现实生态 / Real ecology**：冬季腐熟堆肥/落叶层有微热效应（发酵热），蜂群有时在附近短暂停留回温。游戏中抽象为"暖花"——花本身有微热，靠近暂停体温消耗。
- **机制 / Mechanic**：蜜量 `2–3 滴`，靠近（≤45px）时体温消耗暂停 [PLACEHOLDER]。可先停在暖花旁回温，再采蜜。
- **决策 / Decision**：停在暖花旁回温（安全但慢），还是采完继续走（高效但体温持续下降）？
- **窗口 / Window**：立冬 → 大雪。

## 5. 蜜蜂季行 / Seasonal Bee Activities

### 设计逻辑

蜜蜂活动的差异不增加新操作键（沿用移动、空格情境动作、方向双击急转与归巢），而是**改变现有操作在当季的语义和效果**。每季一个行为差异，与该季招牌机制（授粉/征召/储备/抱团）直接联动。

### 5.1 春季 · 花粉传递 / Pollen Transfer（与授粉机制联动）

| 项目 | 内容 |
|------|------|
| **给粉前件** | 花已开放，花药展开且花粉可见；蜜蜂接触后，花粉以松散颗粒附在身体上 |
| **受粉前件** | 目标花与给粉花属于同一可见花型，已开放且具有可接受柱头；目标不隐藏，柱头与花药不同形 |
| **携带状态** | PR #94 候选以 `pollen_charges` 为唯一规则真相；A／B 两类可同时携带、各上限 2。胸腹体表的两个散粉锚区精确显示 `0/1/2`，A 为金黄圆粒簇、B 为玫红菱粒簇，不使用单一“当前花粉”图标。锚区只总结多个接触面上的松散花粉，不是后足花粉筐 |
| **恢复读取** | 携粉时停稳触角寻迹，每个正在携带的类型分别以同形气味点指向最近可见、未锁定、未结籽的同型柱头；此时收起普通最佳蜜花线，保留危险区与归巢线。无粉时寻迹仍按原寻蜜规则工作 |
| **成功效果** | 按键后体表显示先减一份，目标进入约 `0.46s` pending 防重复；同形颗粒从对应体表散粉锚区离身并落向柱头，落地后才标记已受粉并进入结籽。这是“胸腹等体表松散花粉接触柱头”的可读性抽象，不表示花粉筐直接授粉；不打开花苞，不新增或恢复花蜜 |
| **不匹配效果** | 不扣任何花粉、不结籽、不改花蜜；实际携带形态在目标前弹回，目标所需形态脉冲，并播放与成功不同的短音 |
| **生态依据** | 蜜蜂把花粉从花药转移到兼容柱头，为后续受精和种子发育建立条件；花蜜分泌是独立的植物过程 |
| **决策** | 识别同型花中可见的花药／柱头差异，规划取粉与传粉路线，用当前时间换结籽进度 |
| **实现要求** | 花实例以 `visual_variant` 表达可见花型，以 `has_anthers` / `receptive_stigma` 表达器官角色，并以 `pollen_variant` / `stigma_variant` 校验兼容；共享视觉字母表同时服务花、蜂、寻迹与反馈；只有颗粒落地才写入 `pollinated` / `seed_setting`，不写花蜜数值 |

### 5.2 夏季 · 巢口轮值 & 快速抢采 / Hive Guard & Sprint Harvest（与征召机制联动）

| 活动 | 触发 | 效果 | 生态依据 | 决策 |
|------|------|------|---------|------|
| **巢口轮值 Hive Guard** | 征召·巢口告急期间 | 蜜蜂在 `HIVE_SAFE_X` 内停留 → 蚊群驱散速度 `+50%` [PLACEHOLDER] | 工蜂守卫行为是年龄多态性的一部分——成蜂在蜂群需求下转为守卫 | 放下采蜜去守门（安全+公共储备奖励），还是继续采蜜（收益但巢口风险）？ |
| **快速抢采 Sprint Harvest** | 征召·花区告急期间 | 采蜜间隔 `×0.8` [PLACEHOLDER] | 蜂群在资源竞争压力下的加速采集行为 | 抢采（快速但掠蜜蚁在场=高风险），还是等花区告急结束后正常采？ |

### 5.3 秋季 · 选择采收 & 种子归巢 / Selective Harvest & Seed Return（与储备机制联动）

| 活动 | 描述 | 生态依据 | 决策 |
|------|------|---------|------|
| **选择采收 Selective Harvest** | 秋季花田只减不增（残花不重生），蜜蜂必须规划路线——采哪些花、跳过哪些花。晚蜜花只在地图边缘出现。 | 秋季花量真实下降，蜜蜂变得更挑剔，选择高价值目标 | 采近处残花（安全但低蜜），还是冒险走远路采晚蜜花（高蜜但暴露）？ |
| **种子归巢 Seed Return** | 采籽花获得种子，归巢时在储备分配面板选择投入"花田"（来年基础花量 `+1`）或"储备"（冬蜜 `+2`）[PLACEHOLDER] | 蜜蜂携带花粉/花蜜回巢是蜂群未来的投资 | 种子投花田（来年更从容）还是投储备（冬天更安全）？ |

### 5.4 冬季 · 侦察寻花 & 暖流共享 / Scout Search & Warmth Share（与抱团机制联动）

| 活动 | 描述 | 生态依据 | 决策 |
|------|------|---------|------|
| **侦察寻花 Scout Search** | 触角寻迹（U 键）在冬季改为"侦察"模式——揭示藏花位置（而非蜜量/警戒区）。公共储备 ≥5 时侦察冷却缩短（已有 huddle 机制）。 | 侦察蜂是最资深的外勤蜂，冬季侦察=高风险高价值行为 | 花寻迹冷却找藏花（高时间成本但唯一蜜源），还是直接归巢抱团？ |
| **暖流共享 Warmth Share** | 距离 NPC 蜂（模拟蜂群中的其他工蜂） `< 40px` 时，体温消耗 `×0.3` [PLACEHOLDER]。NPC 蜂为程序化渲染的小蜂点，沿蜂巢-花田间巡逻。 | 抱团保温的个体表达——野外偶遇同巢蜂也是暖 | 跟随 NPC 蜂路线（保温但路线不自主），还是独自飞行找藏花（自由但体温消耗快）？ |

## 6. 跨季因果链 / Cross-Season Causal Chain

```
春·授粉完成同型花的结籽（开放花药 + 身上散粉 + 可接受柱头）
    ↓ 结籽成果可进入后续花田基础（不在当前关开花或产蜜）
夏·盛花暴露采集者（盛花引蚊 + 巢口轮值 + 快速抢采）
    ↓ 采集效率影响秋季可采花量
秋·残花有限 + 种子可投资（选择采收 + 种子归巢）
    ↓ 种子投入花田 → 来年春季基础花量 +N
    ↓ 种子投入储备 → 冬季公共储备 +N
冬·藏花需侦察 + 冰封花需体温（侦察寻花 + 暖流共享）
    ↓ 冬季存活 = 蜂群熬过循环
春·新花田基础花量由上年秋种子决定（循环回馈）
```

**关键设计**：秋季投入花田的种子 → 直接增加下一轮春季的初始花量和连环花出现概率。这让"为来年投资"不是文案比喻，而是真实的前置→后果链。

**降级方案**：如果跨季因果链实现成本过高，种子→来年花田可简化为文案层表达（结算页显示"来年花田因你的种子而更丰盛"），不影响单季玩法闭环。

## 10. 实现路径 / Implementation Path

### 阶段 1：先做 1 季验证

| 候选 | 理由 | 风险 |
|------|------|------|
| **春季先行（推荐）** | 旧授粉机制已被 Alan 否决，必须先以一季切片替换为“花药 → 散粉 → 同型柱头 → 结籽”；敌人压力最低，适合隔离验证器官辨识、路线和完成条件 | 不同器官若缩小后仍同形，或结籽进度仍隐藏，则不得进入其他季节 |
| **冬季先行** | 抱团机制已实现；藏花和冰封花的体温代价是最强决策点；冬季"找花"体验差异最明显 | 冬季系统最复杂（体温+侦察+NPC蜂），调试成本高 |

### 阶段 2：数据驱动铺底

1. 新增 `godot/data/flowers.json`；
2. `main.gd` 花朵生成改为按 `flower_set` 读取花型权重；
3. 花朵对象使用 `type`、`visual_variant`，授粉机制按实例补充花药／柱头、相容变体与 `pollinated` / `seed_setting` 状态；
4. 为蜜蜂增加可同时读取的双类型散粉状态与走神后寻迹恢复，为关卡目标增加独立结籽进度（仅在结籽是必做项时）。

### 阶段 3：逐季铺开 + 跨季因果链

- 实现顺序：春 → 秋 → 夏 → 冬（从简单到复杂）；
- 跨季因果链最后接入：秋季种子 → 春季花田基础花量。

## 12. 设计纪律备注 / Design Discipline Notes

- 所有数值标注 [PLACEHOLDER]，未经 playtest 不定稿；
- 授粉固定为“已开放花药 → 身上松散花粉 → 同一可见花型的可接受柱头 → 结籽”；给粉／受粉器官可见且不同形，不得回退到隐藏同形目标；
- 授粉不即时开花、不创造或恢复花蜜；任何结籽后续收益都必须经过明确时间层级，不得偷换成当前关奖励；
- 任何阻止结算的条件必须从关卡开始起可见并显示进度；
- 每种花型必须回答："如果删掉这种花，玩家的体验损失是什么？"——如果答案是"没有损失"，删掉它；
- 蜜蜂活动的季节差异不增加新操作键（沿用移动、情境动作、方向双击急转与归巢），而是改变现有操作的季节语义；
- 跨季因果链（种子→花田）是"锦上添花"而非"必须闭环"——可简化为文案层表达；
- 本设计与 `enemy-phenology.md` 的物候逻辑互补：敌人按物候出现制造威胁，花朵按物候出现制造采集决策——两者共同构成"节气改变同一套核心操作的条件"的完整图景。
