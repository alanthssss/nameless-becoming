# 地图扩展与蜂巢节点方向 v0.3

状态：**2026-08-26 产品方向已调整，尚未实现。Alan 明确决定后续扩大地图与游玩时间以充实关卡，并把蜂巢设计成类似篝火的核心节点；蜂巢仍只叫蜂巢。世界／地图／场景数量、主次蜂巢数量和节点服务仍是开发建议，待 Alan 确认与灰盒验证。当前 v4／v5 视觉执行已正式否决，没有通过的地图美术候选。不得把“类似篝火”自动扩写为存档、复活、传送、刷怪、商店或多个等价主巢。**

## 1. 已决定的未来方向

- 正式关卡不再以“1280×720 视口就是完整地图”为长期目标；视口成为摄像机跟随的局部画面，路径、生态区和危险继续延伸到屏外；
- 关卡时间通过距离、分路、远近收益、返程风险、机制变化与局部事件增加，不靠降低移动速度、堆高目标数字、增加敌人耐久或重复采集填充；
- 蜂巢节点承担类似篝火的**节奏与情绪锚点**：玩家从暖亮、安全、有人活动的空间出发，进入更远、更不确定的花田，再回到蜂群共同体；
- 蜂巢必须成为每个局部视口最容易建立方向感的地标之一，但不再固定贴在屏幕左边；地图构图围绕“巢／退路—玩家—目标或威胁”的三角关系组织；
- 当前 `1280×720` 仍是显示视口和评审画布，不再被误写成未来世界边界。

开发建议口径是：**1 个连续家园、5 张可加载地图、13 个主场景、4 季与 24 个节气状态，待 Alan 确认。** 若采用该口径，5 张地图可拆为中央主蜂巢 + 四个方向性野外区，13 个主场景可拆为主蜂巢 1 个 + 每个野外区 3 个生态场景；24 节气只改变同一世界的物候、天气、路线和活动，不制作 24 张地图。完整生态与花卉提案见 [`world-season-ecology-framework.md`](world-season-ecology-framework.md)。

此前的[五图世界结构实验](concepts/rejected-five-map-world-atlas-overbright-v1.png)只作为被否决证据保留，不再主动展示，也不表达获批比例、路线或主次蜂巢数量。它的过亮脏色、无效细节、半照片半手绘和缺乏情绪焦点等视觉处理不得复用。

## 2. 当前实现事实，不冒充未来规范

- 当前 `Main` 仍是固定单屏世界，主蜂巢位于左侧；没有摄像机跟随或连续长地图；
- 当前主蜂巢是唯一交蜜、公共储备、`on_home`、节点结算与 Q 归巢目标；
- 当前立夏中继巢只提供有上限的恢复，不交蜜、不结算、不改变 Q；
- 当前不保存进行中的循环，退出即结束；`best_stage` 不是检查点；
- 上述均为现行候选的实现与回归边界。新的未来方向可以重新设计它们，但在新规格与原型通过前，不能假装代码已经具备长地图或检查点。

## 3. 蜂巢要借用篝火的哪些作用

这里不是给蜂巢另起名称，而是说明它在地图节奏上借用篝火的部分作用。蜂巢不是字面火焰，也不复制其他游戏的整套篝火机制。第一层只锁定空间和视听语言：

- **远处可辨**：暖金核心、蜂流方向和地形开口共同提供导航，不依赖常驻文字箭头；
- **接近可感**：环境从冷绿过渡到暖绿／蜜金，危险节拍减弱，蜂巢活动与安全声部增强；不画无语义的发光圆圈；
- **有人等待**：修补、守卫换班、储蜜格亮灭、卸蜜和休息动作让节点像共同体，不是自动售货机；
- **状态清楚**：至少预留休眠、可用、接近、休整、受损和恢复六类可区分状态；具体是否都进入首个原型由 D0 决定；
- **层级明确**：若未来同时存在主巢与野外节点，必须一秒内从轮廓、规模、活动和光色分清“家”与“驿站”。

此前生成的明亮地图方向稿也不再主动展示或充当风格参考。“干净、明亮”不等于整体提亮；后续必须先在真实游戏尺寸上统一地图、角色与海报的形状语言、抽象程度、明度阶梯、色相家族、边缘处理、纹理尺度和光照逻辑。角色视觉须先继承 [`character-visual-canon.md`](character-visual-canon.md)，不得由地图稿擅自固定触角、翅缘、负载方式或其他 AI 自创标志。

## 5. 首个结构原型建议

在 Alan 确认精确数量前，建议不制作完整五图，更不制作无限地图；可先做春季一个可撤销的 `2×2` 视口多屏区灰盒：

```text
                 远区：高价值／高风险／遭遇入口
                    ↗               ↘
主巢／蜂巢节点 → 中区：机制路线 ───── 回环捷径
       ↘            ↖
        近区：教学／普通花
```

- 世界先从约 2×2 个视口的量级验证，具体像素尺寸只是开发者启发式起点，不是产品承诺；
- 玩家与交互物保持真实显示尺寸，不能把所有单位缩小来伪装地图变大；
- 近／中／远路线必须有不同的目标、风险和回程判断，并能通过回环或捷径减少纯空跑；
- 摄像机给移动方向少量前视空间；离屏威胁必须先有方向与时间预告，禁止屏外直接命中；
- 每个视口只保留一个主要关系和充足低噪空间，不因地图扩大而提高满屏对象密度；
- 灰盒可先在主巢外放一个次级蜂巢节点，验证有限休整、地图信息和返程节奏；它不交蜜、不结算、不传送、不刷新敌害。这是可撤销测试参数，不代表最终节点数量。
