## 1. 文档权威与使用方式

本文件把 Alan 历次明确要求、已经认可的剧情框架、当前可运行实现和商业发行缺口合并为一张验收清单。它回答的不是“原型有什么”，而是“什么全部成立后，项目才可以称为可售卖的商业游戏”。

发生冲突时按以下顺序处理：

1. Alan 最新的明确表述；
2. 本文件；
3. 已认可的当前剧情框架与最新美术生产决定；
4. 当前运行实现；
5. 旧 MVP、旧分析、旧原型和历史日志。

旧文档仍可保留追溯价值，但不得覆盖本文件。新增或删改商业范围时，应同步更新本文件，不再另建一套互相矛盾的“总清单”。24 关的逐关制作、Boss、推进／重玩和 v2 存档迁移由 [`solar-term-campaign-production-spec.md`](solar-term-campaign-production-spec.md) 维护为唯一专项规格；本文只维护它是否满足商业成品退出条件。

### 1.1 状态标记

| 标记 | 含义 |
| --- | --- |
| `✅ 已实现` | 该项明确的实现范围已进入当前新旅程可运行路径，并有代码、数据或实机画面可核对；不自动等于商业品质通过 |
| `◐ 部分实现` | 有当前路径能力，但内容、质量、平台、资产或玩家验证仍缺一部分 |
| `☐ 待实现` | 商业成品必须具备，当前尚未完成 |
| `⛔ 禁止` | Alan 已明确反对，不能换名后重新加入 |

### 1.2 证据等级

每项结论必须明确属于哪一种证据，不能互相冒充：

| 标签 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| `[实现事实]` | 仓库中存在相应代码、数据、资产或可运行路径 | 玩家能看懂、喜欢，或达到商业品质 |
| `[开发者自测]` | 开发者在指定提交和设备上实际走通，或自动回归通过 | 独立玩家可以无提示完成 |
| `[专家启发式]` | 依据设计、美术、交互或市场常识做出的专业审查 | 真实用户反应或市场结果 |
| `[AI 模拟]` | AI 对路径、文案或玩家反应的预演 | 任何外部玩家证据；不得计入外测样本 |
| `[外部玩家证据]` | 未参与开发的真实玩家在可追溯构建上的行为、原话和结果 | 未覆盖人群、平台或后续版本的表现 |
| `[需独立玩家验证]` | 明确指出实现已存在、但理解、乐趣、疲劳、可达性或购买预期尚无独立样本 | 不得改写为“玩家已通过”或“市场已验证” |
| `[需 Alan 确认]` | 明确指出命名、语气、美术、音乐或产品取舍仍需制作人最终验收 | 不得由开发者自测、AI 判断或资产已接入代签 |

“自动测试通过”“开发者截图”“AI 认为可爱”都不能把一项标记为玩家验收通过。`✅ 已实现` 只回答仓库与可运行路径，不等于第 13 节发行退出条件已通过。发行判断必须同时列出实现事实、开发者自测和独立外部玩家证据；涉及产品身份、语气、画风和音乐时还要保留 Alan 的明确验收状态。

- `⛔ 禁止` 故弄玄虚、含混梦境、谜语式世界观、旁白故作深沉。

- `⛔ 禁止` 老师傅牺牲、失踪、黑化、隐瞒惊天秘密，或靠身份揭晓推动玩家情绪。

## 4. 完整剧情与内容范围

### 4.1 总体弧线

完整游戏是一个四季邻里喜剧，而不是 24 个互不相干的任务节点。

1. 玩家梦见自己成了一只小蜜蜂，第一次独立出门；前提直接成立，不做真假反转。
2. 老师傅先示范，随后后退半步、与玩家分工、跟飞，最终让玩家给下一只新蜂做示范。
3. 蜂巢从“出生点／结算点”成长为可辨认的生活共同体：接货、换班、修理、储存、清扫、育幼和保温都由真实动作构成。
4. 四季中的邻居会造成麻烦，也会在世界中留下新的关系和帮助；没有角色因不同习惯而被判为邪恶。
5. 结尾由老师傅说“这回你来”，玩家完成一次示范，并自然说出“一会儿巢里见”。

第 4.2～4.5 节同时保留扩产前短 Journey 的已实现叙事细节，作为当前 Campaign 的角色／物件素材来源；它们不能证明 24 个新关卡逐关复现了旧专属导演。当前正式入口、地图尺寸、三阶段高潮、工作组合、推进与存档事实以第 4.6 节和 [`solar-term-campaign-production-spec.md`](solar-term-campaign-production-spec.md) 为准。

### 12.3 发行阻断缺陷

以下任一存在都不能称为商业成品或提交正式发行：

- 主线、结局、存档或场景切换无法完成；
- 关键状态无提示、目标隐藏、资源／角色永久软锁；

- 只有开发者和 AI 测试，没有独立外部玩家证据。
