# 《雨来之前》：完整飞行短篇，2026-10-20

## 问题与决定

Alan 对旧雨水章的反馈是赶路、搬东西、缺乏期待；《花间一着》随后也收到“感觉没啥意思”。其具体游玩版本和完成关数未知，不能推断全部回合制无效。Alan 提到最近喜欢英雄联盟海克斯大乱斗，并明确“不要只为了迎合我的喜好”；这只能作为乐趣参照，不能推断需要复制强化选择、对战或商业体量。

本轮授权：“你来定新方案，按你的判断做出一段从头到尾完整可玩的体验，做完让我整体玩一次，别再陷入零碎修改。”Codex 因此选择并实现《雨来之前》，把“能亲自飞行、与小蜂一起行动、温暖的冒险”做成连续的开始—发展—高潮—结尾。原始创作依据见[需求恢复](original-requirements-recovery-20261019.md)，历史失败和输入缺陷见[花间一着记录](flower-step-game-20261019.md)。

**当前状态：完整原型已交付，Alan 对核心体验给出正向反馈；关卡交互表达和美术仍需改进，音乐获初步肯定。** 这是本项目创作者／产品负责人一位玩家的真实反馈，尚无独立新玩家证据，不代表商业成品验收或扩写授权。只维护[当前 Now](solar-term-campaign-production-spec.md)这一执行视图。

## 本轮固定范围

独立 `prototypes/swarm-flight` 工程；一个实时飞行规则，三个相连场景，一套程序绘制植物与蜂群视觉、合成音乐和音效；标题、暂停、输入恢复、段落存档、结尾、重玩、macOS 交付和独立 CI。旧工程、旧关卡和旧存档保持原状。交互规则与反馈共同服务完整体验，不增加库存、日历、升级树、搬运交付或多个独立系统。

主要权衡：短篇允许快速整体评价，尚不足以判断长线可玩性。蜂群伙伴是有可见反馈的同行角色，碰撞与体力以带队蜂为准，不制造伙伴分别卡住的护送负担。收拢能减小带队蜂碰撞、减慢速度并更稳地蓄力；成员数量不增加攻击伤害，本轮也没有战斗成长。

## 玩家实际经历

| 段落 | 玩家做什么 | 行动后的变化 |
| --- | --- | --- |
| 风起的时候 | 连续飞行、调整朝向、按住空格收拢，松开冲入卷叶；通过花茎间隙 | 三次救出六只伙伴，它们立即跟随；打开的卷叶与干叶帘留下结果 |
| 花桥接力 | 冲进风花获得一段导向加速，在花间重新选择方向、发起下一次冲刺 | 蜂群可以连续越过弯曲花桥，接上最后两只伙伴；此段普通飞行也可完成 |
| 雨来之前 | 在移动雨线与落下的雨滴之间飞行、冲开叶帘，在两处叶下恢复 | 最后一次冲进发光树洞，九只小蜂收起翅膀，出现完整结尾与重玩入口 |

风花只提供有限距离的接力，不用一次输入自动替玩家完成整段。雨滴可避开或冲散；树茎实体阻挡，干叶帘可冲开；目标箭头指向待救伙伴或出口。第一段起飞前没有位移或危险，先安全理解操作。

## 可验证假设与停止条件

**唯一核心问题：** 亲手改变速度、朝向与蜂群状态，能否让一段不断变化的旅程本身值得玩，而无需靠搬运和日数制造进度？

希望观察到：第一次救人后主动尝试下一次冲刺；风花接力后愿意再用；遇到雨线时知道自己想怎样飞；结束时能指出一个自己完成而非只观看的时刻。以上是待验证假设。

若反馈仍是“只在往右飞”“按提示做完，没有期待”“伙伴只是装饰”，则判核心未通过，复查行动选择与反馈关系。不得用增加关卡、装备、更多文案或局部美术掩盖。下次讨论以整趟体验为单位，不让 Alan 逐项审批参数。

## 验证与交付证据

本轮关联 R01–R13 中的适用教训：在用户实际方向键路径中验证可达性；开场、恢复、过场和结尾都必须实际运行；状态变化当场可见；不给真人反馈补写完成记录；以独立包身份明确正确入口。具体映射依[雨水试玩原记录](commercial-product-requirements.md#rain-playtest-review)，本轮没有宣称其所有问题已获真人复测通过。

- 规则测试：完整三段路线、撞墙不穿透、叶帘可破、雨滴及死亡恢复、避雨与雨线、保存及损坏存档处理。
- 输入场景测试：实际按键事件进入 `main.gd` 输入处理器，方向键＋空格走完三段，看到结尾并重玩；同时检查 WASD、暂停、失焦清理与静音。
- 视觉与声音：三幕代码绘制及音频总线运行检查；原生 OpenGL 画面检查。合成与运行通过不等于真人听感认可。
- 原生包：macOS universal 独立包，包含全部运行资源、独立 bundle ID、隔离段落存档；实际 macOS 包已逐段通过方向键与空格完成三个段落：第一段救援和过场；修复包中后两段连续完成风花／普通路线救援、两个叶下恢复点及树洞结尾。暂停、回车继续和 R 就近恢复实际生效；从标题到结尾的单次完整输入事件路线也由场景测试验证。原生测试曾发现收拢贴墙后展开的碰撞卡死，已补最近边缘脱离处理、阻挡方向速度清零及回归测试。额外独立检查覆盖所有现有墙体侧面／角落展开与双向冲刺，716 项通过；对旧版本的负对照检测到原卡死。测试启动标志采用 `--swarm-qa`，避开 Godot 保留的 `--test`，正常双击无附加参数。其它系统未做桌面验收。
- PR #149 交付时尚无真人反馈；交付后的 Alan 反馈见下节。上述技术证据只用于保证能整体试玩。

## 2026-10-20 首轮玩家反馈与商业差距评估

### 直接证据与当前判断

会话证据 `SF-R01`：Alan 在本轮对话评价“核心体验不错”“但是不同关卡的细节感受 不太行”“美术过于粗糙”“不知道距离商业游戏还有多少距离”“音乐也还行”。进一步澄清，关卡细节最接近“提示、操作或反馈让人不明白”。反馈承接 PR #149 的交付；实际运行文件、完成段数、输入设备和时长没有在本轮另行核对，未读取该次试玩录像或行为日志。不得补写其具体失败次数、某关卡问题或已完成全流程。

**结论：保留核心方向，优先处理交互可理解性与美术完成度。** “关卡细节不太行”目前不能归因为玩法变化不足，也不能由此推断需要更高难度、更多系统或重新选型。“音乐也还行”支持保留现有音乐基调，不等于全部音效、混音与动态音乐均已通过。

### 对照实现能确认的表达缺口

以下实现事实可由源文件复核；它们是否正是本次困惑的原因，仍是分析假设，不是玩家行为记录。

| 情境 | 已检查的实现 | 为什么值得优先验证 |
| --- | --- | --- |
| 松开空格却没有冲刺 | `game_model.gd` 的 `step` 仅在蓄力达到 0.75 时发出 burst；提前松开清零，未发出未蓄足事件。界面有蓄力过程提示，但没有该次操作未生效的解释 | 玩家可能分不清按键失效与条件未满足；应让准备中、可释放、提前取消各有可辨识反馈 |
| 风花接力方向 | `world_view.gd` 的 `_ring` 将所有箭头画向右；`game_model.gd` 实际把朝向设为下一朵风花／出口方向，可能斜向 | 图形应帮助预判真实去向；需要核对玩家能否提前理解自动转向与自己控制的边界 |
| 再次使用同一风花 | 规则只允许未激活的风花接力一次；已激活外观仍有箭头动画和向右流动的风线，主要以配色区别 | 可用与已用状态可能发出相反暗示；不能依靠玩家记住所有触发历史 |
| 冲刺撞到实体茎 | 碰撞停止冲刺并修正位置，但这条分支不发出阻挡事件；干叶帘则可被冲破 | 两类对象需要清楚的形状、材质与触碰反馈；这里只能确认表达不足，未证实用户混淆了哪一对物体 |
| 受伤返回与进入恢复点 | 两者共用 recover 事件和“大家都在。喘口气，再一起走。”提示 | 返回原因与进度是否保留需要让玩家看懂；不应靠暂停解释或长篇操作说明补救 |

### 距离商业成品的实际阶段

当前可以称为**核心获得首轮正向反馈、可完整游玩的原型**。以交互、表现、内容和交付分别评估，比给“完成百分比”更可靠：

- **交互与关卡表达：当前首要缺口。** 核心动作已经存在，仍需要一致的教学、行动预告、可用状态、成功／失败原因与空间安排。用户指出的是难以理解；不把加内容或加难度作为默认答案。
- **美术：尚未达到本项目期望的成品表现。** 用户明确觉得粗糙；当前代码绘制的矩形茎、共用植物形状和有限角色动作也支持其仍是原型视觉的判断。提升应覆盖角色轮廓与动画、场景构图、交互材质、效果和 UI 的一致性，并落实到运行中的整章；程序绘制本身并不妨碍商业化，也不能只用概念图替代游戏中的效果。
- **内容与持续体验：证据不足。** 目前只有三段固定旅程，尚未证明更长体验的变化密度、制作成本或陌生玩家的持续兴趣。伙伴主要是可见同行，成员增加没有展开为多套规则；这属于未来内容设计的约束，不是本次澄清后的首要诊断，也不要求增加属性、装备或护送负担。
- **音乐：保留已有基调。** 后续可以随整章安排检查音乐转折和行动音效，暂不推翻重做。
- **产品交付：有原型基础，缺目标产品验证。** 已有 macOS 包、段落保存、暂停、恢复与自动检查；目标平台的兼容／性能、设置与可访问性、完整内容的存档边界、陌生玩家试玩和发行准备尚未形成成品验收。所需范围取决于最终产品，不把每个功能都列成强制清单。

距离一个有代表性的商业品质试玩章节，最直接的工作是把**交互表达与美术做成同一套可运行的完整体验**；距离可收费的完整作品，还要证明其内容和完成度能支撑所承诺的体验。核心暂不需要推翻，但剩余工作仍是实质制作，不能说“换套美术就能卖”。未确定目标平台、篇幅、售价和制作资源，因此不提供缺乏依据的工期、预算或完成比例，也没有销量／付费意愿证据。

### 下一里程碑建议与验收边界

建议把现有三段重制为**一章成品质量样板**，整体交付一次：保留飞行、收拢冲刺、同行与音乐基调，统一处理操作教学、物体可用状态、方向预告、失败反馈和角色／场景美术。优先用环境、动作和声音传达规则，文案只补必要信息；不是给每个困惑加一条常驻提示。

验收以从标题到结尾的完整体验为单位：玩家无需开发者临场解释，就能知道目标、预判关键动作、分辨物体用途和理解恢复原因；各段画面与交互达到一致完成度，核心体验仍被认可。Alan 评审整体效果，未参与制作的玩家用于另外验证理解与节奏。具体关卡卡点未知时，不能先承诺某项小修必然解决。

本轮只归档反馈和评估，没有改动游戏或重新打包；上述里程碑是 Codex 的建议，尚未开始实施，也没有批准扩写全年、批量内容或发行。Codex 负责本轮完成记录与 PR 收尾；下一制作任务以完整样板章为建议验收点，具体工期与资源未承诺。复查触发条件是新的具体试玩证据或后续制作授权。

## 2026-10-20 整章样板制作

Alan 已明确授权整体打磨现有三段，保留核心与音乐，完成后整体试玩。Codex 负责同一 PR、整包、检查证据和清理；本轮交付前完成，不承诺商业发行日期。范围是独立工程的规则表达、世界绘制、UI、交互音效、验证与交付说明，以及本记录、README 和唯一 Now；没有扩写全年内容或旧工程。

### 新反馈与纠正

会话证据 `SF-R02`：制作期间 Alan 评价“美术的ai感太重了 游戏也没有计时等机制 感觉体力消耗也不明显”。当时中间包使用三张生成的绘本图像，所谓体力实际上只有受雨击才减少的三点生命。本轮未取得该次录像、完成段数或时长，不把反馈补写成已全章验收。

据此撤下全部生成图片，改为统一的少色植物剪纸／套色版画表现：墨绿实体、奶油金交互、薄荷风花、蓝灰暴雨，靠轮廓、构图与动作表达用途；图形由代码绘制。此前图片和来源记录仅保留在本地中间产物归档，不进入最终包。这是本轮美术选择，是否足够自然和完整仍由整体体验检验，不能以“移除了 AI 图片”直接声称成品质量已获认可。

### 最终规则与表达

保留连续飞行、按住蓄力后释放、同行伙伴、三个原有段落和音乐。风花箭头使用与真实发射相同的方向，使用后闭合且去掉箭头；实体茎与干叶帘形状区分。提前松开、撞茎、救援、初到叶下、手动返回、雨击、耗尽及超时分别有原因说明。叶下真实遮蔽范围位于叶冠下方，无风漂，边缘也受保护。菜单支持方向键选择，保持画面比例，避免提示遮住关键物体。

体力改为单一 100 点资源，不再把三个生命点称作体力。HUD 每格 20 点；蓄力预告冲刺成本，消耗留短暂残影，数值与状态同步。参数是本轮设计假设，单位和来源均为独立工程 `game_model.gd`：

| 行为／条件 | 实际变化 | 用途 |
| --- | --- | --- |
| 首次操作前 | 不消耗，不倒计时 | 安全读懂开场 |
| 起飞后露天飞行／悬停 | 每秒 −2 | 看见持续成本，鼓励规划行动 |
| 成功释放冲刺 | −20；不足 20 时不释放并说明原因 | 连续冲刺有成本；最后一次冲刺允许飞完再判耗尽 |
| 雨滴或雨线命中 | −30，1.8 秒保护间隔 | 错误有代价，避免连续判伤 |
| 救出一组伙伴／首次借风 | +40／+8，上限 100 | 行进目标能补给，借风有回报 |
| 在大叶下 | 每秒 +24，上限 100 | 短暂休息恢复，回访有效 |
| 前两段 | 显示旅程用时，无硬限时 | 学习和运用动作 |
| 第三段 | 起飞后暴露时间预算 55 秒；叶下、菜单暂停 | 明确最终回家的时间压力 |
| 耗尽／超时／主动返回 | 回最近恢复点，补满体力，计时恢复到记录值且至少 20 秒 | 已救伙伴保留，避免晚检查点反复超时 |

结尾显示本次旅程用时和返回恢复点次数；跨应用续玩仅保存段落，不冒充跨会话总计时。主动返回可以补给但计一次恢复，不设竞速排行榜或把它称为严格竞技规则。音乐的合成、编曲、环境音、混音和段落切换保持原基线，仅补充交互音效。
