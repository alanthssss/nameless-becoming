- **【待验证】** 需要工程、运行或真人证据才能确定的判断。

## 2. 成品范围与核心循环

### 2.1 本稿选择的范围

**核心内容：** 四季关卡、飞行与蓄力冲刺、一次性风花、持续气流、实体与可破叶帘、露珠与体力、喷嚏花／水幕、天气与遮蔽、叶亭与恢复、少量救援、常态生物遭遇、四位有独占玩法的Boss角色、小满等同伴、蜂舞交流、无字色卡载体、完整开场和结尾。成长以玩家的熟练与认识为主，不靠提高属性。

**为完整旅程需要新增的能力：** 区段天气转换；事件来源与少量故事事实；帮助后改变棚面的机关；四位大型角色的独占状态与场景；蜂舞观测／报告；局部色卡窗；选定风花新形式；20关目录／章节进度；成品设置、手柄与平台验证。它们是本稿推荐的设计依赖，仍须逐个切片证明可用，不是已有能力。四场Boss放在05／10／15／19原高峰位置替换编排，不在关尾加四段冗长内容。

**备选：** 可转风轮、输入缓冲、动态音乐分层、个人熟练挑战、更多剧情分支；风花形式库中的摇曳、呼吸等按关卡需要择用，不全部成为首发配额。无证据需要就不做。

**不纳入本作主循环：** 运货日课、库存、经济经营、装备树、战斗升级、挂机收益、联网排行、可付费数值成长、强制全收集。四季不是日历模拟，季节推进不要求重复刷天数。

### 2.2 三个尺度的循环

1. **即时动作：** 看落点与预兆→普通飞行调整／蓄力→释放冲刺或主动绕行→身体、对象、声音及时回应→在新位置选择下一步。
2. **一段旅程：** 识别一个地标与局部目标→运用熟悉动作完成不同空间关系→看见开门／相遇／新视角→经过安全落点→继续。叶亭服务恢复，不是每段必停的结算站。
3. **整部游戏：** 春天学会看与飞→夏天选择时机与飞法→秋天在变化的花园重新找路→冬天运用持续风与邻里成果→亲手抵达老树，结束旅程。

**为什么不总选同一招：** 冲刺快，但方向锁定且消耗体力；普通飞行适合转角和观察；风花省去重新起冲，但承诺一个落点；持续风会持续作用，需要决定何时退出；安抚花获得暂时安静，但绕行也能通达。选择价值来自后续位置与动作，不能只比较哪个给更多奖励。

### 2.3 目标、成功与失败

- **整作目标：** 完成20关主线并亲手进入最终树洞，看到一路关系的回响。20关结构可在正式范围复核时调整，本稿不自行删关。
- **关卡目标：** 到达一个可见终点；少量主线救援须直接位于必经可见位置并明确表现。可选帮助、露珠和分路不锁出口。
- **局部成功：** 到达选择的落点、穿过危险、打开路线或完成帮助；反馈发生在对象和动作处，不等关尾才告诉玩家成功。
- **失败：** 体力耗尽或特定危险段超时，回最近恢复点；不扣永久资源、不损失已提交的帮助事实。主动返回同样安全。
- **主线完成后的价值：** 重玩已解锁关卡、尝试另一条路、飞得更从容；不以全露／零失败作为“真正结局”的条件。

### 2.4 世界变化的设计骨架【v1.1】

24节气用作气候、光照、物理空间和生物活动的内部参考；不是24张标题卡或24个固定怪物配额。20关中01／07／13／16各承载两个相邻参考点，其余各一个；完整色值与变化映射见[24点物候表](swarm-flight-world-elements.md#phenology)。

- 气候先有预兆：雨前叶面和声场变化，风通过叶与花粉表现，冷暖由露天与暖廊的活动对比表现。
- 物理空间要回应：顶盖真挡雨，箱角真遮蔽，木墙建立后风力真的改变；未实现湿滑就不暗改操控。
- 生物按场景活动：蚁沿表面、小虫守荫边、鸟有栖枝、熊有体量；寒冷露天活动稀疏，暖处仍有生活。
- 变化不全靠危险：芽到花、花到种壳、远景虫声渐弱、蜂流改向都可表达；只有影响选择的部分才做新规则。

上述是架空庭院设计，不宣称每个节气都有固定温度、降雪或物种出现；旧资料中未经复核的精确生态表不直接进入玩法。原色卡通过无字花蜡窗与少量色痕承接变化，场景主色调独立设计，见§8.6。

## 3. 操作、动作状态与资源

### 3.1 操作表

| 行为 | 当前键盘 | 成品设计／反馈 |
| --- | --- | --- |
| 飞行与调整朝向 | 方向键／WASD | 保持八向输入；手柄左摇杆同义，死区可调；不新增独立瞄准按钮 |
| 收拢蓄力／冲刺 | 按住空格／就绪后松开 | 蜂体收拢、就绪姿态和短声；手柄主面键，最终映射经设备验证 |
| 提前松开 | 取消蓄力 | 不扣冲刺成本，轻回应；不以响亮失败声惩罚尝试 |
| 返回恢复点 | R，暂停菜单也可操作 | 保留当前快速重试；重映射时避免与主要动作冲突 |
| 暂停／继续 | Esc | 冻结游戏和演出时钟；继续需要安全接手，不让旧按键自动起冲 |
| 确认／菜单导航 | Enter、方向键 | 鼠标与手柄同等可达，不要求鼠标才能退出 |
| 静音 | M | 成品音量设置见第10节，快捷键保留或允许重映射 |

### 3.2 已有动作合同

`自由飞行 → 蓄力中 → 就绪 → 释放冲刺 → 收势 → 自由飞行`。提前释放回自由飞行；体力不足时不释放并说明原因；撞实体终止冲刺，撞可破帘则打开并继续；借风重新给定方向和剩余冲刺时间。

- 冲刺期间不能自由转向；入风花按其预告方向转向。曲线／分瓣风花是新局部规则，不能冒称当前已有，也不改07／08的基础手感。方向预告与实际方向必须同源。
- 持续按住空格可以在上一冲刺结束后开始下一次蓄力。当前不是完全不能衔接，不先增加隐藏预输入。
- 普通松键应迅速收住；持续风区例外，会继续受风影响。蓄力也不使真实气流消失。
- 收拢碰撞半径与展开半径不同，贴边展开不能卡死；动画不得偷偷改变规则窗口。
- 新助力动作均复用飞行、蓄力和冲刺；不为每个物件增加交互键。蜂舞只在明确落脚蜡脾的交流状态复用空格分享，首版单来源直接确认；多来源时仅按住选源态左右切换、上／下离开，待机与播放中任一移动退出；普通飞行空格始终用于蓄力／冲刺。

### 3.3 数值基线，不把调参当内容

来源均为当前`game_model.gd`及长样板的章节覆盖；新关需根据实际路线核算。

| 参数 | 已有值／单位 | 设计用途与约束 |
| --- | --- | --- |
| 普通飞行／蓄力移动 | 250／90 px/s | 普通转向可控；不能降速凑时长 |
| 蓄力有效门槛 | 0.50 s × 0.80＝0.40 s | 就绪表现与可释放时点一致 |
| 冲刺 | 880 px/s，基础0.54 s；风花接力重设0.60 s | 落点要留收势空间；不靠固定理论距离判可达 |
| 碰撞半径 | 普通14 px，蓄力9 px | 关卡按实际碰撞与展开测试，不只看画面缝隙 |
| 最大体力／冲刺消耗 | 100／20 | 成本可预告；满体力不是无穷连冲 |
| 露天持续消耗／叶下恢复 | 2／24 点/s | 起飞后露天悬停也耗体力；叶下可观察，不强迫等满 |
| 露珠 | 默认12；08为4点/颗 | 补给数量须与实际净收益一起核查；不误把3颗小露当36点 |
| 风花奖励 | 默认8；07为4点/朵 | 辅助动作链，不让长链溢出成无意义资源 |
| 救援／首次安抚花奖励 | 40／10点，封顶100 | 显示真实获得量，不按未截断值表扬；重复安抚不刷奖励 |
| 花朵暂时安静 | 6 s；08接触可延续至少0.38 s冲刺 | 历史奖励与当前安静分开，见第7节 |
| 喷嚏预警／08周期 | 预警0.8 s；08喷发周期2.2 s | 保留08现有节奏；初次计时有单独配置，不能仅按周期推第一次攻击 |
| 雨击／喷嚏及喷口命中 | 默认30／12点；受击保护1.8 s | 同时多颗命中不连扣；护雨免伤范围要与提示一致 |
| 护雨叶 | 5 s | 挡指定天气伤害，仍消耗飞行体力；不等于无视实体 |

**资源验算：** 一条实际路线的体力＝起点体力－露天耗时×2－起冲次数×20－有效伤害＋实际补给＋叶下恢复；每次获得受100上限截断。风花／花朵改变动作持续时间，不能只靠这条静态公式判定通路成立，必须跑普通输入。

两条分路的必要补给都要支撑本路动作，共用补给放在合流后。低体力不能只能去一条无趣的绕远路拿露；允许玩家稳定普通飞行到下个恢复点。需要重新发力之前应能预见补给或安全落点，避免出现只能反复自杀的存档。

## 4. 物件、环境和规则组合

### 4.1 物件合同

| 对象 | 玩家读到的用途与输入 | 状态和结果 | 错误／恢复边界 |
| --- | --- | --- | --- |
| 实体花茎、箱角、顶盖【已有】 | 厚实、有根或支撑；绕行 | 阻挡，沿边滑动；顶盖按真实几何挡落雨 | 不能画成可破；冲刺撞上有材质回应，无隐形延长 |
| 干叶帘【已有】 | 薄、卷边、透缝；冲刺可破，普通可绕 | 完整→破开；路径当场显露 | 条件门仅在明确预告条件下使用；不把普通帘无故变硬 |
| 风花【已有】 | 张开的花瓣预告去向；冲刺进入 | 未用→导向接力→收拢 | 同次恢复区间不能重复刷；已用去除可用暗示；错过仍有可行通路 |

### 4.2 区段天气设计【新增状态层】

天气是空间关系变化。10和15使用`晴／预告／降雨／雨后`四阶段设计，19可组合短追雨；不是整关挂一个55秒倒计时。当前全关`storm`和已有局部`rain_fields`可复用部分行为，但不具备完整阶段演变，需单独实现。

| 阶段 | 触发建议 | 可见／可听结果 | 玩家行动 |
| --- | --- | --- | --- |
| 晴 | 初入片段 | 先见棚内外两路与出口 | 认识空间，任选一路 |
| 预告 | 越过可识别前景地标 | 叶面零星雨点、环境音变化；前路仍可读 | 有机会进入已看见的遮蔽，不立即扣伤 |
| 降雨 | 预告完成且进入天气区 | 露天落雨；实体下没有穿顶雨滴 | 选择短穿越或沿棚路线；安全处可观察 |
| 雨后 | 越过明确出口边界 | 危险清理或自然退场，雨声淡去，背景重新明亮 | 回到正常飞行，获得真实舒展 |

预告时长、雨强和段宽从切片实测确定。本稿不要求全球动态天气、自由时间或季节模拟。重试从片段起点恢复时重给可读预告；精确挂起则保存当时阶段及计时，继续前暂停。不能用读档跳过预警或反复触发奖励。

**实现注记（2026-10-27）：** [SF-R48](swarm-flight-game-20261020.md#weather-window-slice-20261027)的0.15.1独立《叶下的光》已做出一处晴→预告→降雨→雨后、真实叶棚挡雨与色窗两段变化，并验证精确恢复。它未接为完整10关，不代表暖廊、风花天气状态或全篇环境音已实现。

### 4.3 同时发生的事件

沿用现有有意义的规则次序：到达有效终点优先于同子步天气伤害；护雨拾取早于天气判伤；一次受击后启用保护；一次恢复终止旧帧输入。新机关与剧情不能依赖渲染帧巧合。剧情只订阅带来源的已发生事件，不自行加体力或移动玩家。

### 5.6 09代表切片与正式关卡的边界

目标是检验“借力决定下一步位置”。先做约3600～4200 px宽的独立片段作为试排初值，沿用当前纵向活动范围与角色参数。这个宽度不是正式09关长。

- 入口视野能辨认上方风链及高落点、下方宽廊及低出口；若同屏放不下，提前用地形开口显露，不先做强制镜头飞览。
- 上路只用一次三节点接力，落点后留宽收势区，再向下穿窗；下路绕低花台作一次宽转向后进入共同出口。
- 两路合流之后取露，下一目标提前可见；普通路不会因避开风花而被剥夺续航。
- 验证正常两路、错过入口、低体力、退出再继续。技术验证确定能走，真人观察确定是否看见后续差异、是否形成自己的选择。
- 若两路只有速度差而后续动作相同，先改出口与转角关系；不能靠延长下路或收窄上路补“差异”。

**0.15.0实施记录：** 已接入3600 px落点选择＋6000 px两段反向接力／主动换层＋700 px短尾声，另有出口空间；07→08→09连续、独立09与r8保存见[SF-R47](swarm-flight-game-20261020.md#wind-choice-slice-20261026)。这是既有定向节点的关系验证，没有实现真曲线、动态分瓣或正式09完整篇幅；真人是否看懂并愿意选路仍待观察。

正式09应由这个关系的发展组成，而非复制同一片段数次。完整动作规格与N01事件交接见[候选稿第8节](swarm-flight-design-opportunities-20261026.md#8-两份可直接交给制作的示例规格)。

## 6. 节奏、难度与内容厚度

### 6.1 节奏在四个尺度成立

| 尺度 | 编排方法 | 本作例子 |
| --- | --- | --- |
| 一次动作 | 预告→主动输入→可见结果→可衔接位置 | 读花预警，冲过花体安抚，接露抬升穿帘 |
| 动作群 | 有一个目标，多步相关动作；末尾收束并露出下一目标 | 借风越高窗，收势入低廊，再从低处起飞 |
| 单关 | 先建立中心判断，再改变语境，给予舒展与一次兑现；不固定段数 | 09相似入口不同落点，10相同棚在晴雨下不同用途 |
| 四季整作 | 变化观察焦点、精度、环境压力和人物关系；高峰后降压 | 夏读时机，秋读空间，冬重新低压认识持续风；19高峰、20归来 |

**判断一段是否有内容：** 玩家有可说明的行动目的；途中至少发生位置关系、时机、后果或认识上的发展；下一段不是再次教同一件事。纯景观也可以短暂承担舒展，但不能大量计入有效主线厚度。

先避免连续三组高压操作、新规则首现叠追赶、每个庭院都回亭重置。这是有条件的编排启发，不是不可破的数字规则。例外只需说明它服务何种体验并验证，不另加审批流程。

### 6.2 难度是五个独立维度

| 维度 | 低负荷做法 | 增长方式 | 不采用的捷径 |
| --- | --- | --- | --- |
| 操作精度 | 宽通道、宽收势位 | 少量可选紧凑路线 | 所有关卡不断缩缝 |
| 时机 | 可停处看完整预告 | 在已知空间决定何时起飞 | 隐藏预警、突然加速弹丸 |
| 路线理解 | 可见地标和出口 | 同一空间从另一侧理解连接 | 无地标盲路／强制迷宫 |
| 资源计划 | 关键动作前可预见补给 | 安排冲刺位置，选择接力 | 必需补给只在无趣绕路 |
| 失败代价 | 当前动作群重试 | 在完整高潮中保持连续感 | 重走长空路、扣永久货币 |

主线初次提高其中一个维度时，其余尽量保持熟悉。可选熟练路线提高精度，但不会独占剧情、基础补给或真结局。当前07／08作为控制与连续体验的参照，不作为后续关卡的同难度模板。

### 6.3 时长核算与未决矛盾

原SF-R32的20关／6～8小时曾用单关分钟窗口试排；07实际反馈已经说明，不能继续机械套表。**本稿不同时承诺“07维持当前节奏”和“所有关强行达到旧分钟下限”。**

记录每关的主线行动与理解、可选探索、正常重试、演出、无目的移动与等待。互斥路线只计实际走的一条；重玩和全收集不补主线缺口。样板完成后用自然试玩的分布重算全作：如6～8小时不成立，应在既定产品复核点比较增加真正新关系、调整篇幅承诺或调整资源三种取舍，不能暗中注水或自行缩水。当前没有新的可靠小时数与上市日期。

## 7. 故事、角色与事件剧本

### 7.1 故事梗概

一只新蜂看见同伴在巢脾分享花源，随后亲自飞到花园。它会借风与收势，也逐渐学会看见别人的习惯：蚊庄主把自己的牌挤满通道，油葫芦跳得潇洒却总掉工具，画眉被好听的回声留住，大熊想帮忙却把长木卡在转角。雨露、光影、植物与蜂流一路变化；玩家通过穿行、解开局部障碍和传递真实信息参与其中。最后风被新架起的木墙挡住，熊安稳睡下，同伴继续沿刚分享的花路出发。玩家自己飞进老树，看到沿途色痕已在熟悉的窗里连成一圈。

这条故事由行动发展构成。角色没有神秘身份、牺牲或世界危机；不由旁白宣告“你已成长”。终点有归属感，但沿途发现与亲手飞行承担主要卖点，避免把整个游戏写成赶回家。

### 7.2 角色表与资产边界

| --- | --- | --- | --- |
| 玩家小蜂 | 好奇、急于试试；蓄力收拢，收势后舒展 | 从看眼前目标到主动安排下一步 | 当前蜂体为基础，不设职业／属性成长 |
| 小满【已有邻居】 | 愿意先搭把手，顶叶棚、给同伴让出落点 | 06建立互助，07尊重不同来路，18兑现空间帮助，20会合 | 先补支撑／放手／让位动作，联系主要角色，不新增整套日课系统 |
| 画眉【已有邻居】 | 侧头听风，普通鸟鸣；会记错旧路 | 03预见，08局部回应，11纠正指路，13回声铺垫，15独占高峰，20短鸣 | 身体保持自然鸟体；对白服务事实，不当万能导航牌 |

v1.1恢复蚊庄主、油葫芦、画眉、大熊四位大型角色的完整设计位置；老师傅与其他旧角色仍按具体功能取舍，不自动恢复旧24关任务。四位不是四种道德寓意，角色缺点、长处与自己的收尾动作必须同时可见，见§7.7。

### 7.3 四季情绪线与对白口吻

春：好奇和小成功；夏：各有飞法、互相搭手；秋：认错路也能一起重新找；冬：更从容地使用风与一路形成的关系。每个角色以“习惯—造成的局面—玩家介入—角色自己收好”出现，不担任某个错误价值观的代表。

台词短、具体、正常。可以是“我走叶下，前面见”“刚才多亏你，这会儿我躲叶下就好”；避免“你终于找回内心的节律”“真正的勇敢不是……”等说教。对白不是唯一规则提示，不遮住主要行动方向。玩家不停留时允许漏听闲话，关键结果在画面可读。

### 7.5 可实施事件脚本：08画眉与喷嚏花

绑定一朵稳定ID的花、一处亭、一位画眉。现有“任意花rewarded则说已安静”的条件需要替换；新事件来源字段、故事事实和保存支持均为新增工作。

| 条件 | 角色／场景动作 | 台词示例 | 数据结果 |
| --- | --- | --- | --- |
| 玩家接近，指定花将喷 | 画眉侧头后缩入叶下 | “它又要打喷嚏了。” | 不写帮助事实，不暂停 |
| 指定花被安抚，玩家仍附近 | 花泄气，画眉放松，翅膀落下 | “呼——终于能歇口气了。” | 记录本地曾安抚；奖励仍由花规则负责 |
| 玩家由绕行出口到亭 | 画眉沿叶下换位 | “我走叶下，前面见。” | 记录实际会合，不把未取露当绕行证据 |
| 帮助过，但花已恢复 | 画眉留在安全位置 | “刚才多亏你；这会儿我躲叶下就好。” | 当前安全读花状态，历史帮助读事实 |
| 玩家已离开 | 不强拉镜头，不远处播放重要长句 | 下一会合处可简短承接，或沉默 | 不排队播放一串过时对白 |
| 暂停／重试／挂起继续 | 冻结或正确恢复姿态与一次性演出 | 不重复奖励／陈述过时状态 | 依第11节事务恢复 |

**编剧交接最小字段：** 事件ID、对象ID、触发范围、前置条件、角色动作、台词ID、事实读写、打断／离开规则、重入规则、保存策略、结束状态。少量事件先用专用条件函数；不为本作直接引入庞大分支引擎、好感度或脚本语言。

### 7.6 开场与结尾分镜

**开场（01）：** 标题画面已能看见菜圃、巢门花蜡窗与一小片真实蜡脾上的交流；选择新旅程后角色在宽叶附近，等首次输入。NPC舞蹈与听者出发可见但不强制观看。短句“小满：先到前面那片叶子，我等你。”随第一次移动淡出。卷叶里伙伴的动作引出冲刺，完成后它先飞走给玩家留位置。风花入口把视线带向喷泉。全程控制不中断，剧情不会在玩家还没理解方向时持续播放。

**结尾（20）：** 19高峰已结束；20进入低压叶廊。沿玩家正常前进路径，以短场景痕迹承接花牌、补棚、种壳、挡风木；焦点回应最多突出一两处，不逐项盘点。小满挪开半步，画眉在高处短鸣，大熊在挡风墙外安睡；花蜡窗收束色痕，花源有效时可在安全落脾处分享给新蜂，移动即可离开。玩家亲手飞过树洞边界才触发抵达。蜂体收翅，洞内暖光接住，出现“你回来啦”。随后制作名单可跳过，回到“继续看花园／选择关卡／返回标题”。无帮助事实也有完整温暖结尾，没有坏结局或隐藏结局惩罚。

### 7.8 蜂舞的信息链【v1.1】

已经找到三部《养蜂手册》原PDF并核验身份；本轮实读江西版书内39–42／PDF57–60页（图23、24）。蜂舞传递资源方位与距离的依据及现代交叉来源、原件路径见[蜂舞资料与设计](swarm-flight-world-elements.md#bee-dance)。游戏用地图方向与近远节拍作抽象，不声称模拟太阳导航，不以固定米数考玩家。

**三个情境：** 01在真实蜡脾见返回蜂交流、听者出发，03在花源看见信息兑现；03可自愿确认花源，05落脾后用空格分享，听者真实改变下一次出发；12可见NPC更新过时花源，20有有效报告才让新蜂接着出发。没有花源不硬播“庆祝蜂舞”，没有观看不挡主线，也不每关要求回巢。

**实现合同：** 提议`resource_observation`保存来源ID、有效版本、方向、近远、花形；明确落脾交流态与飞行态。第一段完整信息传递后提交，提前移动离开不提交；重复不加奖励／蜂数；暂停、挂起和重试保存演出与事实的一致性。首版一来源、一舞区、两听者，不先做庞大选择界面。旧`godot/playtest/rain_route/bee_social.gd`只供舞步／取消参考，不直接移植旧Q键、固定六蜂、日程或存档。

验证信息是否被理解、听者是否按真实来源出发，覆盖取消、重复、来源失效与读档。若只像庆祝动画，先完善接收动作和去向，不用文字告诉玩家它有意义。

## 8. 美术、动画、镜头与反馈

### 8.1 统一美术方向

【确认】沿用当前获得方向认可的手绘庭院表现：圆润角色、明确轮廓、柔和体积、温暖色彩与植物材质。0.14.1手绘感叹号已替换被拒绝的硬边版本；本稿不重做成几何警告牌。美术目标是同一世界里的可信对象，不是单张素材细节越多越好。

| 层次 | 画法与作用 | 具体约束 |
| --- | --- | --- |
| 远景 | 天空、树群与庭院生活提供季节和去向 | 降低细碎对比，不假装可碰撞；地标必须能从后续视角认出 |
| 可玩中景 | 箱、茎、叶亭、风花、角色 | 轮廓与碰撞用途一致；重物有支撑，短茎有根或合理遮挡 |
| 前景 | 少量叶沿与花盆建立深度 | 不遮住攻击预兆、关键落点和转角；不在接力链正前方突然遮屏 |
| 效果 | 花粉、叶碎、风线、水珠、短光晕 | 用世界已有材质，按事件重要性控制强度；不靠全屏闪光解释成功 |
| UI | 叶／木／暖金材质，清楚中文字 | 字体清晰优先于装饰；与角色警告保持同族，避免现代硬边图标突兀插入 |

**优先修正的真实视觉问题：** 叶亭下横绿线应删除或改成有明确来源的叶脉／挂件，不能像碰撞边；画面底部孤立短茎应连到可信的地面或被前景合理遮挡，保留真实碰撞；叶帘与实体叶墙需要薄厚、撕裂边和状态差异。以上均是后续候选改动，本轮未修改素材。

### 8.2 季节差异必须同时服务空间

下表季节名是制作分组，不出现在游戏界面。主场景保留自己的自然用色；原色卡只经§8.6的特定载体与局部色痕呈现，不绑定每关主色调。

| 季节 | 形态／构图 | 综合色调 | 动作关联 |
| --- | --- | --- | --- |
| 春 | 低菜架、泉桥、开放水面与宽叶 | 鲜绿、浅黄、明亮天空 | 宽轮廓帮助初学读落点，水面给舒展 |
| 夏 | 花篱内外、长棚、饱满花架 | 深绿、花紫与暖金 | 上下层互见、预警与叶冠保持对比 |
| 秋 | 果箱、枝条、层叠台面 | 赭黄、果木棕、温暖斜光 | 明确箱角与遮蔽关系，枯枝不画成陌生机关 |
| 冬 | 暖廊、霜窗、背风台面与老树 | 冷蓝背景配暖灯 | 飘动叶粉显示持续风；暖廊与真正安全区对应 |

季节不是给同一张地图换色；不同的轮廓组织、视线关系和主要判断共同构成区别。保持蜂与关键预告在明暗背景上可读，不能只靠红绿区分状态。

### 8.3 最小状态资产表

| 家族 | 成品需要的可辨状态 | 可复用办法 |
| --- | --- | --- |
| 玩家蜂 | 普通、转向、蓄力、就绪、起冲、收势、受击、叶下休息、抵达 | 主轮廓统一，姿态／翅膀／拖尾组合，不为每关新画角色 |
| 风花 | 张开可用、接触动作、收拢已用 | 方向与模型同源；可共用季节变体的状态结构 |
| 喷嚏花 | 闲置、预警、喷出、安静、恢复 | 当前手绘预警保留，优先补身体状态连贯 |
| 叶帘／实体／棚 | 完整与破开；实体材质；棚支撑与展开 | 同族边缘和厚薄；破开后留下可识别结果 |
| 小满／画眉 | 识别待机、注视、支撑或避让、回应、离开 | 只制作事件实际使用的动作，不预先铺满表情库 |
| 蚊庄主／油葫芦／大熊与常态生物 | 日常习惯、明确预告、独占动作、出错、自己收好；真落点与大体量扫掠 | 先做一位首段验证人格可读，再制作四位；不以三张状态图代替整场动画 |
| 四季环境 | 地标、危险前告、危险中、压力解除 | 关键地标先做运行样板再扩产，不批量生成未选镜头 |

素材需记录来源、用途、透明边缘、尺寸与状态映射；生成或购买的原图不是已可用游戏资产。现有来源登记沿用，不在GDD里重新复制一套授权结论。

### 8.4 反馈层级

1. **安全与行动窗口优先：** 预警、受伤原因、可释放状态应能看见和听见；静音时仍可理解。
2. **关键成功其次：** 开帘、救援、安抚、进入新通路各有自身动作和短声音；强度高于普通露珠。
3. **连续小奖励克制：** 同一动作群连续取露可合并少量声音／文字，不让多次浮字盖住出口。
4. **角色回响留空：** 画眉的放松、小满让位可在短安全段被注意到，动作发生后不叠三条系统表扬。

不以额外卡顿、强震屏或延迟操控“加强反馈”。关键受击可用短身体变化；镜头震动与闪光提供降低／关闭选项。新增缓冲只在复现遗漏输入后试验，不改动玩家尚未抱怨的节奏来追求通用手感清单。

### 8.5 镜头设计

当前镜头主要横向跟随，逻辑画布1280×800，玩家在约480 px横向偏移附近。本稿优先用关卡布局提供前方信息，不先增加镜头系统。需满足：冲刺进入前能预见关键出口，转向后能辨认下一目标，画面边缘不会突然出现必须立刻反应的危险。

场景演出尽量在玩家前进视野内发生；不强拉镜头看NPC、不用突然缩放掩盖布局。若一处确实需要更远预读，先做独立镜头对照并验证输入控制、遮挡和晕动，再决定是否添加前瞻；不是全关默认项。

### 8.6 色卡通过无字载体表达【v1.1】

保留[原色卡](../COLOR_SYSTEM.md)四锚：玄`#101420`、青`#008080`、朱`#DC3C3C`、白`#F5F5F5`及24点色值。它们**不规定每关主色调，也不改变危险／安全功能色**；不能给全屏套滤镜，更不能把朱色阶段所有角色都染成红色Boss。

主载体选巢门旁的**花蜡窗**：24块不等大的弧形半透明色片，带手绘叶脉；角色世界里的拟人化造物，不当作真实蜂学。旅程中相邻色片的透光位置逐渐改变，01／05与10／15局部呼应、20完整回望；不出现色名、节气名、解锁文字、未完成格子和收集指标。沿途只在少量花瓣边、叶脉、水面反光呼应，不强制每关设一扇窗。

暂停“旅途”可用已见地标剪影与窗片无字回看；没有补齐和真结局门槛。采用E04原色卡的局部组件，旧`seasons.json.colors`的四元组不混作同一来源。完整映射与验收见[色卡表现形式](swarm-flight-world-elements.md#color-window)：四锚＋过渡原生对照，灰度仍有位置／轮廓线索，角色、露珠与手绘感叹号辨识度不下降。

## 9. 音乐、音效与环境声

【已有】三套原创合成音乐／环境声交叉淡变，以及Music、SFX、Ambience总线和动作事件音效。保留俏皮、温暖的现有方向；三首不等于四季全部音乐已完成，也不等于每段动态配器已有。

**成品音乐方案：** 用共通短动机连接四季；每季至少有可辨认的音色或编配差异，具体独立曲目数待运行试听确定。春轻巧清楚、夏稍有弹性、秋留空间、冬在疏冷环境中保留暖声；19增加推进感，20释放密度，允许最后的鸟鸣和抵达声露出来。不能简单按角色速度加快音乐，也不强迫操作对拍。

| 声音 | 设计信息 | 实施方式 |
| --- | --- | --- |
| 蓄力／就绪／冲刺 | 从准备到可执行再到发力 | 以真实状态事件触发；就绪只提示一次，长按不持续刺耳 |
| 借风 | 接住力和方向变化 | 同一链可作轻微音高／音色发展，不逐朵提高音量 |
| 普通露／开帘／救援 | 区分补给、路径改变与关系结果 | 普通露轻，叶帘有叶材质，救援给短角色回应；共用事件池避免爆音 |
| 花预警／喷发／安静 | 吸气、喷出、松气 | 预警不被音乐淹没；安静状态不继续循环攻击声 |
| 天气 | 告诉玩家压力出现与解除 | 本地雨区驱动淡变；叶下改变音色／强度，离开雨段确实退去 |
| NPC／结尾 | 角色存在和停顿 | 画眉自然鸣叫，小满轻短动作声；不强制配全对白语音 |

四位大型遭遇各有独占声音：庄主数牌与绳响、油葫芦真实落点及迟半拍工具响／腹部三拍、画眉的真声与回声、熊的脚步木响与长哈欠。它们既表达性格也预告行为，不能都套同一警报。蜂舞用近距翅振与听者动作，不做胜利庆祝音乐；色窗变化无需每次播解锁音。

首版可先为代表段做稀／密两个编配版本，使用现有交叉淡变能力；更细的实时分层是备选，需要额外资源与播放状态支持。暂停、重试、挂起都保持声音与游戏状态一致，不叠放重复音乐。验证同时包括波形／削波技术检查与原生连续试听，后者不能被数值报告替代。

## 10. 界面、引导与辅助体验

### 10.1 完整流程

`标题 → 新旅程／继续／选关／设置 → 关卡飞行 ↔ 暂停 → 短关间衔接 → 下一关 → 最终抵达 → 制作名单／重玩`。

新旅程覆盖现有进度时明确确认并允许取消；继续优先恢复挂起状态并停在安全暂停界面；没有有效挂起时从已提交恢复点继续。选关只显示已解锁关；开发入口与正式选关分开，不让开发捷径冒充通关进度。结尾后可以重看尾声和重玩，不自动清空完成记录。

### 10.2 HUD与场内提示

**v1.1玩家文案约束：** 移除“夏·第08关”等显式季节标签；HUD只显示地点／关名与眼前目标。15显示“箱影下的新路”，不用“秋雨中的新路”。选关、字幕、场景卡和旅途回看也不出现24节气名、阴阳比例或人格标签；调试数据允许保留。天气可用“雨要来了”等自然短句，关键仍由画面／声音预告。

保留体力、当前局部目标、必要状态。旅程用时与露珠计数可降到次级，是否常显由实机可读性选择；它们不是催促或完成度债务。目标应是眼前可做的事，例如“借风越窗，再落到叶下”，不写后台术语或整关解法。

蓄力成本预告与实际体力一致；伤害和恢复原因短暂优先，普通取露不覆盖它。护雨剩余时间只在保护时出现。对白放在角色附近，避开前进方向与攻击预警。章节衔接简短并可跳过，下一关等待新输入后再启动危险。

### 10.3 引导与继续

- 新规则第一次出现在可观察且能退开的区域；示范之后让玩家自己做，不要求读完说明书。
- 方向指引指向真实可达目标；已有地标足以引导时不额外加箭头。
- 隔天继续的暂停卡显示关名、最近地标和一句当前目标，状态从存档读取，不生成虚假剧情回顾。
- 连续失败时先明确原因，允许返回安全处；不以强制降低难度或弹窗打断每次尝试。

### 10.4 成品设置与可访问性设计【尚需实现／验收】

| 项目 | 最小成品功能 | 验证 |
| --- | --- | --- |
| 输入 | 键位重映射、冲突提示、恢复默认；手柄导航和飞行 | 从标题到结尾无需鼠标；拔插后不残留输入 |
| 声音 | 总音量及Music／SFX／Ambience独立控制，静音 | 退出重启保留；静音仍能读预告 |
| 显示 | 窗口／全屏、保持纵横比、文字可读 | 至少核对现有960×600最小窗口与1280×800逻辑画面，不因缩放遮关键按钮 |
| 动效 | 震动／闪光降低或关闭 | 危险与就绪信息仍保留 |
| 动作辅助 | 首选试验“更宽松的蓄力操作”和危险节奏辅助，具体模式先验证 | 不能暗中改存档规则；不将辅助玩家排除出剧情与通关 |
| 认知负荷 | 简短目标、可靠暂停、可重看基本操作 | 不靠颜色或声音单通道传递必需信息 |

辅助项以实际困难选择，先做一个代表模式再决定其他项；不一次承诺大量难度档。若采用切换蓄力，应明确“按一次开始、再次按下释放”，与当前按住松开的规则分开测试，避免误触自动冲刺。

## 11. 章节进度、恢复与叙事记忆

### 11.1 三种状态，不混成一个存档布尔值

| 层 | 保存什么 | 何时恢复／提交 |
| --- | --- | --- |
| 精确挂起【样板已有】 | 位置、速度、蓄力、冲刺、危险计时、活动物件、随机状态、当前演出阶段 | 退出后继续到原局面；先暂停，解除旧输入，不悄悄向前模拟 |
| 恢复点事务【已有基础】 | 合法安全位置、已提交物件状态、必要救援与本地故事事实 | 失败／主动返回时回滚未提交变化，恢复体力并清除临时危险；不能退到无法继续的局面 |
| 跨关旅程记忆【新增】 | 解锁／完成关、已提交故事事实、必要季节结果、设置与存档版本 | 正常跨关提交；重玩与新旅程分别有清楚语义，不因重玩失败抹掉首次旅程事实 |

当前长样板r7只有两关，并有严格字段白名单、动态对象字段和形状校验。旧16关档与07／08样板档独立；正式20关档采用新旅程ID与版本（提议），不能把旧数组按新关号直接解释。旧档保留可读，迁移只有在稳定ID和状态含义明确时才提供；否则明确为新旅程，不覆盖用户旧进度。

**v1.1新增字段边界：** Boss阶段／已打开通口、曲线进度／分瓣选择／花相位、花源观测／报告与听者状态、花蜡窗物候索引都需稳定ID和版本。物候由叙事推进，不读现实日期；重玩不倒改主旅程色窗。怪物和环境阶段按同一恢复点事务回滚；不能只存剧情成功而让几何或生物留在旧状态。

### 11.2 具体恢复合同

1. 经过恢复点可登记安全位置，不必实际落入亭中；体力恢复与遮雨只在真实叶下发生。
2. 露珠、风花、花朵奖励与故事事实遵从同一提交边界，不能回滚花朵却保留可重复发奖的故事触发。
3. 救援当前会提交恢复快照。新增剧情应沿用或明确调整这个合同，不随意增加每句对白自动存档。
4. 动态叶棚碰撞、角色表演状态与帮助事实必须一起保存。读档不能出现“剧情已展开，几何仍封死”。
5. 章节重玩使用独立会话快照；回到主旅程保留主线进度。是否把重玩完成的可选帮助写回旅程，首版推荐**不写回**，界面明确标为重玩，避免故事时序倒流。
6. 正常跨关、存档损坏、写入失败都有可见处理；失败时保留上一份有效文件和当前内存进度，不静默清空。采用临时文件验证后替换与备份属于正式存储新增工作。
7. 读取有效但旧的精确快照，若关卡几何已不兼容，回退到该版本明确对应的安全恢复点或保留旧入口；不得随机放到新墙里。

一次性演出与奖励分开记；每帧绘制不写事实。花重新喷嚏是当前世界状态，不能因为“曾帮助”而永久显示安静。

### 12.2 内容交接最小数据【提议】

一个关卡交接包含：`chapter_id`、显示名称、季节、主要判断、入口／出口、连续空间区段、对象稳定ID、可玩几何、地标、恢复点、天气阶段、必要目标、可选事件绑定、音乐区域和本关验证路径。每个对象必须能指回其规则家族，不能在画面里凭空增加玩家以为能用的机关。

一次叙事事件交接包含第7节字段；一次新素材交接包含来源、目标尺寸、可用状态、碰撞参照与导入设置。参数优先保持当前ID，文档描述与代码值变化一起更新，避免另立一套同名参数表。

### 12.4 运行质量与文本交接

成品按离线单机设计，运行素材随包，不以联网加载作为通关前提。建议以1280×800逻辑画布、目标60 fps稳定帧时间作为首轮性能预算；这是待指定目标设备验证的工程目标，不是当前已达成的全平台承诺。测试最密集水珠／风花／天气组合和持续游玩后的内存，不只测空场景。最低配置与支持系统版本由实际测试确定，不能从编辑器运行推断。

文本使用稳定台词ID与可替换字符串；HUD避免把字嵌入图片，留出译文伸长和字体缺字处理。首次交付优先把中文目标、原因提示与角色口吻做到一致；其他语言进入首发前单独检查排版、输入提示和关键规则含义。无障碍、性能与本地化工作计入产品工时，不能从关卡成本之外遗漏。

### 12.5 资产与工作量怎样估算

按“玩家动作家族、小满＋四位大型角色、常态生物行为、已有物件＋选定风花形式与场景机关、四季环境／花蜡窗、蜂舞与事件状态、UI与音频”建生产清单；不按20关逐关复制整套资产。同一资产进入不同几何后仍要重新检查支撑关系、碰撞、缩放和遮挡，不能把复用当零成本。

每个代表片段记录设计、编排、程序、美术、音频、验证、返工及外部等待，生产估算＝已选择内容的代表实耗＋一次性产品工作＋已观察返工＋无法并行的等待。不是“复制一个关5分钟×20”。当前历史累计与主动工时缺口尚存，剩余可靠预算／日期未知；200＋40小时控制和10月29日样板／范围／产能复核继续有效。

若代表质量未成立、预测超240小时或仍不可核算，给出有证据的篇幅／制作方式／日期取舍，不自动追加预算、扩产或降低基本质量。Windows设备、手柄、独立玩家、Steamworks／AppID与发行手续仍是依赖；本稿没有采购、招募、开通账号或发布。

## 13. 验证、产品完成与风险

### 13.1 让设计产生可观察结果

| 问题／假设 | 最小验证 | 通过后能说明什么；不能说明什么 |
| --- | --- | --- |
| 操作是否可信 | 普通输入覆盖移动、蓄力、松开、转向、撞角、借风、持续风、恢复 | 规则与反馈一致；不等于人人喜欢 |
| 09是否产生不同选择 | 两路技术可达；不给推荐答案，观察玩家预读和选择原因 | 该片段选择可读；不外推20关耐玩 |
| 10是否重用熟悉空间 | 晴时认识，再进入短雨；观察是否主动使用顶盖 | 天气改变行动；不只是画面换色 |
| 08角色是否有因果 | 近花／远花安抚、绕行、安静结束、快速离开、重入 | 事实正确；真人还需能注意到角色变化 |
| 叶棚帮助是否成立 | 帮助和跳过两条路线，查看棚与伙伴同步结果 | 参与可见且可选；不需要长对白解释 |
| 美术是否一致 | 原生画面中比较角色、预警、物件和背景；运动时再看 | 材质／语义一致；单张概念图不能代验 |
| 07→08节奏是否保持 | 同一入口连续游玩，记录明确卡点和重复感 | 该连续段体验；不代表整季已完成 |
| 结尾是否回应旅程 | 有帮助／无帮助存档各完成19→20；观察认出什么 | 两版本完整且无虚假回响；不强求玩家复述主题 |
| 保存是否可靠 | 在冲刺、预警、天气转换、棚展开、关间各退出继续；失败回点对照 | 状态一致与可继续；不等于总体无缺陷 |
| 篇幅是否有效 | 自然首次流程分开记录行动、探索、重试、对白、等待 | 支撑当前范围判断；机器人秒数不能作商品时长 |

技术验证按风险选择，沿用[LV01–10](swarm-flight-game-20261020.md#level-flow-checklist)及已有普通输入回归。纯文案／删装饰线不写模拟实现的单元测试；新规则、存档和动态几何必须有针对检查。自动测试、开发者自玩、Alan反馈、独立玩家证据分别归档。

**v1.1专项验收：**

- 无季节／节气文字时，玩家仍能从雨露、植物和生物活动感到环境变化；玩家不必猜对历法名称。
- 花蜡窗的颜色／透光变化可辨，场景主色独立；界面、台词、选关和普通日志无节气标签。
- 生物与Boss各有独占准备／动作／恢复，玩家能说出行为特点；不会都退化成同款追逐或三次处理。
- 风花曲线／分瓣在错误入口、已用重入、回折、低体力及读档时仍可信，主动决策没有被自动牵引吞没。
- 蜂舞有观测才报告，听者出发到真实花源；提前离开、重复、过期、恢复都不产生假信息或额外奖励。
- 05／10／15／19替换高潮后测完整前后节奏，20继续低压；07／08原节奏作为对照不被新内容破坏。

### 13.2 真人试玩安排的最小方案【选定实现后执行】

先给实际可玩的代表片段，不讲设计意图或正确答案。观察玩家何时停、为何换路、哪里重复试同一错误、是否主动用已学动作；结束只问具体经历，例如“这里为什么选这条”“刚才花和鸟发生了什么”“哪段想快点结束”。记录版本、入口、设备、是否见过游戏与观察材料。

第一轮可以是少量陌生玩家的定性观察，人数和招募方式随可用资源明确，不把小样本意见写成比例结论。Alan对总体方向与风格的判断独立保留。无授权不联络或招募他人；本轮没有新试玩。

### 13.3 成品完成条件

- **内容完整：** 确定的主线关卡全部可玩，前后连接明确，季节有不同主要判断；高峰和结尾属于本体。
- **规则可信：** 方向、预告、碰撞、资源、遮蔽和恢复一致；没有已知软锁或必要补给与行动分离的问题。
- **表现完整：** 关键物件与角色状态可读，画风统一；音效与音乐不抢危险信息，剧情事实与场景一致。
- **产品完整：** 标题、继续、暂停、设置、输入设备、章节重玩、退出恢复、制作名单与存档异常处理都能实际使用。
- **体验有证据：** 代表关与全篇自然流程经过真实观察，已处理主要重复／读图／节奏问题；没有把CI当作产品验收。
- **交付完整：** 目标平台真实安装运行、资源随包、来源与署名可追溯、版本和存档策略明确；商店材料只描述实际可交付内容。

这不是对当前0.14.1的达标声明。现有商业要求与交付合同仍负责发行验收；文档评审通过只证明可以进入选定设计的验证。

### 13.4 主要风险与处理

| 风险 | 预警信号 | 处理／负责人 |
| --- | --- | --- |
| 完整体量与已认可节奏不相容 | 只有复制或空路才能达到分钟数 | Codex给实际内容与时长证据，Alan在范围复核点决定篇幅／资源，先保住动作质量 |
| 20关主要判断仍同质 | 去掉标题后仍只是“冲过下一排” | Codex先改落点、时机和后果，删掉无作用重复，不先加机关 |
