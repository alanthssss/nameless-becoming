## 一、目标与边界

目标不是继续美化原型，而是建立一套可以支撑 Steam 商店、预告片和公开 Demo 的实际游戏美术：玩家不读说明也能识别自己、目标、危险、路线与反馈；截图本身像一个完整世界；资产能够拆层动画并在 Godot 中稳定运行。

本轮明确不做：

- 不沿用被否决的贴纸式 SVG、毛毡玩偶或儿童布书质感；
- 不做剪纸、丧葬、祭祀或黑红民俗恐怖语汇；
- 不把概念图直接当游戏截图或最终资产；
- 不在春季代表切片通过审阅前批量制作四季、四 Boss 和 Steam 胶囊；
- 不用像素滤镜把现有高分辨率资产伪装成像素风。

## 二、方向实验记录

### v1：通用手绘花田（未通过）

- 场景是有前景、中景、路径和生态聚落的真实花田，不再是纯色面板；
- 角色和交互物保持简化、夸张、可动画，但不幼态卖萌；
- 自然纹理只服务空间与季节，不能淹没 40～60 px 的玩法主体；
- 花粉链、蜜滴、风向和危险预告使用世界内光点、叶片运动和轨迹，不依赖说明文字；
- HUD 退居边缘，只保留携蜜、体力、蜂巢储备和当前阶段，不与场景争夺注意力。

![春季正式游戏视觉目标 v1](concepts/spring-commercial-gameplay-target-v1.png)

该图使用现有春季实机截图作为空间结构参考，由内置图像生成工具生成。Alan 审阅结论：**太普通、没有特点，而且没有采用此前讨论形成的项目身份。**

失败原因不是此前讨论失效，而是提示中过度纠偏：为了排除剪纸、贴纸和幼态感，同时排除了蜂蜡、植鞣革、刺绣与微缩文明等既有辨识语言，只留下“成熟手绘自然花田”，因此得到一张通用的商业插画。该图只保留为失败对照，不进入灰盒或资产生产。

### v2：随四时呼吸的蜂族城邦（已进入实现，独立审美门禁仍待记录）

![春季蜂族城邦视觉目标 v2](concepts/spring-commercial-gameplay-target-v2.png)

v2 恢复并强化此前已经形成的五项核心身份：

1. **高度文明化的蜂族社会**：蜂巢不是道具，而是能看到共同劳动、育幼、储存与交通的微缩城邦；
2. **撤离即回家**：安全区是明亮、有人等待的社会空间，花田越远离蜂巢越不确定；
3. **无名→成蜂**：玩家的行动通过授粉链、共同资源和归巢路线连接花、蜂群与其他个体；
4. **材料有语义**：蜂蜡只承载生命与能量，植鞣革/蜂巢浮雕承载蜂群秩序，刺绣式轨迹承载运动与联系，自然纤维只作为环境层；
5. **节气内化**：春/木/角通过向上分枝、萌芽、展开、上行路径和开放节奏体现，不出现季节标题或文化装饰标签。

该张 v2 图仍是生成式方向实验，不是实机截图或最终资产。它影响了后续实机切片，但 Alan 对当时候选的“可以”只批准整体整改方向，不能倒推为这张概念图、`57aefc4` 实机美术或全部美术已逐项通过。信息密度、蜂巢占幅和角色缩小后的辨识度仍要用实机动态证据验证。

### 2026-08-26 旧概念参考重编提案（继承边界保留，表现路线由 v4 继续）

**证据边界：** Alan 提供了六组包含可能已废弃设定、且部分构成过于复杂的旧概念图，要求只取其美术方法，统一画风与感觉，并先讨论方案；以下是基于该直接输入形成的开发侧美术提案，不代表旧设定恢复、正式资产已经修改或方向已经通过。

本节的“只继承方法／不复活字面设定”仍是现行输入边界；当时暂称的“有情的生态寓言”负责回答**角色化内容从哪里来**。v3 曾用三路同构图回答**用什么统一表现系统画出来**，但其推荐已因配色、线噪和构图被 Alan 否决。后文 v4 改用明亮生态动画与蜂巢地标继续承载角色化内容，两者不是互斥画风。

本轮不把旧图当作角色名单，而像重编音乐一样拆出可复用声部。唯一工作方向暂称 **“有情的生态寓言”**：

> 真实物种骨架 + 行为夸张 + 共同生活痕迹 + 节律光色；扣除写实微细节、人类职业装扮、文字标签和旧怪物技能。

| 旧参考 | 只继承的设计方法 | 明确不带回的字面设定 |
| --- | --- | --- |
| 僵尸装束野猪 | 大块轮廓、重量感、正侧背与多状态一致性 | 僵尸、符纸、官服、朝珠、顶戴和复活世界观 |
| 油葫芦容器怪 | 身体结构直接说明功能；准备／动作／结果三拍。翻译到现有油葫芦时只表现后腿压缩、起跳与落地停顿 | 油罐怪、储油／液体语义、“油”字、吐油、自燃、水火克制和旧技能树 |
| 地主蚊子 | 口器作为行动轴；吸取前后腹部重量与飞行姿态变化 | 地主讽刺、西装、皮草、烟斗、钱袋、收租或剥削系统 |
| 三弦鸟精 | 声音成为空间轨迹；阶段变化同时改姿态、轮廓和节拍 | 乐器武器、长袍、符咒、鬼火、骷髅、摄魂与阴间紫氛围 |
| 蚁城与蚁后 | 交通、储存、修补、照料、休息等生活痕迹让场景有温度 | 蚂蚁帝国、阶级阵营、暴君蚁后、监狱、贡品和经营系统 |
| 二十四节气色卡 | 季节是连续的明度、饱和度、光影与运动密度变化 | HUD 阴阳图、节气名称、RGB 说明、24 套场景和四季硬换色 |

旧参考进入当前游戏时必须经过玩法翻译：主角以触角方向、翅拍、负重和急转压缩表现性格；蜂巢以修补、育幼暖光、交蜜、守卫换班和交通表现共同体；给粉花向外递出、承粉花向内承接；蚊子的贪婪由口器过长、腹部胀重和吸取后下坠表达。任何新细节若不能同时改善角色、交互或路线中的至少一项，就不进入代表样板。

#### 后续角色化力度 A/B，不做两套世界

这项 A/B 只在 Alan 先通过 v4 表现系统／构图后执行，不与历史 A／B／C 画风候选重复。两版固定同一个春季传粉视口、镜头、布局、光线、对象数量、游戏状态和动作时间线；不新增怪物、玩法、服装或装饰，只比较同一明亮块面／蜂巢地标语法下的角色化力度。功能色、外轮廓、季节光色、蜂蜡反馈和接地阴影在两版保持相同，不作为 A/B 变量：

| 版本 | 视觉权重 | 要验证的风险 |
| --- | --- | --- |
| A · 生态克制 | 物种识别约七成，轮廓／姿态夸张约三成 | 是否仍过于接近“写实素材转手绘”、缺少记忆点 |
| B · 寓言强化 | 物种识别约五成，轮廓／姿态夸张约五成 | 是否越过成熟克制边界，变成幼态或廉价拟人 |

门禁 A 通过后，只用同一组临时分层资产交付两张同帧 1280×720 场景图、两段同时间线 8–12 秒运动小样，以及一张主角／蜂巢／花／蚊子的黑白轮廓表。先回答“哪版更像游戏而非插画、哪版更属于同一个世界、哪一处太拟人或太繁杂”，再决定中间权重；未通过前不整体替换现有美术，不把概念图裁切为正式资产。

明确禁用：完整人类服饰、人脸和直立人体；僵尸／亡灵／丧葬／摄魂视觉；地主、蚁后、阶级阵营与蚁城经营；油弹、自燃等旧技能；节气文字与阴阳图回到 HUD；统一像素化；用黑红代表全部危险；将六张图直接拼贴或顺手扩充怪物名单。

### v3：正式画风重开（2026-08-26，推荐已否决）

本轮先从最新 `main` 生成真实 1280×720 春季快照，再只改变画风、不改变花田／HUD 的基本空间关系。这样可以单独比较造型语言，而不是让三张构图、信息量和完成度都不同的概念图互相竞争；同时也意味着这一轮**没有回答 HUD 是否应该继续集中在顶部与右侧**。

![2026-08-26 春季实机审阅基线](screenshots/spring-art-direction-baseline-2026-08-26.png)

这张图属于**实现事实与开发者快照**：能证明当前背景、蜂巢、玩家、花、授粉状态和 HUD 已在真实场景同屏；不能证明画风已通过。视觉审计得到四个根因：

1. 背景、花、角色和蜂巢像不同写实素材分别转成手绘，再由深色图形 UI 包住，缺少统一的抽象规则；
2. 场景中心、边缘植被、花器官和蜂巢都在争夺细节预算，远近与交互层级主要靠尺寸硬撑；
3. 蜂巢有建筑，没有足够的共同劳动痕迹；玩家蜂与敌害有物种外形，却没有由行为动词塑造的姿态；
4. “布艺／毛毡／皮革”被当成表面材质目标，反而遮住了最先必须确定的投影、轮廓、明暗和动画语法。

#### 三路同构图候选

**A · 蜂蜡蚀刻浅浮雕**

![候选 A：蜂蜡蚀刻浅浮雕](concepts/spring-style-candidate-a-wax-etching-v1.png)

- 优点：材质身份强，蜂巢与 HUD 很统一，商店缩略图有辨识度；
- 风险：全屏同质金绿会疲劳，容易像金属桌游面板；浅浮雕纹理的批量生产与动画成本偏高。

**B · 矿物色套色版绘**

![候选 B：矿物色套色版绘](concepts/spring-style-candidate-b-mineral-print-v1.png)

- 优点：严格俯视、轮廓清楚、留白稳定；角色、花、地形和 UI 可以共用有限色、套色边与两档明暗，最适合单人分层生产；
- 风险：若没有局部体积和蜂群活动，可能退化为静态生态图谱或复古桌游插图。

**C · 蜂蜡微缩舞台**

![候选 C：蜂蜡微缩舞台](concepts/spring-style-candidate-c-wax-miniature-v1.png)

- 优点：空间、触感和暖意最直接，蜂巢像一个可进入的地方；
- 风险：即使主动降细节，仍容易像高级桌游／手游棋盘；角色转向、状态帧、四季模块和光影统一的成本最高。

#### 原始反馈复核：三张候选未覆盖界面构图

`playtest-NB-20260825-6412D7BA.json` 的逐字反馈包含：“提示什么的放在最右侧、上侧是不是不是一个很好的设计，是否可以简约设计到画面中”。它来自 Alan 对历史 `Main` 的局部自测，不是独立玩家证据，也不是允许自动删除全部文字或结算条件的实现指令；但它确实是本轮美术讨论的直接输入。

现有 A／B／C 与推荐图故意保留“顶部紧凑 HUD＋右侧窄情境栏”，目的是隔离画风变量。该控制方法对比较造型系统有效，却不能被倒推为旧界面构图已经获批。此前方案把“整体美术未达宣传／发售水准”纳入门禁，却没有让这条更具体的构图建议改变下一步交付，属于遗漏。修正后的门禁拆为两部分：

1. **A1 · 表现系统**：比较 A／B／C；当时专家启发式推荐“矿物色套色版绘 × 局部蜂蜡浅浮雕”，现已被 Alan 直接审阅否决；
2. **A2 · 信息构图**：在同一推荐表现系统、同一世界状态下，比较现有界面壳与“世界内主表达＋最小可查询界面”的版本。A2 通过前，不制作 Godot 正式美术样板。

该轮曾提出八条规则，其中严格俯视、世界先说、行为塑形和真实尺寸验证仍可继承；深靛／橄榄有限色、套色颗粒与固定单屏构图不再继承：

1. **投影先于材质**：可连续旋转的角色必须使用严格俯视轮廓；真正三分之四视角只允许用于不旋转建筑，或改做 4／8 向角色帧后重新立项；
2. **一套边缘**：环境、角色、花、敌害和 UI 共用靛青／深绿套色轮廓、有限色和两档明暗，不再拼贴不同渲染完成度；
3. **蜂蜡是动词**：只给入口、蜜、花粉、体力、卸蜜和调律结果增加半透明体积；常态地表不铺蜂蜡；
4. **人情味来自动作与生活痕迹**：巢口搬运、点亮的储蜜格、磨损的落脚路、玩家略弯触角和工作姿态；禁止帽子、人脸或人类身体；
5. **敌害由行为动词造型**：蚊＝前刺／追踪，蚁＝低重心／路径，油葫芦＝折腿／爆发，画眉＝停驻／诱骗，熊＝宽面／碾压；Boss 在常态轮廓上失衡，不另做恶魔皮；
6. **细节预算 1∶2∶4**：场地中心最低、边缘生态中等、交互物与角色最高；纹理只在边界和状态变化处出现；
7. **概念图必须缩回实机**：推荐图把玩家蜂放大得超过目标尺寸，只表达角色化倾向；正式切片仍从约 58×42 px 起测，最终靠动态与轮廓通过，不靠概念图放大。
8. **世界先说，界面再查**：携带状态优先落在蜂身，去向优先由同形目标与寻迹连接，蜂巢储备／受损优先落在蜂巢，成功或拒绝优先在交互发生处完成三拍反馈；顶部／右侧不得继续用大块常驻文字承担这些主表达。暂停、无障碍文字和所有会阻止结算的条件仍必须从开局可查询，世界内化不得重新制造隐藏门槛。

#### v3 门禁结论

v3 的 A1 表现系统与 A2 固定单屏构图均未通过。现有图片仍可作为失败归因和制作成本记录，但不得继续进入 Godot 动态样板。

### v4：明亮生态动画 × 蜂巢地标（2026-08-26，待审阅）

![v4 明亮大地图与蜂巢节点方向稿](concepts/spring-bright-hive-checkpoint-direction-v1.png)

该图是基于 Alan 最新三条直接反馈重新生成的**方向实验**，不是实机截图、正式资产或玩法实现。它把 `1280×720` 解释为更大滚动地图中的一个局部视口：路线延伸出屏幕，蜂巢从左侧固定建筑变为暖亮的安全／节奏节点，并承担类似篝火的作用；界面缩为两个角落入口，世界承担主要状态表达。图中蜂巢服务、地图尺寸、节点数量和时长都不是已定数值，玩法边界见 [`map-evolution.md`](map-evolution.md)。

#### 从 PVZ 借方法，不借作品外形

- 借统一而明亮的场地大色面、交互物高局部对比、功能先于装饰的轮廓、少文字和避免噪声；
- 借“角色造型直接说明动作”：蚊的口器先读成前刺／追踪，花的器官先读成给予／承接，蜂巢的亮灭先读成安全／储备；
- 不借草坪格子、平行路线、左屋右敌、卡槽、阳光、铲子、植物／僵尸比例和五官、UI、字体或音乐；
- PVZ 参考边界以 [`../decisions/ADR-001-pvz-reference-boundary.md`](../decisions/ADR-001-pvz-reference-boundary.md) 为准。

#### v4 九条规则

1. **高明度大色面**：春季地表以清亮黄绿、叶绿和暖白路径为基底；暗色只做轮廓、阴影与危险锚点，不允许深靛面板或橄榄旧化占据大面积；
2. **颜色承担功能**：蜂巢用蜜金／琥珀，玩家用蜂黄／淡青翼，普通目标用白／珊瑚，危险用珊瑚红／深紫；季节色不能把这些功能色吞没；
3. **只留必要线**：一个单位先有清楚外轮廓，再保留最多几组解释功能的内部结构；不使用满屏蚀刻、排线、点描、颗粒边和装饰性轨迹；
4. **单帧只有一个视觉主句**：每个局部视口优先组织“巢／退路—玩家—当前目标或威胁”的三角关系，其他对象成组退后；缩到 320×180 或转灰度仍先读到这三者；
5. **视口不是地图**：路径、生态区和危险继续延伸到屏外；地图扩大不靠缩小玩家或塞满对象，中央与路线交汇处保持低噪；
6. **蜂巢承担类似篝火的作用**：暖金核心、蜂群活动、储蜜格和地面色温共同说明安全／休整／方向，不画抽象安全圈；不从“篝火”类比自动新增存档、复活、传送或刷怪；
7. **世界先说，界面再查**：携带在蜂身、目标在同形实体／寻迹、储备在巢房、结果在交互处；常驻 UI 目标占屏不超过约 8%，完整结算条件仍可从角落入口查询；
8. **严格俯视与真实尺寸**：连续旋转单位继续使用严格俯视轮廓，玩家从约 58×42 px 起测；构图稿不得用巨型角色或三分之四资产掩盖缩小问题；
9. **干净不等于塑料**：保留轻微哑光笔触与一致软阴影，但不做手游高光塑料、糖果材质、桌游棋盘或通用奇幻花园。

#### v4 门禁 A

- **A1 色彩／线条**：是否已经达到干净、明亮、色差清楚、线条有主次；
- **A2 信息／构图**：是否接受“滚动地图局部视口＋蜂巢节点＋最小查询 UI”的结构；
- **A3 项目身份**：是否仍能读出蜂群共同体、归巢、授粉与非杀戮调律，而不是只得到一张通用明亮卡通地图。

只有 Alan 明确通过这三项，才制作真实地图灰盒和 1 个玩家蜂、1 只蚊、两类花、蜂巢节点的动态样板。长地图代码、节点服务、四季扩产和 Steam 素材仍由各自门禁决定。

### 蜂巢与蜂群分工决策

- 统一锚点：卸蜜、回血和冬季取暖共同使用巢门矩形 `Rect2(34, 350, 176, 120)`，归巢落点为 `(150, 410)`；左侧其他高度不再是隐藏的蜂巢竖条；
- 蜂巢活动：储备提高会点亮更多巢房，交蜜会短暂增强入口活动，受损会改变蜂巢色调；
- 蜂群角色：先以三种色调和巢口活动表现侦察蜂、采蜜蜂、守卫蜂三类同种工蜂，而不是新增可玩物种；寻迹时侦察蜂离巢，真实卸蜜时采蜜蜂穿过落巢通道，袭扰发生时守卫蜂停在巢口。这是世界反馈动画，不冒充具备独立寻路和战斗决策的完整 AI；
- 决策依据：现阶段“不同物种”若没有独立操作、资源取舍和成长路线，只会增加名词与资产量。先验证玩家能否从蜂群活动读出一个活的社会；若三类角色仍同质，再为有独立玩法价值的蜂种立项。
