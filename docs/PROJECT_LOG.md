# 《无名：成蜂 Nameless: Becoming》项目记录

> IP 正式名《无名：成蜂 · Nameless: Becoming》已定案并于 2026-08-18 正式落地（结束第九节休眠，见[第十二节](#十二哲学核查修正与正式改名落地2026-08-18)）；本文档中旧名「归巢之前」仅出现在历史记录中。

本文档记录项目的稳定共识、关键取舍和每次原型要验证的问题。聊天中的想法只有写入这里，才算进入项目。

## 一、项目愿景

以蜜蜂文明为载体，制作一款具有东方生态寓言气质的游戏。玩家不是被台词告知答案，而是在采集、劳动、归巢、季节变化和生命循环中自行感受世界。

设计原则：

- 体验大于解释；
- 大 Boss 保持民间寓言感，小怪与环境负责生态叙事；
- Boss 是偏离自然循环的“失律者”，并非绝对恶人；
- 四季既是自然变化，也是文明与精神状态；
- 所有扩展内容必须建立在可玩的核心互动上。

## 二、世界观共识

### 主角

人在梦中变成一只蜜蜂，最初并不知道自己属于工蜂、雄蜂、蜂王或其他身份。主角的意义通过行动与循环显现，而不是通过大量独白解释。

### 失律者

目前保留的民间寓言型 Boss 原型：

| 原型 | 主题方向 | 季节/状态 |
| --- | --- | --- |
| 蚊 | 贪婪、持续索取 | 春末至盛夏 |
| 油葫芦 | 油滑、漂泊、不愿归巢 | 夏末 |
| 熊 | 停滞、疲惫、不愿苏醒 | 冬 |
| 画眉 | 诱惑、沉溺、不愿告别 | 秋 |

蜂螨、假花、腐蜜、空巢和漂蜂更适合作为小怪、区域生态、图鉴或支线，而非替换核心 Boss。

### 架空节令

曾讨论的世界状态包括：初蜜、盛鸣、长渴、静巢、逆潮、空花、无昼、灰雨。未来可以作为普通二十四节气之外的异常关卡或终局章节。

## 三、玩法定位

当前定位：

> 蜂巢经营 + 轻 RPG 探索 + 四季循环 + 轻搜打撤肉鸽。

最小核心互动：

```text
飞行探索
→ 靠近花朵并持续采蜜
→ 体力下降、危险聚集
→ 冲刺、蜂针或绕行
→ 亲自飞回蜂巢完成撤离
```

关键情绪不是“击败所有敌人”，而是“已经收获很多，但远处还有一朵更好的花”。

## 四、节气与阴阳

完整产品计划以二十四节气组织小关卡，每季六关。每个节气改变同一套核心操作的条件，而不是制作二十四种无关小游戏。

MVP 压缩为四个代表节点：

| 节令 | 阴阳 | 玩法职责 |
| --- | --- | --- |
| 春分 | 阴阳相半 | 学习飞行、采蜜和归巢 |
| 夏至 | 阳极阴生 | 花蜜充足，蚊群压力最高 |
| 秋分 | 阴阳相半 | 花期衰退，路线与撤退更重要 |
| 冬至 | 阴极阳生 | 资源稀少，以守成为先 |

配色不是四套孤立主题色，而是一条连续曲线：春季青绿与米黄，夏季高明度金橙，秋季赭石，冬季蓝灰；蜂蜜金贯穿全年，阴影逐季加深，再从冬至孕育下一轮暖色。

## 五、版本记录

### 0.1 · 规则原型

目标：确认四季、采集、携带、归巢、储蜜和过冬能否构成宏观闭环。

实现：按钮式选择花朵和远近区域，以数值模拟搜打撤。

结论：宏观规则可以成立，但缺乏空间感、动作感和“扮演蜜蜂”的感觉，因此不继续堆叠剧情和 Boss，转向直接交互。

### 0.2 · 核心交互原型

目标：验证玩家是否会在采蜜时产生“继续贪还是立即撤”的真实犹豫。

实现：

- 直接控制蜜蜂飞行；
- 持续采蜜而非点击领取；
- 体力与冲刺；
- 蚊虫追击、碰撞惩罚；
- 消耗体力的蜂针；
- 必须亲自飞回蜂巢才能结算；
- 四个压缩节令及完整二十四节气路线骨架；
- 键盘、鼠标与触摸操作。

当前需要真实试玩，而不是继续凭策划判断。

### 0.3 · Godot 单机垂直切片

技术路线正式确定为 Godot 4 单机游戏。网页原型作为历史验证和快速分享版本保留，但不再承担正式产品架构。

首个 Godot 切片已经具备：

- 原生桌面输入与直接飞行控制；
- 持续采蜜、体力、振翅冲刺；
- 蚊虫追踪、碰撞惩罚、蜂针击退和冷却；
- 携带资源必须返回蜂巢才能结算；
- 春分、夏至、秋分、冬至四个外部数据驱动关卡；
- 阴阳比例、节令配色和四季压力差异；
- 失败、节令推进与完整循环；
- 无外部素材的程序化占位美术；
- Godot 主场景启动验证和节令数据自动检查。

当前工程目标仍是手感验证，并非内容生产。美术、音频、完整地图和蜂巢经营将在核心互动通过试玩后进入。

### 0.4 · 飞行手感与玩家控制拆分

- 将玩家控制从主游戏脚本拆分为独立 `BeePlayer`；
- 飞行由即时位移改为加速、惯性与制动模型；
- 振翅使用独立高速与额外体力消耗；
- 新增 E 键“感知”，短暂显示花蜜、敌意和归巢方向；
- 玩家体力消费提供统一接口，为后续成长系统预留修改点；
- 自动检查加入玩家重置、体力消费与不足拒绝测试。

0.4 的技术目标是让后续成长、敌人和设置不再继续挤入单体控制逻辑。

### 0.5 · 生态压力与失律者

- 新增掠蜜蚁：追逐携蜜玩家，夺取一滴蜜后逃跑；
- 四节令使用不同的蚊虫与掠蜜蚁组合形成压力差异；
- 新增“失律之蚊”，不采用清空血条的传统 Boss 规则；
- 玩家需把失律者引到三处共鸣花粉附近，再用蜂针完成调律；
- 感知能力现在同时标示花朵、两类普通敌人与失律者。

### 0.6 · 蜂巢分工成长

- 每完成一个节令，进入一次蜂巢三选一；
- 长翼蜂强化速度并降低振翅耗能；
- 采蜜蜂缩短采蜜时间并增加单朵花储量；
- 守卫蜂扩大蜂针范围并缩短蜂针冷却；
- 成长允许同类叠加两次，使四季路线出现轻量构筑差异；
- 成长内容由外部 JSON 驱动，便于扩充和平衡。

### 0.8 · 单机产品外壳（第一轮）

- 标题界面展示历史最远节令与完整轮回次数；
- Esc 与界面按钮均可暂停/继续，暂停时冻结玩家控制；
- 新增窗口/全屏切换并自动保存偏好；
- 新增本地 ConfigFile 存档，记录出巢次数、最佳节令与完成次数；
- 存档不记录局中状态，保持“退出即结束本轮”的搜打撤约束。

### 0.9 · 候选 MVP（进行中）

- 采蜜、归巢、蜂针、受击、成长、调律和结算均接入程序化占位音效；
- 声音开关与窗口模式一样写入本地存档；
- 核心玩家、蚊虫、掠蜜蚁与 Boss 数值集中到外部 `balance.json`；
- 新增候选版本发布清单和五人外部试玩记录表；
- 只有桌面构建、人工全流程和外部试玩全部通过后，才升级为 1.0 MVP。
- 已使用 Godot 4.6.2 官方模板生成 macOS universal 与 Windows x86_64 调试包；macOS 包完成原生启动验证，构建哈希记录于 `BUILD_MANIFEST.md`。
- 新增无存档副作用的全流程状态测试，并在结算与标题记录主动游玩时长，为 15～25 分钟目标提供真实试玩数据。
- 补齐鼠标采蜜、振翅、蜂针与感知控件，使鼠标路线不再依赖战斗键盘操作。
- 建立私有 GitHub `v0.9.0` 预发布版本并上传两个平台构建，供外部试玩者直接下载。

### 0.9.1 · 世界规则修订

首轮创作者试玩指出四项占位机制破坏了世界可信度，因此不按“小幅调数值”处理：

- 移除单屏场景中没有信息价值的感知技能，留待遮蔽、气味轨迹与复杂路线阶段重新设计；
- 蜂针退出普通攻击循环，现有防身动作改为震翼驱离；蜂针未来只可能作为不可逆抉择；
- 蚊虫、掠蜜蚁与失律者均不能越过蜂巢安全边界；
- 归巢后无论是否携蜜都会通过休息和蜂群照料逐步恢复体力，交蜜只负责公共储备结算。

### 0.9.2 · 技能与状态可读性

- 根据继续试玩反馈恢复辅助技能，但重做为“触角寻迹”：显示蜜量、警戒区、归巢线和推荐花，而非重复高亮可见物；
- “震翼驱离”更名为“震翼惊退”，敌人会在状态期间实际向外移动，词义与结果一致；
- 惊退中的蚊虫和掠蜜蚁显示剩余状态条，不再用变灰与静止假装被赶走；
- 飞行体力改为进度条与数字并列，震翼按钮直接标注 8 点消耗；
- 使用震翼和受到攻击时，体力区域显示短暂的负数跳字。

### 0.9.3 · 资源守恒、技能键区与节令音乐

- 修复初始花量充足但多次失败、洒蜜和偷蜜后总量永久不足的软锁；
- 体力耗尽仍会失去本次携蜜并损失蜂巢呼吸，但洒落蜜会生成明显标记的返蜜花；
- 掠蜜蚁现在真实携带偷走的蜜，震翼惊退后才会掉落并回到花田；
- 技能主键集中为 U 寻迹、I 采蜜、O 振翅、J 惊退，原有 E、空格和 Shift 保留兼容；

### 0.9.4 · 输入、构图与音乐返工

- 体力条改为固定 6 像素自绘条，消除 Godot 主题最小高度导致的越界；
- 花朵使用拒绝采样，生成中心距至少 82 像素；
- WASD 使用独立动作映射，并在运行时补全物理键映射；自动测试验证物理 D 键与移动行为；
- 六键区补全：K 为消耗 12 体力的短暂无伤急转，L 为消耗 1 滴携蜜的蚊虫诱饵；诱饵结束后花蜜回归花田；
- BGM 从持续三和弦重写为四季各自的 16 步旋律、低音运动与轻打击脉冲。
- 发行端收敛为同一 Godot 工程的 Web、macOS universal、Windows x86_64 三种导出；旧网页游戏逻辑停止维护；
- macOS 包在导出后重新临时签名，并由首次启动脚本处理浏览器下载隔离；正式公开发行仍需要 Apple Developer ID 签名与公证。
- WebAssembly 超过 Sites 单文件限制，因此发布阶段拆为两个传输分片，浏览器加载时重新组装；这只改变传输方式，不产生第四套游戏代码。
- 新增随春分、夏至、秋分、冬至变化的低音量程序化五声音阶环境音乐。

## 六、下一阶段候选

完整 MVP 范围已于 Godot 0.3 后冻结，详细规则与验收标准见 [`MVP_SPEC.md`](MVP_SPEC.md)。后续实施以 0.4～1.0 七个里程碑推进，不在 MVP 中扩展二十四个完整关卡或四个完整 Boss。

只有在 0.2 的核心互动通过试玩后，才进入下列工作：

1. 调整飞行惯性、采蜜时间、敌人速度和撤离距离；
2. 增加一种与蚊虫行为明显不同的小怪；
3. 将一个节令扩展为包含路线选择的小地图；
4. 增加蜂巢中的一次资源分配决策；
5. 制作第一个失律者遭遇；
6. 再决定是否从四节令扩展到二十四关。

暂不制作：完整剧情、大量对白、装备系统、复杂技能树、开放世界、账号、联网与商业化功能。

## 九、命名定案（2026-08-18）

- **IP 正式名**：`无名：成蜂 · Nameless: Becoming`；系列格式 `Nameless: <主题>`／`无名：<主题>`（参考黑神话：悟空——系列品牌 + 单作主题）。
- **系列主标题「无名 Nameless」**：取自主角"不知道自己属于哪一种蜂"，呼应老子"无名，天地之始"；为替代"归巢之前"的二元论结构（家/非家、之前/之后）而设立。
- **第一作副标题「成蜂」**：双重双关——变态发育终态（成虫期）+ "成为一只蜂"；指向"结算揭示身份"机制。
- **吻合度评估**：世界观 ≈95%、核心玩法 ≈90%、身份机制 ≈50%（三选一为雏形、缺"揭示"一步）、文本层 0%（旧名散落 22 个文件）。
- **休眠决策**：当前 MVP（0.9.4）仅含采蜜/归巢/少量战斗，承载不了身份冲突；名字定案但**不落地到代码与试玩版本**，继续以工作名《归巢之前》运行，避免玩家对尚不存在的身份系统产生落差。
- **兑现路径**：把节令间三选一升级为"结算揭示身份"（按整局行为占比结算身份标签，零新增操作），即"成蜂"的最小兑现，也是新名"配得上"的时机（对应第八节 P1 的身份揭示项）。
- **未来系列候选**：`Nameless: Overwinter`（越冬）、`Nameless: Swarm`（分蜂）、`Nameless: Bloom`（花开）。

## 十、生态核查与身份机制修正（2026-08-18）

对"结算揭示身份"方案做生态真实性核查（依据：年龄多态性 temporal polyethism 与行为可塑性 behavioral plasticity 文献——Robinson 1989、Huang & Robinson 1992；2023《Science》Dong et al. 摇摆舞社会学习），结论：**方向符合生态，但初版有三处偏差**，已修正为三维机制。

- **✅ 符合**：真实工蜂任务由"实际行为 + 蜂群需求"决定，而非先天地选择（行为可塑性）；工蜂是全能选手，无终生职业 → "揭示而非选择"比"菜单选职业"更真实。
- **❌ 修正 1（侦察映射）**：初版"回避战斗→侦查蜂"是生态学错误。侦察蜂是采集蜂中最资深、最年长的精英（外勤 <10%），是"采集的毕业进阶"。修正：侦察 = 采集资历达阈值后解锁；探索成功 → 回巢跳摇摆舞分享花源信息。
- **❌ 修正 2（时序）**：真实分工有严格顺序——安全任务在前（巢内），危险任务在后（巢外）；蜂群把风险分配给生命末期个体（"老兵冒险、新蜂守巢"）。修正：身份揭示增加"生命阶段"轴，幼龄做不了危险任务。
- **❌ 修正 3（集体）**：身份不是个体自发，而是蜂群需求与个体行为互相塑造。修正：增加"蜂群需求"调节轴（缺蜜征召、缺卫回防、危机返老还童）。
- **修正后机制**：身份 = 生命阶段（节令模拟日龄）× 任务角色（行为占比）× 蜂群需求（调节），结算揭示"本季主任务"而非"天生职业"。

## 十一、四季差异化玩法设计（2026-08-18）

## 十二、哲学核查修正与正式改名落地（2026-08-18）

**四机制落地要点（参数均可在 balance.json 调）**：

- **秋分 · 储备**（`reserve_mechanic.gd`）：季末结算出现**分配面板**（5 档滑杆），把本季采蜜在「储备冬蜜（公共储备）」vs「哺育幼虫（来年劳动力）」间分配（蜂群未来的两种投资，无私有财产语义）；幼虫加成 = 幼虫投入 ÷ 10 × 5 上限，冬至兑现为能量上限。为来年投资。
- **冬至 · 抱团**（`huddle_mechanic.gd`）：体温 100 起，野外 0.5/s 消耗、巢内恢复；带蜜归巢消耗 1 公共储备，体温 +45（储备空则弱抱团 +25）；体温 <15 恢复速度减半（严寒逼近）；**公共储备 ≥5 解锁侦察**（探知冷却 4.0s）+ 摇摆舞视觉；能量上限 = 100 + 幼虫加成。储备是选项空间不是生死线。共御严寒。

**主循环接入点（节点钩子）**：采蜜钩子→授粉触发；抉择钩子（驱退成功）→征召花区结算；结算钩子（季末）→储备分配面板；出巢钩子（冬）→侦察冷却缩短；归巢钩子→抱团恢复与储备消耗。

## 二十二、Web 中文字形覆盖修复（2026-08-20）

- 0.9.5-rc.1 私有 Web 实测出现大量方框字；确认不是 UTF-8 编码错误，而是仓库内 106 KB 的 Noto Sans SC 早期裁剪子集只覆盖旧文案，新四季、Boss 与情境动作文本超出字形集合；
- 桌面系统可用系统 fallback 掩盖缺字，WebAssembly 环境没有可依赖的系统中文字体，因此问题集中暴露在 Web；
- 从 Noto 官方仓库完整 Noto Sans CJK SC Regular 生成覆盖当前项目文案的子集，上游文件以 Git blob SHA `dc15562470b4f842321894787a0d066879ccff8b` 核验，并随子集保留 SIL Open Font License 1.1；完整字体直接提交会让 Web PCK 增加约 14 MB 且触发 Sites 源仓库单 blob 上传失败，因此改用受测试门禁约束的 418 KB 子集；
- smoke 测试新增 CJK 字形覆盖门禁：扫描游戏数据、项目设置与实际界面脚本中的中日韩统一表意文字及全角标点，任何项目字符缺字都会使测试失败；
- 修复后需重新导出 Web、验证 PCK/字体大小与页面显示，再发布新的 Sites version；桌面候选二进制不因本轮 Web 字体修复自动替换，后续 RC 重建时一并吸收。
- 修复经 PR #25 与体积收敛 PR #26 的 GitHub Actions 双门禁通过后合入；最终空导出 PCK 为 514,320 bytes，Sites version 6 已成功私有发布。受当前会话浏览器接口限制，生产页面目视确认保留为明确待办。
