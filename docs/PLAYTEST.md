# 《无名：成蜂》MVP 试玩记录

本文件只记录未参与策划者的真实试玩。开发者自测不能替代外部试玩，也不能预填结果。

## 记录形式（2026-08-21 改版）

原先的九列大表已废弃：它把「观察」（进行中的打勾计时）与「反思」（结束后才答得出的紧张/困惑时刻）混进同一张矩阵，填表负担大、留不下真话。现改为两件轻工具：

- **观察卡**：观察者在试玩进行中随手打勾、记分钟数，30 秒能填完；两个通过门槛行为直接来自这里；
- **口头三问**：结束后固定三问，**记原话**，不追问、不诱导——紧张时刻与困惑点从玩家的原话里来，不从表格空格里来。

**为什么不用问卷**：问卷把记录负担转嫁给玩家、诱导答案，且两个门槛均为行为数据（主动放弃远花、失败后主动重开），靠问是问不出来的——玩家会事后合理化自己的决策。观察者亲眼看勾选，才是门槛要的证据。

## 统一流程

1. 不解释操作，让试玩者从标题画面自行开始；
2. 试玩进行中，观察者只填观察卡（打勾/分钟数），不写长句；
3. 不提示“应该撤退”，观察其是否主动放弃远花；
4. 首局结束后不催促重开，观察是否主动开始第二局；
5. 试玩结束后只问「三问」的三个问题，记原话，不追问、不解释设计意图。

## 结束后三问（口头问，原话记录）

1. 刚才最紧张的一刻是什么时候？
2. 有哪里没看懂，或者觉得别扭的？
3. 用一句话跟朋友介绍这个游戏，你会怎么说？

> 第三问顺带验证一句话定位（蜜蜂生态 × 节气 × 撤离）能否真的从玩家嘴里传出去——传不出去说明定位讲法有问题。

## 通过门槛

- 5 名试玩者均未参与策划；
- 观察卡上至少 3 人勾选「曾主动放弃远花并归巢」；
- 观察卡上至少 3 人勾选「失败后主动开始第二局」；
- 每人观察卡填齐时间与失败原因，三问留有原话记录。

未填满且未达到门槛前，版本只能称为“0.9 候选 MVP”，不能标记为 1.0 MVP。

### 2026-08-18

- **力竭代价两问**：①小关卡体力耗尽“没有任何消耗直接回巢重置”是否不合适；②终局失败页体力条不显示 0。——查明体力耗尽其实有三层代价（蜜囊续命→力竭扣呼吸→三命终局）但**代价不可见**。定案“机制不变、强化反馈”（PR #17）：续命时体力条提亮、扣命圆点闪红、力竭归巢改 45 体力低开局；修复失败页体力条满格 bug。
- **首轮创作者试玩（0.9.1）**：四项占位机制破坏世界可信度——单屏下感知技能无信息价值、蜂针作为普通攻击、敌害可越过蜂巢安全边界、归巢恢复与交蜜耦合。→ 0.9.1 世界规则修订：移除感知、蜂针退场改震翼惊退、敌害禁越安全边界、休息恢复与交蜜解耦。
- **继续试玩（0.9.2）**：技能与状态不可读——被惊退的敌人只是变灰静止“假装被赶走”、震翼消耗不直观、体力只有条没有数。→ 触角寻迹重做、惊退显示剩余状态条、体力条与数字并列、震翼标注 8 点消耗、受击/震翼负数跳字。

### 2026-08-20

- **界面堆砌与教学依赖**：界面把系统级操作、过程动作与说明文字同权堆砌；新手体验依赖一次性按键文字罗列而非逐步行动。→ 首次 UX 收束（PROJECT_LOG 第二十七节）：系统操作收进暂停层、顶栏五卡并三组、行为驱动教学状态机。
- **教学覆盖不足（Godot 本地试玩）**：移动与采蜜教学有效，但**未感受到其他机制教学**——核对实现确认此前只有移动、采蜜、归巢三步，侧栏情境文字不能替代首次体验教学。→ 补三项事件驱动一次性短卡（停稳解释寻迹、敌害逼近解释惊退、体力 35% 解释蜜囊续飞与回巢恢复）。
- **Web 首载长时间无响应**：外层把 iframe HTML 加载误认为 Godot 已启动导致超时误判，约 36 MB WASM 首包加剧等待。→ 改流式解压（gzip ~10 MB）+ 外壳向父页面发送真实启动/失败事件。
