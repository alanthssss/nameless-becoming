### 分析单位与覆盖

每次围绕一个设计问题组织：定位片段 → 保存原始证据 → 分开事实与解释 → 对照本作 → 判断是否值得改 → 定义验证。按早/中/后期、村落/各区域、首次使用/熟练重复/边界情况交叉检查遗漏；同一证据编号可复用。

先利用已有时码定位，再补前后过程；区域、行动、资源用途、限制、输入提示或结果变化时加密观察。重复采集可减少取样，但跳过区间仍是未观察，不能据稀疏索引断言其中没有新系统。分别标记定位到、过程已观察、媒体已保存、分析已形成、需实机验证。原作研究不等于玩家普遍体验，也不等于本作已实施。

### 地图还要回答什么

| 问题 | 需要的证据 | 对本作的用途 |
| --- | --- | --- |
| 空间怎样连接 | 入口/返回点、主通道、侧室、分叉、回路、尽头；连续经过证明连接 | 理清庭院—池岸—紫花地及近道关系 |

| 地形怎样配合动作 | 通道宽窄、视野、目标移动、工具范围和资源位置 | 为自由飞行、采蜜、振翅提供空间；未标尺只记角色/屏幕相对尺度，不猜世界米数 |

| 什么固定或刷新 | 地标、同点采空前后；等待、离场、重入分开 | 检验本作18秒再生/离家重置；原作因果交给Windows控制实验 |

| 领域 | 核心问题 | 优先证据 |

| 反例与异常 | 满店、低氧、满包、材料不足、拥挤NPC/特效、中断是否造成问题 | 保存不顺畅片段；一次问题不代表发生率，原作做法也可判不适合本作 |
