## 连接与设备准备

最短路径是在装有 Shelldiver 的 Windows 上打开最新版 ChatGPT 桌面 App，进入 Codex，安装并启用 Computer Use 插件，启动游戏并允许该应用的访问。Windows 使用前台桌面，游戏须可见；保持会话解锁、联网、设备唤醒，取样期间避免另一人同时操作同一桌面。CLI 可用于文件和命令工作，但本方案的画面与输入验证使用桌面 App 的 Computer Use。[官方 Computer Use](https://learn.chatgpt.com/docs/computer-use) · [Windows 支持](https://learn.chatgpt.com/docs/windows/windows-sandbox)

若要从当前 Mac 或手机接续，需先由 Alan 在 Windows 的 **Settings → Connections → Control this PC → Set up / Add** 完成连接与账户验证；控制端使用同一账户和工作区。Mac 的 **Control other devices** 可用时添加该 Windows 主机；手机按主机显示的二维码配对。功能可用性以实际界面为准。远程任务使用 Windows 主机自己的文件、权限、插件与 Computer Use；仅在同一账号登录并不会自动赋予当前聊天访问另一台桌面的能力。主机未连接或离线时不得报告已在远程玩游戏。[官方 Remote connections](https://learn.chatgpt.com/docs/remote-connections)

## 先保护现有进度

1. 记录当前游戏版本、Steam 构建标识（若可见）、语言、分辨率、输入方式、已有存档槽与 Steam Cloud 当前状态；先观察，不按“新游戏”覆盖旧进度。
2. 退出游戏并确认保存完成；根据该机实际文件、游戏设置或可靠说明定位完整存档及配置，**不猜固定路径**。复制到带日期的独立备份目录，记录原路径、文件大小、修改时间和 SHA-256 清单。保持原件及备份，不删除原档。
3. 优先使用游戏自带独立存档槽；没有独立槽时，先明确备份恢复及云同步的关系，再使用经过验证的隔离副本。无法确认恢复或云端覆盖行为时，仅在现有档做可逆观察，初始成长实验保持待执行。不得擅自关闭云同步、改注册表、修改余额或注入解锁来伪装普通流程。
4. 存档重载实验只在隔离研究档进行。结束先正常退出，核对原档未变；若确需恢复，按备份清单还原并重新核对字节及游戏可读状态，单独记录云同步提示与处理结果。未核验不得写“原档已恢复”。

## 五分钟能力验证

计时从配对、游戏启动和存档保护完成后开始；安装、登录、授权和下载等待单独计时。建议窗口化以方便观察，但先使用当前设置判断可操作性。此探测不是五分钟完成全游戏研究的承诺。

| 时间 | 动作 | 可见通过条件 |
|---|---|---|
| 0:00–1:00 | 读取当前窗口和一张截图，辨认角色、位置、HUD、版本和暂停入口 | 返回真实游戏画面；分辨率足以读关键计数，不能只收到标题或黑屏 |
| 1:00–2:00 | 根据游戏显示的键位，短按一个方向、松开，再反向回到附近 | 能看见位移与松开后的状态；没有持续卡键或控制到错误窗口 |
| 2:00–3:00 | 打开暂停／菜单，再返回；记录暂停前后 HUD | 输入焦点和暂停状态可靠；无法暂停也如实记录，后续采用短操作取样 |
| 3:00–4:00 | 在隔离研究档选择一个低风险目标，尝试一次采集或设施交互 | 可识别输入→目标响应→资源或状态改变，保存前后截图 |
| 4:00–5:00 | 再次短操作并松开，暂停，核对截图时间及可重复性 | 至少两次操作形成可追溯行为链；给出可继续／局部可用／阻塞结论 |

黑屏、输入无效或状态不稳定时，保留错误和截图，做一次有依据的调整；同一办法再次失败便停止重复尝试，及时向 Alan 说明卡在哪、缺什么及需要哪一步设备协助。不能把打开窗口或发送按键算作成功试玩。若仅实时操作不可靠，可由 Alan 操作并提供连续录像，Codex负责观察和测量，证据注明操作者。

## 控制实验表

各行先记录初始存档、区域、升级、货物、金币和氧气，再只改变指定条件。默认先做一组配对观察；存在随机性或反例时重复并报告次数。所有行现均为**待执行**，表中“判断”是要回答的问题，不是原作已知事实。

| 编号 | 问题与操作 | 固定条件／对照 | 必留证据与判断边界 |
|---|---|---|---|
| W01 | 同一区域不采集，记录等待前后目标位置、数量；另做暂停等待 | 同档、同区、同路线；实际等待与暂停等待分列 | 带时间的数量／位置截图；区分游动、离屏和新增，不能凭回到镜头就称刷新 |
| W02 | 采空一个可辨认的小范围，留在区内观察；必要时绕开再返回 | 不回村、不升级，记录观察时长和视野 | 采空前后及出现过程；没在有限窗口看到再生只表示该窗口未观察到 |
| W03 | 采空后正常回村，再进同一区；与 W02 比较 | 同一入口、相近停留时长、相同升级 | 出入场连续录像、目标数量与类型／坐标；区分重生、重排、独立资源刷新规则 |
| W04 | 隔离研究档在部分采集／待掉落／未交售状态正常保存退出并重载 | 不做新游戏，不修改文件内容；记录退出等待和重载时间 | 货物、氧气、材料、目标状态前后表；验证哪些持久化，不能把读旧档当刷新机制 |
| W05 | 同量商品交给商店，原地观察一段时间；另一轮离场等长时间再回来 | 尽量同初始库存、售价和商店升级；无法配对则写混杂因素 | 交付、库存、金币每次变化的时码；区分即时收购、逐件售出、待售队列、满店限制与离场出售 |
| W06 | 首三趟分别记录出发、负载／氧气触发返程、交售、购买、再次出发 | 新研究档、普通输入，不加钱／材料 | 每趟起止余额、货物、氧气、耗时、购入节点；实测路线只代表该玩家选择 |
| W07 | 在购买阈值前后悬停／选择节点，记录前置、价格、效果和显隐 | 同语言与版本；购买前后各截一次 | 当前值→升级值、扣款／扣料、解锁连线与后续节点；不可读数值留空，不臆补全树 |
| W08 | 比较“容量先满但氧气仍够”和“氧气先低但未满载”的路线；再仅提升一个相关升级复走 | 同区与路线，记录目标差异、采集失误、工具消耗 | 两种瓶颈分别出现的时刻与剩余量；升级收益不能简单等同标称倍率 |
| W09 | 正常返程与氧气耗尽分别观察转场和回村状态 | 耗尽只用隔离研究档；记录所持商品与材料 | 连续出入场、落点、货物／金币／氧气变化；区别惩罚、救援、补给与售卖 |
| W10 | 遇到新的材料、设施、区域、便利或后期系统，记录首次可用→操作→结果 | 以实际解锁顺序为准，不预设系统存在 | 解锁门槛、动作、反馈、资源用途及对原循环的影响；视频未出现不等于游戏没有 |
