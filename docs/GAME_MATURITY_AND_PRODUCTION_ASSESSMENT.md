# 《无名：成蜂》成熟度、市场定位与新品节生产评估

评估日期：2026-08-24；事实源同步：2026-08-26
当前固定可玩 artifact：`57aefc4933db88968777b11ea1d1679c6374842a`，包含 PR #76 秋季双轨、PR #79 Boss 失败／暂停、PR #81 弹层焦点／切出暂停、PR #82 导出门禁和 PR #87 B01 固定急转切片／共享急转运行时／证据门禁；标准包无秋季直达，尚无 Alan B01 result JSON，Windows 真机与实机混音仍待验证
目标窗口：Steam 2026 年 10 月新品节

## 执行摘要

《无名：成蜂》不是“刚有想法”的原型，而是一个**工程完成度较高、产品验证和商业表现明显滞后的候选垂直切片**。

综合判断：

| 目标形态 | 当前成熟度 | 结论 |
|---|---:|---|
| 内部可玩原型 | 85% | 已成立 |
| 封闭外测构建 | 70% | 接近可用，但缺 Windows 真机与人工全流程 |
| Steam 新品节公开 Demo | 55% | 可以冲刺，主要缺外测、视听、商店与 Steam 接入 |
| 正式收费版本 | 30% | 暂不具备内容厚度、表现和市场验证 |

现阶段正确目标不是两个月完成正式游戏，而是把现有原型收敛成一个可验证市场的高质量 Demo。总时长不再预设为 32–42 分钟；新品节的主要任务是验证：陌生玩家是否理解“搜、驱、撤”，是否主动承担“再采一朵”的风险，以及这种差异能否转化为愿望单。

## 二、核心循环与关卡判断

### 核心循环已经完整

```text
寻找花朵
→ 飞离蜂巢
→ 停留采蜜
→ 体力下降、敌害逼近
→ 继续贪 / 震翼驱赶 / 饮蜜续航 / 主动撤离
→ 回巢卸蜜
→ 蜂巢储备增长
→ 成长选择
→ 下一节气
```

它具备明确目标、风险、决策和结果反馈。真正的差异不是“蜜蜂战斗”，而是**撤离等于回家，带回的资源服务蜂群**。这应成为商店页、截图和预告片的中心。

### 小关卡存在参数化重复风险

当前小关主要由目标、花量、能耗、敌害组合、颜色和季节机制变化。这足以建立难度曲线，但不自动构成 24 个不同体验。玩家可能感到“又采一次，只是数字和颜色不同”。

当前拓扑不是“每季六个小关，第六个必然是 Boss”。`seasons.json` 共有 24 个数据节点：授粉普通节点 0–5 之后是春分 Boss 6；袭扰普通节点 7–11 之后是夏至 Boss 12；留种普通节点 13–17 之后是秋分 Boss 18；暖点普通节点 19–23 之后，由状态流进入冬至熊。

内容角色应根据节点／Boss 用时、失败原因与无决策重复时长来分配：先证明玩家能看懂本组规则，再增加路线变化、压力或机制组合。不能为了填满预设的“六种职能”而扩写重复内容；若外测证明节点只是参数变化，再决定压缩、重排或加深。

### 四组季节行为已实现，感知证据不足

| 季节 | 设计作用 | 必须造成的行为变化 |
|---|---|---|
| 春 | 开放花授粉 | 从开放花药取粉，送到同型开放柱头结籽；授粉不增加花蜜 |
| 夏 | 实体袭扰 | 首次真实卸蜜后打断原路线，逐只惊退偷蜜并持赃的有翅劫掠者 |
| 秋 | 野外留种 | 最后一滴前松手，决定采尽还是留种并通过真实归巢使其成熟 |
| 冬 | 暖点接力 | 在寒冷减速中用携蜜依次点亮 3 个暖点，逐段开放远花路线 |

每季进入后 20 秒内，玩家必须通过画面、声音或规则变化感到不同，不能只依赖文字和色板。如果陌生玩家无法复述差异，问题在机制反馈，不应继续增加节气文案。

### Boss 已有独立暴露条件，仍待玩家复述

四位 Boss 共用“进入暴露窗口后，在共鸣实体附近震翼登记一次调律”的收束，但前提不同：蚊完成真实吸取、油葫芦真实落地、画眉被寻迹揭出真声、熊在玩家闪过冲锋后撞上暖息花。每次成功只推进 1 次，共 3 次；阶段会加速、缩短窗口，画眉假回声增加。Boss 失败后，玩家必须能说出输给哪个独特规则；自动状态机测试不能替代这项复述。

### 发布结论

- 简单并不阻止发布免费 Demo；
- 重复、不可读和缺少视听表现会阻止 Demo 获得市场反馈；
- 当前内容不建议直接正式收费发行；
- 在路线与构筑变化得到验证前，不应把产品承诺为深度 Roguelite。

## 三、市场定位

目标玩家不是单一群体，而是两个相邻受众的交集：

1. 喜欢自然、采集、生态和温和视觉的休闲玩家；
2. 喜欢资源风险、撤离判断和短局重开的策略动作玩家。

市场表达应避免两种误判：

- “蜜蜂模拟经营”：当前没有 APICO 式繁育、生产链和沙盒经营深度；
- “蜂群战斗肉鸽”：当前差异恰恰是非杀戮、撤离与生态流转。

推荐品类语言：

> 一款关于采集、风险和归巢的轻量动作冒险。每次飞离安全的蜂巢，都要决定再采一朵，还是带着现有收获回家。

早期标签以实际行为为准：`动作冒险`、`资源管理`、`自然`、`风格化`、`单人`、`俯视`、`短篇`。`动作类 Rogue` 或 `轻度 Rogue` 应在外测确认重玩性与构筑预期后再进入前五标签。

## 四、美术生产需求

仓库已有产品 HUD、低噪背景、独立蜂巢、玩家蜂、8 种季节花和机制实体进入真实构建，但这些仍是候选切片，不等于商业美术完成。当前语言以布艺贴花主体、毛毡体积、蜂蜡生命能量、浅色植鞣革蜂群设施和刺绣信息轨迹为核心；剪纸主方向已经撤回。主要风险是运动中的主体读取、整体统一、授粉器官可辨识和成长界面仍偏数值化。

### 第一优先级：核心可读资产

- 玩家蜜蜂：飞行、采蜜、受击、震翼、携蜜、力竭；
- 蜂巢：安全、卸蜜、衰弱三种状态；
- 四季普通花每季约 2 种，以及一眼可辨的高价值花；
- 普通敌害与四位失律者的独立轮廓；
- 共鸣点的静止、可用、成功、失效状态；
- 携蜜、体力、敌害警戒、归巢路线的统一表达；
- 四季各一套背景、地面和空气效果。

### 第二优先级：营销资产

- 一张接近最终方向的关键视觉；
- Steam 全套胶囊图；
- 5–8 张真实游戏截图；
- 3 个循环 GIF；
- 30–60 秒玩法预告片；
- 中英文 Logo 与简单媒体包。

### 第三优先级：节点演出

- 出巢、首次交蜜、季节转换、Boss 登场、调律成功、通关与愿望单结束页。

### 推荐制作方法

先把已经接入 Godot 的**春季代表切片**做到可动态审阅：玩家、主蜂巢、普通花与授粉花器官、敌害、一次采蜜归巢、HUD 和机制反馈必须在运动中同时可读。验证截图传播性和资产复制成本后，再按同一语法扩展其余三季。禁止先批量制作 24 套节气资产。

## 五、音乐与声音需求

当前已接入春夏秋冬各 1 首探索和 1 首 Boss 变奏，共 8 个独立 WAV；旧单一程序化背景循环已经移除。它们仍是候选配乐，不能替代盲听、实机混音和后续商业母带判断。

PR #64 已以 `b03811c4` squash merge 到 `origin/main`，并提供 `npm run audio:review` 生成的 8 轨匿名盲听包。自动测试固定了 WAV 哈希、A–H 匿名映射、正确配对、侦听端不泄露答案与输出目录安全性。Alan 随后完成逐轨评论、PR #70 定向 A/B、Draft PR #74 方向选择和 PR #76 全长最终 A/B；最终探索与 Boss 两组均盲选新版秋季候选。该结果关闭秋季双轨创作者替换门禁，不关闭整套情绪、同季配对、三轮耐听或实机混音。

当前音乐验收优先级：

- 盲听同季探索／Boss 配对和四组气质；
- 连续循环三轮后的疲劳、不舒服音色和低频占位；
- 实机检查采蜜、攻击锁线、真正急转成功、归巢与调律 cue 是否被音乐遮蔽；
- 夏 Boss 笛式标点仍可在整套复听中观察；旧秋探索二胡式滑音已随被否决版本退出，不再重复 A/B；
- 只有真人记录指出问题后才定向修订，不先按“轨数不够”扩产。

后续候选的动态结构（不是当前已实现事实）：

```text
普通采集：季节基础主题
敌害接近：加入危险节奏
体力告急：降低旋律、强化脉冲
进入蜂巢：移除危险层、加入安全和声
Boss：保留季节调式、叠加 Boss 动机
```

音效优先于完整配乐。玩家应在不看 HUD 时也能听出蜜囊将满、体力危险、敌害进入警戒、进入安全区、花蜜正式入库以及震翼是否成功。

## 六、AI 专家试玩的能力边界

### 可以有效承担

- 专家认知走查与首分钟教学审计；
- 关卡数据、难度曲线和失败路径分析；
- UI 信息层级与商店承诺一致性审计；
- 边界条件、软锁和不同策略模拟；
- 对完整录像逐秒标注理解问题；
- 设计遥测事件、试玩问卷和修复优先级；
- 在控制工具可用时完成无外部说明的专家操作测试。

### 不能替代真人外测

- 评估者已经读过设计与代码，不再是陌生玩家；
- AI 不产生真实购买冲动、疲劳、挫败和审美偏好；
- 单个 AI 样本不代表不同经验、语言和设备玩家；
- 专家可发现可用性问题，但不能证明游戏好玩；
- 本轮已有本机应用控制、真实窗口输入回归、候选窗口检查和 B01 精确 ticket 启动，但尚未形成 Alan B01 result JSON、完整人工一局或任何陌生玩家记录；这些开发者证据仍不能伪装成真人试玩结果。

最低现实方案为 3–5 名异步真人：发送安装包或私有链接、不解释操作、要求录屏或启用匿名事件遥测，最后填写两分钟问卷。三个陌生真人仍然远胜于大量开发者自测和一个 AI 样本。

建议遥测：`game_started`、`first_move`、`first_harvest`、`first_damage`、`first_repel`、`first_return_decision`、`first_deposit`、`stage_completed`、`boss_started`、`boss_failed`、`run_restarted`、`demo_completed`、`wishlist_clicked`，并记录相对时间。

## 最终结论

核心循环足以支撑一个有辨识度的新品节 Demo；24 个数据节点有参数重复风险，四组机制与四位 Boss 已有实现但缺少陌生玩家的感知证据；美术与音乐已进入候选构建，仍未通过完整商业品质和真人听感门禁。项目应参加新品节，但必须将其定义为市场验证，而不是正式发行前的最后冲刺。

接下来两周，任何不能帮助“完成报名、让陌生玩家理解核心循环、验证主动撤离，或建立一个可传播的代表场景”的需求，都不进入排期。

## 九、2026-08-24 玩家反馈后的修订与纠偏

玩家明确反馈关卡过短简单、教学未覆盖寻迹/惊退/闪避、音乐听感只有一首、文字解释过多，以及四季玩法感知为“只有采蜜”。代码审计确认：四套程序旋律和四季机制脚本存在，但统一音色结构、短关触发时机和文字化反馈使其在产品体验中等同于未实现。

初版修订曾据此直接决定“目标 Demo 32–42 分钟、24 节气改成四季大关内部连续阶段”。该结论没有经过可玩切片验证，属于把感受反馈过早翻译成产品结构，现已撤回。

当前决定是保留 24 节点，在现有结构内让第一关教学、四季路线差异、四位 Boss 暴露条件和 4 组探索／Boss 音乐变奏成为可直接体验的事实；关卡时长只记录、不预设答案。实施状态、证据等级和外部复测门槛以 `PLAYER_FEEDBACK_ACTION_PLAN_2026-08-24.md` 为准。
