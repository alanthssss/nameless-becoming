# 《无名：成蜂》成熟度、市场定位与新品节生产评估

评估日期：2026-08-24
评估基线：Godot `0.9.5-rc.2`
目标窗口：Steam 2026 年 10 月新品节

## 执行摘要

《无名：成蜂》不是“刚有想法”的原型，而是一个**工程完成度较高、产品验证和商业表现明显滞后的候选垂直切片**。

综合判断：

| 目标形态 | 当前成熟度 | 结论 |
|---|---:|---|
| 内部可玩原型 | 85% | 已成立 |
| 封闭外测构建 | 70% | 接近可用，但缺 Windows 真机与人工全流程 |
| Steam 新品节公开 Demo | 55% | 可以冲刺，主要缺外测、视听、商店与 Steam 接入 |
| 正式收费版本 | 30% | 暂不具备内容厚度、表现和市场验证 |

现阶段正确目标不是两个月完成正式游戏，而是把现有原型收敛成一个 32–42 分钟、可验证市场的高质量 Demo。新品节的主要任务是验证：陌生玩家是否理解“搜、驱、撤”，是否主动承担“再采一朵”的风险，以及这种差异能否转化为愿望单。

## 一、成熟度审计

| 维度 | 成熟度 | 依据与风险 |
|---|---:|---|
| 核心概念 | 80% | “蜜蜂生态 × 东方节气 × 轻撤离”有清晰差异 |
| 核心玩法实现 | 80% | 搜蜜、携带、体力、敌害、撤离、归巢结算闭环已实现 |
| 玩法验证 | 30% | 外部试玩记录仍为 0；开发者自测不能证明乐趣 |
| 内容结构 | 70% | 24 节气、四季机制、成长和四位失律者已进入代码与数据 |
| 新手体验 | 55% | 有行为驱动教学，但未由陌生玩家验证 |
| 视觉表现 | 35% | 有概念方向，实际运行资产仍以原生绘制和占位表达为主 |
| 音频表现 | 45% | 有程序化音乐与反馈音，未完成动态层、混音和陌生玩家听感验证 |
| 技术稳定性 | 80% | Web/Godot CI、自动测试、三端构建链路较完整 |
| 平台发行 | 40% | Windows 真机、Steam Demo App、Depot 和审核尚未完成 |
| 商业准备 | 15% | 尚无公开商店页、愿望单基线、媒体包和创作者触达 |
| 正式版内容 | 25% | 适合垂直切片，不足以支撑正式收费版本 |

### 已经成熟的条件

- Godot 工程实现直接飞行、采蜜、震翼、寻迹、诱饵、闪避与归巢；
- 花蜜只有回巢后才进入储备，失败掉落与敌害盗蜜遵循守恒设计；
- 24 节气参数、四季机制和四位失律者已数据化；
- Web、macOS、Windows 由同一 Godot 工程导出；
- 自动门禁覆盖脚本解析、完整状态流、Boss 上下文、资源可解性、输入和 Web 构建；
- PR #52 的 Godot 测试和 Web 构建、测试、lint 全部通过。

### 尚未成熟的条件

- 没有独立外部玩家数据；
- 没有真实 Windows x86_64 全流程验证；
- 没有记录首次交蜜时间、首局时长、中途退出点和失败后重开率；
- 四季是否在实际游玩中被感知为机制变化尚未验证；
- 商业视觉尚未接入实际游戏；
- Steamworks、商店页、AppID、Demo Depot 和新品节报名尚未形成完成证据；
- 正式版的长期构筑、路线变化与内容价值仍不足。

## 二、核心循环与关卡判断

### 核心循环已经完整

```text
寻找花朵
→ 飞离蜂巢
→ 停留采蜜
→ 体力下降、敌害逼近
→ 继续贪 / 震翼驱赶 / 饮蜜续航 / 主动撤离
→ 回巢卸蜜
→ 蜂巢储备增长
→ 成长选择
→ 下一节气
```

它具备明确目标、风险、决策和结果反馈。真正的差异不是“蜜蜂战斗”，而是**撤离等于回家，带回的资源服务蜂群**。这应成为商店页、截图和预告片的中心。

### 小关卡存在参数化重复风险

当前小关主要由目标、花量、能耗、敌害组合、颜色和季节机制变化。这足以建立难度曲线，但不自动构成 24 个不同体验。玩家可能感到“又采一次，只是数字和颜色不同”。

每季六个节点应承担不同职能：

1. 引入关：安全展示本季规则；
2. 变化关：改变路线或资源分布；
3. 压力关：迫使玩家主动撤离；
4. 组合关：季节机制与敌害组合；
5. 高潮关：极端收益与风险；
6. 正色 Boss：检验本季学到的行为。

如果六个节点无法形成六种职能，应压缩相似节点。对 Demo 而言，四个有行为差异的节点优于六个参数节点。

### 四季大关概念完整，感知证据不足

| 季节 | 设计作用 | 必须造成的行为变化 |
|---|---|---|
| 春 | 授粉与生长 | 主动规划授粉顺序，让花田产生新收益 |
| 夏 | 征召与高压劳动 | 在高收益采集与蜂群并行需求间选择 |
| 秋 | 储备与规划 | 提前准备储备，不能只看当前交付目标 |
| 冬 | 抱团、体温与生存 | 围绕安全区、体温和活动半径规划路线 |

每季进入后 20 秒内，玩家必须通过画面、声音或规则变化感到不同，不能只依赖文字和色板。如果陌生玩家无法复述差异，问题在机制反馈，不应继续增加节气文案。

### Boss 的共同语法可保留

“引向共鸣点，再以震翼调律”作为共同操作语法是合理的。四位 Boss 至少应各自制造一种不同问题：

- 蚊：持续追击，测试震翼时机；
- 油葫芦：快速变向，测试预判与诱导；
- 画眉：诱惑或假目标，测试路线判断；
- 熊：压缩安全空间，测试耐力和长期规划。

Boss 失败后，玩家必须能说出输给了哪个独特规则。仅改变速度和轨迹不足以支撑四次高潮。

### 发布结论

- 简单并不阻止发布免费 Demo；
- 重复、不可读和缺少视听表现会阻止 Demo 获得市场反馈；
- 当前内容不建议直接正式收费发行；
- 在路线与构筑变化得到验证前，不应把产品承诺为深度 Roguelite。

## 三、市场定位

目标玩家不是单一群体，而是两个相邻受众的交集：

1. 喜欢自然、采集、生态和温和视觉的休闲玩家；
2. 喜欢资源风险、撤离判断和短局重开的策略动作玩家。

市场表达应避免两种误判：

- “蜜蜂模拟经营”：当前没有 APICO 式繁育、生产链和沙盒经营深度；
- “蜂群战斗肉鸽”：当前差异恰恰是非杀戮、撤离与生态流转。

推荐品类语言：

> 一款关于采集、风险和归巢的轻量动作冒险。每次飞离安全的蜂巢，都要决定再采一朵，还是带着现有收获回家。

早期标签以实际行为为准：`动作冒险`、`资源管理`、`自然`、`风格化`、`单人`、`俯视`、`短篇`。`动作类 Rogue` 或 `轻度 Rogue` 应在外测确认重玩性与构筑预期后再进入前五标签。

## 四、美术生产需求

仓库已有冬至 HUD、成长界面和候选概念图，但这些属于方向验证，不等于已接入的商业美术。现有概念方向具备深蓝、米黄、正色、蜂巢六边形和节令品牌语言；当前优先比较毛毡微缩与布艺贴花，主要风险是游戏内主体读取、整体偏暗、成长仍像数值菜单，以及织物、蜂蜡、浅色植鞣革与刺绣语言尚未统一。剪纸主方向已经撤回。

### 第一优先级：核心可读资产

- 玩家蜜蜂：飞行、采蜜、受击、震翼、携蜜、力竭；
- 蜂巢：安全、卸蜜、衰弱三种状态；
- 四季普通花每季约 2 种，以及一眼可辨的高价值花；
- 普通敌害与四位失律者的独立轮廓；
- 共鸣点的静止、可用、成功、失效状态；
- 携蜜、体力、敌害警戒、归巢路线的统一表达；
- 四季各一套背景、地面和空气效果。

### 第二优先级：营销资产

- 一张接近最终方向的关键视觉；
- Steam 全套胶囊图；
- 5–8 张真实游戏截图；
- 3 个循环 GIF；
- 30–60 秒玩法预告片；
- 中英文 Logo 与简单媒体包。

### 第三优先级：节点演出

- 出巢、首次交蜜、季节转换、Boss 登场、调律成功、通关与愿望单结束页。

### 推荐制作方法

先完成一个真正接入 Godot 的冬至代表场景：玩家、蜂巢、三种花、两种敌害、一次采蜜归巢、HUD、共鸣点和冬季环境。验证运动中的读取、截图传播性和资产复制成本后，再扩展其余季节。禁止先批量制作 24 套节气资产。

## 五、音乐与声音需求

程序化五声音阶可以继续承担机制验证，但不能替代商业配乐、动态层和混音。

新品节最小音乐包：

- 四季基础主题各 60–90 秒，可循环；
- 一个蜂巢安全层；
- 一组动态危险声部；
- 四个 Boss 短动机；
- 出巢、交蜜、节令完成、Boss 登场、调律成功、失败等短句。

动态结构：

```text
普通采集：季节基础主题
敌害接近：加入危险节奏
体力告急：降低旋律、强化脉冲
进入蜂巢：移除危险层、加入安全和声
Boss：保留季节调式、叠加 Boss 动机
```

音效优先于完整配乐。玩家应在不看 HUD 时也能听出蜜囊将满、体力危险、敌害进入警戒、进入安全区、花蜜正式入库以及震翼是否成功。

## 六、AI 专家试玩的能力边界

### 可以有效承担

- 专家认知走查与首分钟教学审计；
- 关卡数据、难度曲线和失败路径分析；
- UI 信息层级与商店承诺一致性审计；
- 边界条件、软锁和不同策略模拟；
- 对完整录像逐秒标注理解问题；
- 设计遥测事件、试玩问卷和修复优先级；
- 在控制工具可用时完成无外部说明的专家操作测试。

### 不能替代真人外测

- 评估者已经读过设计与代码，不再是陌生玩家；
- AI 不产生真实购买冲动、疲劳、挫败和审美偏好；
- 单个 AI 样本不代表不同经验、语言和设备玩家；
- 专家可发现可用性问题，但不能证明游戏好玩；
- 本次会话的浏览器和本地应用控制运行时不可用，因此未完成键鼠实玩，不能把代码与画面审计伪装成试玩结果。

最低现实方案为 3–5 名异步真人：发送安装包或私有链接、不解释操作、要求录屏或启用匿名事件遥测，最后填写两分钟问卷。三个陌生真人仍然远胜于大量开发者自测和一个 AI 样本。

建议遥测：`game_started`、`first_move`、`first_harvest`、`first_damage`、`first_repel`、`first_return_decision`、`first_deposit`、`stage_completed`、`boss_started`、`boss_failed`、`run_restarted`、`demo_completed`、`wishlist_clicked`，并记录相对时间。

## 七、需求优先级

### 新品节前必须完成

1. Steamworks、本体 AppID、商店页与新品节报名；
2. 开发者人工完整一局和真实时长；
3. 3–5 名首轮真人测试，最终累计 10 名；
4. 首分钟教学、主动撤离和卸蜜反馈；
5. Windows 真机与 Steam Demo 配置；
6. 一个接入游戏的高质量代表场景；
7. 核心音效和四季可感知差异；
8. 愿望单、反馈和再来一局结束页；
9. 胶囊图、截图、预告片和媒体包。

### 新品节后再做

- 完整身份徽章系统；
- 新角色、新地图和第二模式；
- 深度元进度与大量成长路线；
- 24 套独立美术或音乐；
- 大量剧情与配音；
- 联机、排行榜、云服务；
- 未经验证的 Steam Deck 正式支持。

### 资源建议

最值得并行外包或邀请协助的顺序：

1. 主胶囊与关键视觉；
2. 预告片剪辑；
3. 英文商店文案校对；
4. Windows 真机测试；
5. 外部试玩招募和组织。

核心玩法和数值调整不宜外包，因为反馈周期短且依赖现有资源守恒、节气与蜂群设计。

## 最终结论

核心循环足以支撑一个有辨识度的新品节 Demo；小关卡有参数重复风险，大关卡有设计但缺少陌生玩家的感知证据；美术和音乐仍处于概念与验证阶段。项目应参加新品节，但必须将其定义为市场验证，而不是正式发行前的最后冲刺。

接下来两周，任何不能帮助“完成报名、让陌生玩家理解核心循环、验证主动撤离，或建立一个可传播的代表场景”的需求，都不进入排期。

## 九、2026-08-24 玩家反馈后的修订

玩家明确反馈关卡过短简单、教学未覆盖寻迹/惊退/闪避、音乐听感只有一首、文字解释过多，以及四季玩法感知为“只有采蜜”。代码审计确认：四套程序旋律和四季机制脚本存在，但统一音色结构、短关触发时机和文字化反馈使其在产品体验中等同于未实现。

本评估据此修订：目标 Demo 从 15–25 分钟调整为 32–42 分钟；24 节气改为四季大关内部连续阶段；教学改为六步行动式体验；音乐采用 1 个蜂巢主题、4 个探索主题、4 个 Boss 主题/变奏和状态层；四季机制必须进入大关完成条件。完整整改与排期见 `PLAYER_FEEDBACK_ACTION_PLAN_2026-08-24.md`。
