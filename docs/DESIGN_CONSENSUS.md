## 二、四个落地重点详细对照

### 重点 1 · 玩家的实时操作循环 —— ✅ 已基本实现

**每分钟实际在做什么**（当前版本的真实闭环）：

```text
飞向花朵（WASD，持续飞自动振翅加速）→ 近花按住空格采蜜（逐滴、需停留）
→ 体力下降、蚊虫/掠蜜蚁逼近 → 决定继续贪、持续飞脱离、
近敌空格惊退驱敌、双击方向急转闪避，或松开空格后长按投蜜诱饵
→ 体力耗尽前按 Q 归巢自动飞回 → 结算入公共储备 → 触发下一节令
```

**已落地清单**（对应代码；输入已合并为情境动作键，见 2026-08-18 输入收敛）：

| 动作 | 输入 | 成本/限制 | 落点 |
| --- | --- | --- | --- |
| 飞行（加速/惯性/制动模型） | WASD / 方向键 | 持续缓慢耗体力 | `bee_player.gd:_physics_process` |
| 振翅加速 | WASD 持续飞自动触发（体力 > 8） | 额外耗体力 | `bee_player.gd` 自动冲刺 |
| 采蜜 | 空格（近花时） | 停留 + 额外耗体力，逐滴 | `main.gd:update_game` |
| 震翼惊退 | 空格（近敌时） | 8 体力 + 冷却，敌人实际向外移动 | `main.gd` / `balance.json` |
| 触角寻迹 | 空格（静止时） | 3 秒持续、7 秒冷却 | `main.gd:on_sense_started` |
| 投蜜诱饵 | 松开空格后长按（需携蜜） | 1 滴携蜜、5 秒、结束归回花田 | `main.gd:drop_honey_decoy` |
| 急转闪避 | 双击方向键 | 12 体力、1.6 秒冷却、短暂无伤 | `main.gd` 双击检测 / `bee_player.gd:try_evade` |
| 归巢结算 / 失败 | Q 自动飞回；失败不按键 | 失败损失携蜜但资源守恒 | `main.gd:update_hive_rest / fail_expedition` |

> 输入映射仅剩 `move_*` / `action`（空格+回车）/ `return_hive`（Q），旧的 I/O/U/J/K/L/E/Shift 独立按键已全部移除（`smoke_test.gd` 断言旧 action 不存在）。

**差距**：
- "战斗"维度仍薄：玩家唯一对抗手段是惊退/闪避/诱饵，无主动进攻性互动；与"移动↔采集↔战斗"的切换节奏还有设计空间。
- 每节令同一套操作，尚无节令特有的操作差异（例如冬季寒风区、秋季枯花干扰仍只在数据层存在）。

### 重点 2 · 蜂巢成长系统 —— 🟡 部分实现

**已落地**：
- 每完成一个节令进入一次三选一（0.6）：长翼蜂/采蜜蜂/守卫蜂，同类可叠 2 次，构成轻量构筑；
- 成长会改变**实际手感**而非纯数字：速度、振翅耗能、采蜜间隔、额外留蜜、惊退范围、冷却（`upgrades.json` → `main.gd:on_upgrade_selected`）；
- 外部 JSON 驱动，便于扩充与平衡。

**差距**：
- 无建筑、无扩建，蜂巢仍是背景贴图；
- 公共储备只有数字结算，没有实际消耗/产出（如哺育下一代、解锁区域）；
- "培育下一代"（幼虫→成蜂的变态发育路线）完全未做；
- 成长目前是"本局增益"，不是"蜂巢状态"——玩家感受不到蜂巢在成长。

### 重点 3 · Demo 单季节设计 —— 🟡 部分实现（方向有演化）

**现状**：MVP 实际交付的是**四个压缩节令 + 失律之蚊 Boss**，全流程 15～25 分钟，同一张单屏地图按 `seasons.json` 参数连续变化。

**与"只做一个代表性季节"共识的关系**：
- 共识本意是"不要四张不同颜色的地图"，当前实现恰好规避了这一点（四节令共享一张地图，差异来自参数与配色曲线）；
- 代价是牺牲了单季节的**深度**：没有地图规模、路线选择、区域差异，也没有完整 Boss 的流程设计（Boss 是 3 次调律的单场景遭遇）。

**结论性建议**：把「冬至 + 失律之蚊」视为第一个完整单季节 Demo 的候选核——它已有最低生存压力和唯一的 Boss 遭遇，扩展成"含路线选择的小地图 + Boss 遭遇"的完整关卡，成本最低、验证价值最高。

### 重点 4 · 角色身份成长 —— ⬜ 已确定未实现

**设计共识**（已确定）：玩家不知道自己是工蜂/雄蜂/王蜂/侦查蜂（游戏设定），通过经历逐渐意识到不同身份意味着不同责任；完全变态发育（卵→幼虫→蛹→成蜂）作为职业成长；不靠菜单，靠玩法。

**现状**：
- 代码中无任何身份系统（检索 `godot/` 无 identity/身份/工蜂/雄蜂等命中）；
- 现有的长翼/采蜜/守卫三选一本质是**分工倾向**，是身份概念的种子，但没有"身份"本身；
- 结算文案（"你没能带回花蜜，蜂巢的呼吸弱了一分"）已有责任归属感，但未点破身份。

**最小验证路径 · 生态修正版（2026-08-18 生态学核查后升级）**：不做菜单化职业，在**结算时揭示身份**——但初版"行为占比→标签"经生态学核查（年龄多态性 + 行为可塑性文献，2023《Science》摇摆舞社会学习）发现三处偏差，已修正为三维机制：

| 维度 | 生态依据 | 游戏化 |
| --- | --- | --- |
| 生命阶段（时间） | 年龄多态性：工蜂按日龄从巢内任务（清洁/育幼/筑巢）推进到巢外（守卫/采集），危险任务留给老龄个体 | 节令模拟日龄：春=幼蜂（巢内任务），夏=成蜂（巢口任务），秋=资深（巢外解锁：采集→侦察） |
| 任务角色（行为） | 行为可塑性：工蜂是全能选手（jack-of-all-trades），任务由"实际做了什么"决定，无终生职业 | 行为占比决定"本季主任务"；受阶段约束——幼龄做不了危险任务 |
| 蜂群需求（调节） | 行为可塑性：缺采集蜂→年轻蜂提前外采（最早 5 天）；缺育幼蜂→老采集蜂返老还童回巢育幼（可再生腺体） | 缺蜜→征召守卫去采集；缺守卫→采集蜂回防；危机事件→全员返老还童 |

**关键修正**：初版"回避战斗→侦查蜂"是**生态学错误**——侦察蜂不是胆小新手，而是采集蜂中最资深、最年长的精英（外勤 <10%），是"采集的毕业进阶"。修正为：**侦察 = 采集资历达阈值后解锁**；探索成功 → 回巢跳摇摆舞把花源信息教给蜂群（舞步需向老蜂社会学习才准确），即"探索→影响蜂群"的真实操作化。

**最新演化 · 属性节点 × 成就徽章（2026-08-18，alan；详见 PROJECT_LOG 第十三节）**：身份**不选一个、也不揭示为单一标签**，拆为两层——

1. **属性节点层**：三选一升级 = 纯能力构筑，不承担身份语义（现有"长翼蜂/采蜜蜂/守卫蜂"命名待去职业化）；
2. **成就徽章层**：身份 = 徽章系统，基于**实际做了什么事 + 完成程度**事后授予，徽章集合构成身份画像。

生态自洽性：徽章 = 被蜂群记住的事迹（非任命），比单一标签更贴行为可塑性；侦察进阶用徽章前置链表达（采集徽章达阶→解锁侦察）；"完成程度"以徽章分阶呈现（如驱退掠夺者 1/5/20 次），区分"事迹"与"统计"；结算时由徽章组合生成一句身份描述（"这一季，你主要被花需要"），零新增操作。

### 重点 5 · 四季差异化玩法设计 —— 🟡 已实现（原型级，待手感验证）

**触发**：生态核查后身份机制扩展出多个行为维度（授粉/征召/储备/抱团），超出"仅采蜜"单动作 → 每季应有一个区别于其他季节的招牌玩法。

**设计原则**：不推翻"搜打撤 + 采蜜"骨架（四季共有层）；每季一个招牌机制作为**叠加层**，全部从已确认的生态机制长出；四季之间形成跨季因果链；身份三维机制（重点 4）借四季自然落地——阶段=节令推进、角色=行为占比、需求=夏至征召。

**修正版四季矩阵（2026-08-18 哲学核查后定稿，★=本轮修正）**：初版设计对照「循环/共生/无二元」哲学与生态事实，修正 4 处偏差并划定 1 条边界：

| 季节 | 生命阶段 | 招牌机制 | 玩法差异（修正版） | 生态/哲学依据 |
| --- | --- | --- | --- | --- |
| 春分 | 幼蜂·学习季 | **授粉 · 花田的馈赠** | 花田是活的：采蜜使新花开放，久不采则**休眠**（非凋零损失，来年随循环重开）；目标从"采 N 朵"变为"维持花田活力 + 归巢" | 授粉是生态的一部分而非任务；休眠与花蜜总量守恒不冲突 |
| 夏至 | 成蜂·高压季 | **征召 · 被需要的方式** | ★巢口告急 / 花区告急交替出现，玩家响应哪边都是贡献——**被需要的方式在变化**，而非"个体 vs 集体"的对立 | ★修正 1：真实工蜂无私人利益；行为可塑性是"蜂群需求驱动换任务"，不是牺牲自己服务蜂群 |
| 秋分 | 资深·匮乏季 | **储备 · 为来年投资** | ★抉择变为蜂群未来的两种投资：**储备冬蜜**（越冬燃料）vs **哺育幼虫**（来年劳动力）；★驱逐雄蜂 = 停止供养/拒绝入巢，**零战斗零敌意** | ★修正 2：真实蜂巢无私有财产，强化个体 = 强化蜂群；★修正 3：雄蜂是同类不是敌人 |
| 冬至 | 老龄·极限季 | **抱团 · 共御严寒** | 巢内抱团保温、消耗公共储备；★**储备是选项空间不是生死线**：储备足→从容（可抱团、可稳采），储备不足→选择变少、更依赖冒险（风险留给老兵）；侦察解锁 + 摇摆舞分享花源 | ★修正 4：生态语言替换经济隐喻；★边界：没有玩错的局，只有不同活法的局 |

**被需要的四季（深层结构）**：春被花需要（授粉）、夏被巢需要（征召）、秋被来年需要（储备）、冬被彼此需要（抱团）——"被需要的方式"每季在变，结算揭示"这一季你主要被怎么需要、你又主要做了什么"。**四季玩法不是四个并排系统，它就是「无名→成蜂」的操作化**：完整走完一轮四季，玩家才第一次真正理解标题在说什么；四季玩法与身份揭示是同一个东西的两面。

**跨季因果链**：春·授粉（花田的馈赠）→ 夏·征召（被需要的方式）→ 秋·储备（越冬本钱）→ 冬·抱团（共御严寒 + 侦察）。

**实现路径（架构不变，增量扩展）**：
1. ✅ `seasons.json` 每季增加 `mechanics: ["pollination"]` 等玩法槽位（数据驱动，与现有参数并列）；
2. ✅ `main.gd` 增加**季节机制调度层** `season_mechanics.gd`：`spawn_stage` 时按当前 stage 的 mechanics 列表启停对应子系统；
3. ✅ 每个机制独立实现（状态 + 更新 + 绘制），经采蜜/归巢/结算/抉择四个节点钩子接入，不侵入现有主循环；
4. ✅ 四季全量实现（2026-08-18，响应"把四季都实现了吧"）：授粉/征召/储备/抱团四脚本 + `balance.json` mechanics 分区 + 分配面板 UI；smoke_test / flow_test 全绿，headless 启动零报错（详见 PROJECT_LOG 十四节）。

**实现后的已知边界**：秋分驱逐雄蜂事件未实现（需零战斗零敌意表达）；冬至侦察收益链未闭环；结算"被需要的四季"身份描述依赖重点 4 徽章系统；**手感与主题表达待实机试玩验证**（原"先做 1~2 季验证"的步骤因全量实现而顺延）。

**关卡结构（4 × 6 + 四正色 Boss）**：每大关 6 个小关卡对应六个节气节点，色调逐阶渐变；**守关 Boss 位于终点正色节点**——正色即阴阳消长的关键转折，也是失律者盘踞之处（Boss 从"每季第 6 小关"调整而来，比"第六小关"更具结构一致性）。

**功能色分配**：青=生机/采集/按钮，朱=危险/Boss/受击，白=蜂巢/安全/结算，玄=背景/终点/未知；材质原则=低饱和低对比 + 宣纸/岩彩纹理，避免纯色塑料感。

**实现状态**：设计/文档已定稿（PR #3 待合并）；**代码未接入**——`seasons.json` 尚无双色/节气渐变字段，场景仍用 0.9.4 的四节令单关配色，`CanvasModulate` 与 UI 调色板待实现。
