## 二、四个落地重点详细对照

### 重点 1 · 玩家的实时操作循环 —— ✅ 已基本实现

**每分钟实际在做什么**（当前版本的真实闭环）：

```text
飞向花朵（WASD / 鼠标）→ 按住采蜜（I/空格，逐滴、需停留）
→ 体力下降、蚊虫/掠蜜蚁逼近 → 决定继续贪、振翅脱离（O）、
惊退驱敌（J）、急转闪避（K）或投蜜诱饵（L）
→ 体力耗尽前亲自飞回左侧蜂巢 → 结算入公共储备 → 触发下一节令
```

**已落地清单**（对应代码）：

| 动作 | 输入 | 成本/限制 | 落点 |
| --- | --- | --- | --- |
| 飞行（加速/惯性/制动模型） | WASD / 方向键 / 鼠标目标 | 持续缓慢耗体力 | `bee_player.gd:_physics_process` |
| 采蜜 | I / 按住空格 | 停留 + 额外耗体力，逐滴 | `main.gd:update_game` |
| 振翅 | O / Shift | 高体力消耗 | `bee_player.gd` |
| 震翼惊退 | J | 8 体力 + 冷却，敌人实际向外移动 | `main.gd` / `balance.json` |
| 触角寻迹 | U / E | 3 秒持续、7 秒冷却 | `main.gd:on_sense_started` |
| 急转闪避 | K | 12 体力、1.6 秒冷却、短暂无伤 | `bee_player.gd:try_evade` |
| 投蜜诱饵 | L | 1 滴携蜜、5 秒、结束归回花田 | `main.gd:drop_honey_decoy` |
| 归巢结算 / 失败 | — | 失败损失携蜜但资源守恒 | `main.gd:update_hive_rest / fail_expedition` |

**差距**：
- "战斗"维度仍薄：玩家唯一对抗手段是惊退/闪避/诱饵，无主动进攻性互动；与"移动↔采集↔战斗"的切换节奏还有设计空间。
- 每节令同一套操作，尚无节令特有的操作差异（例如冬季寒风区、秋季枯花干扰仍只在数据层存在）。

### 重点 2 · 蜂巢成长系统 —— 🟡 部分实现

**已落地**：
- 每完成一个节令进入一次三选一（0.6）：长翼蜂/采蜜蜂/守卫蜂，同类可叠 2 次，构成轻量构筑；
- 成长会改变**实际手感**而非纯数字：速度、振翅耗能、采蜜间隔、额外留蜜、惊退范围、冷却（`upgrades.json` → `main.gd:on_upgrade_selected`）；
- 外部 JSON 驱动，便于扩充与平衡。

**差距**：
- 无建筑、无扩建，蜂巢仍是背景贴图；
- 公共储备只有数字结算，没有实际消耗/产出（如哺育下一代、解锁区域）；
- "培育下一代"（幼虫→成蜂的变态发育路线）完全未做；
- 成长目前是"本局增益"，不是"蜂巢状态"——玩家感受不到蜂巢在成长。

### 重点 3 · Demo 单季节设计 —— 🟡 部分实现（方向有演化）

**现状**：MVP 实际交付的是**四个压缩节令 + 失律之蚊 Boss**，全流程 15～25 分钟，同一张单屏地图按 `seasons.json` 参数连续变化。

**与"只做一个代表性季节"共识的关系**：
- 共识本意是"不要四张不同颜色的地图"，当前实现恰好规避了这一点（四节令共享一张地图，差异来自参数与配色曲线）；
- 代价是牺牲了单季节的**深度**：没有地图规模、路线选择、区域差异，也没有完整 Boss 的流程设计（Boss 是 3 次调律的单场景遭遇）。

**结论性建议**：把「冬至 + 失律之蚊」视为第一个完整单季节 Demo 的候选核——它已有最低生存压力和唯一的 Boss 遭遇，扩展成"含路线选择的小地图 + Boss 遭遇"的完整关卡，成本最低、验证价值最高。

### 重点 4 · 角色身份成长 —— ⬜ 已确定未实现

**设计共识**（已确定）：玩家不知道自己是工蜂/雄蜂/王蜂/侦查蜂（游戏设定），通过经历逐渐意识到不同身份意味着不同责任；完全变态发育（卵→幼虫→蛹→成蜂）作为职业成长；不靠菜单，靠玩法。

**现状**：
- 代码中无任何身份系统（检索 `godot/` 无 identity/身份/工蜂/雄蜂等命中）；
- 现有的长翼/采蜜/守卫三选一本质是**分工倾向**，是身份概念的种子，但没有"身份"本身；
- 结算文案（"你没能带回花蜜，蜂巢的呼吸弱了一分"）已有责任归属感，但未点破身份。

**最小验证路径**（建议）：不做菜单化职业，而是在**结算时根据整局行为占比揭示身份**——采集多的局揭示"你更像采蜜蜂"，护卫多的局揭示"你更像守卫蜂"，全勤归巢但回避战斗的局揭示"你更像侦查蜂"。这会让"再来一局"产生新的动机（我想看看自己到底是谁），且零新增操作。

## 四、后续建议（按优先级）

### P0 · 1.0 MVP 门禁前（不新增玩法）
1. Windows 构建验证（macOS 已原生启动验证）；
2. 至少 5 名外部试玩者，收集 `docs/PLAYTEST.md` 模板数据；
3. 全流程验收对照 `MVP_SPEC.md` 第 9 节。

### P1 · 四个重点的下一步（第一个迭代周期，均可在现有工程上增量完成）
| 重点 | 建议动作 | 对应 PROJECT_LOG 候选 |
| --- | --- | --- |
| 操作循环 | 增加第二种行为差异明显的小怪（如受惊会呼救、或只偷不追的寄生虫型），让"战斗"出现抉择 | 候选 2 |
| 蜂巢成长 | 把公共储备变成**真实资源**：归巢结算的蜜可以花掉——选择哺育下一批幼虫（下次出巢增益）或加固蜂巢（Boss 前减伤），一次节令间决策 | 候选 4 |
| 单季节 Demo | 把「冬至 + 失律之蚊」扩展为含路线选择的小地图完整关卡 | 候选 3 + 5 合并 |
| 身份成长 | 结算时按行为占比揭示身份（见重点 4），先验证情感效果，再决定是否深化 | 新增 |

### P2 · 世界深度（单季节 Demo 验证通过后再做）
1. 节气驱动动态世界：花期、资源刷新、敌人迁徙挂到节气参数；
2. 雄蜂驱逐、幼虫变态发育等文学性内容进入流程；
3. 四 Boss 原型逐季落地（秋分画眉 → 夏至油葫芦 → 冬至熊）。
