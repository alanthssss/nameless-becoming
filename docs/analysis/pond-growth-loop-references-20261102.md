# 池岸归途0.18：一关体量、成长循环与开局参考

日期：2026-11-02（Asia/Shanghai）。状态：**分析提议，未实施新的关卡、美术、经济或成长系统。**

关联：[GDD§2、§13.6](../design/swarm-flight-gdd.md)／SF-R32内容体量 → [M4](https://github.com/alanthssss/nameless-becoming/milestone/4)／[#211](https://github.com/alanthssss/nameless-becoming/issues/211)，同时影响M3整体产品判断。沿用[原草稿PR #262](https://github.com/alanthssss/nameless-becoming/pull/262)和[唯一Now](../design/solar-term-campaign-production-spec.md#production-now)，不新增执行队列。

## 1. 本轮真正需要决定什么

**Alan实玩反馈：** 0.18有进步，但现有整段体量更适合作为一关，不能当作三关的内容量；花蜡灯画风不统一，是否应与跳舞形成舞池；返程区域元素过密，需要重设计。另以Shelldiver开局少量元素但收集、售卖、成长树相互承接的体验，提出本项目是否可采用类似体系，并明确要求“请先分析”。[原始截图及哈希](evidence/20261102-mvp-feedback/manifest.json)仅证明画面与反馈，不是逐键过程记录。

**本轮判断：** 将池岸出发、穿雨、返程作为一关里的三幕来讨论，更符合这次反馈；不按内部stage数量统计成品关数。关卡内容量还包含独立目标、动作发展、变化、选择和收束，不能只按分钟或世界宽度判断。当前不改存档、编号或正式24关目标，也不把24×本样板机械换算为已确认总时长/产能。0.17设计与节奏0分是历史产品裁定；0.18“有进步”是新的有限正面反馈，尚非整作或新成长方向被接受。

**首选研究方向：手工编排的飞行冒险＋轻量持续成长。** 关内飞行要成立，关外收获再为下一次飞行提供新目的。Shelldiver最有价值的参照是收益如何回流到后续行动；Mario和A Short Hike则帮助约束关内动作与探索。全部仍为设计假设。

## 2. 怎样使用这些游戏的“MVP”

本次主要研究成品开局、完整短循环和可压缩验证的结构，不能把它们统称为原作者的开发MVP。任天堂开发者明确说Super Mario Bros.的1-1在开发后期才制作，后来仍继续调整；早期移动图形/滚屏试验才是另一开发阶段。A Short Hike的作者复盘确认从新原型开始并限制初发版制作期限，但它也不是本项目工期的基准。

| 参考对象 | 值得研究的结构 | 对本项目的用法 | 不据此引入 |
| --- | --- | --- | --- |
| **Super Mario Bros.（1985）1-1及后续关卡** | 少量跑跳动作由地形、物件和遭遇不断改变用途；开场让操作与后果在场景里发生 | 一关提出一个清楚的动作问题，认识、变化、组合、收束；下一关有新的期待 | 地面跳跃参数、生命数或即时死亡；不能用加长同一障碍链替代发展 |
| **旷野之息：初始台地** | 可见目标、选择路线、取得能力、使用能力，阶段成果又打开更大的行动空间 | 一处区域容纳两种真正有效的飞法；成长后重新读懂之前看见的空间 | 整套开放世界、战斗、烹饪和装备系统 |
| **地铁跑酷：核心循环** | 自动前进下少量输入形成连续读路与修正；任务/倍率支持重复尝试 | 局部高速飞行段的预判、动作衔接、收集路径与安全路径取舍 | 全程自动前进、无尽高分或运营任务作为冒险主轴 |
| **神庙逃亡：核心循环** | 追赶情境立即说明为什么跑；转弯、跳、滑持续改变下一判断 | 一次短逃离或天气追赶段的即时目的与路况可读性 | 把追赶铺满全关、用最终必败的无尽结构替代完整归来 |
| **A Short Hike：完整小型冒险** | 清楚的远目标；沿主路或偏离探索、帮助旅人；移动本身有舒展和发现 | 最适合参照飞行探索的气质：目标明确，沿途有自主停留理由，登高/滑翔本身有回报 | 默认扩大为3D开放岛屿或堆满支线 |
| **Shelldiver：采集与增量循环** | 采集、出售、回投装备/技能与探索新环境相互承接 | 小量资源也能支持“下一次我想怎样飞/去哪里”的长期动机 | 照搬整棵树、用低效初始能力逼刷、用更大数字代替冒险内容 |
| **DAVE THE DIVER：外出与归来** | 潜水收获进入餐厅经营，收益用于后续探索；剧情和角色承接两种活动 | 行动带回东西，回家后发生可见结果；外出与归来的节奏不同 | 餐厅员工、菜单、战斗、养殖等完整多系统制作量 |

表中借鉴均为本轮推断，不是本项目效果验证。Subway/Temple的初版教程顺序和早期MVP未核实；不能编写“第一分钟必定怎样教”的历史。

## 3. Shelldiver像不像潜水员戴夫

**结构相似。** 官方介绍可确认Shelldiver以水母采集和小店出售为资源主线，其他海底材料可用于升级，分支技能树涉及氧气与商店等能力，不同海域/深度提供后续内容。Dave官方介绍则明确白天潜水、夜间经营寿司店，并把采集资源和餐厅收益投入装备。这支持共同循环：外出 → 获取 → 带回并转化 → 投入 → 更有能力再次外出。[Shelldiver官方](https://store.steampowered.com/app/3862670/Shelldiver/) · [Dave官方](https://store.steampowered.com/app/1868140/DAVE_THE_DIVER/)

**设计重心不同。** Shelldiver以incremental game介绍自己，资料重点在采集效率、分支升级和海域展开；Dave还明确把餐厅经营、冒险叙事和附加活动作为主要内容。可将前者理解为更聚焦成长回投的参照，将后者用于研究外出/归来两段如何互相供给。这是结构比较，不是证明作者直接借鉴，也不声称两者经营深度或精确操作过程相同。

Alan所说“开头元素不多”来自其实际游玩；本轮未亲自运行Shelldiver，未测它每项升级价格、解锁分钟、售卖操作量或实际分支最优策略。下面提炼的是可验证的设计机制：

1. **短期有动作。** 玩家当下能追逐、收取和决定继续还是返回。
2. **中期有这趟的目的。** 带回什么、在哪个限制出现时收手，有明确依据。
3. **长期有下趟的变化。** 收获投入后，玩家能更深入、更有效或采用不同做法。
4. **系统沿需求展开。** 玩家先遇到问题，再看见一种值得选择的解决办法；收集、售卖、升级不必同时用三张菜单教完。

“自然发散”的体验可以由清楚的因果关系产生，不代表系统会自动长出来。一棵画得很大的树若全是相似倍率，未必提供不同玩法；一项升级若只消除故意设置的繁琐，也未必增加乐趣。以上不是对Shelldiver某具体节点的贬评。

## 4. 对我们的体系：可以借，但要明确改变哪一层

现行GDD§2.1明确以熟练和认识为主，并将库存、经济经营、装备树排除出主循环。本次提问重新打开这个产品取舍，**授权分析，不等于已批准改型**。

| 方向 | 持续动力与代价 | 本轮意见 |
| --- | --- | --- |
| 继续纯关卡动作冒险 | 依靠新关卡、动作变式、发现和熟练；每份新增游玩较依赖手工编排 | 成立的可选方向；不能因为Shelldiver有树就认定必须加树 |
| **飞行冒险＋轻成长** | 关内保留手工体验；少量收获投入飞法、路线或伙伴，使后续行动发生变化；需要新增资源/成长/保存与跨关验证 | **优先做最小比较实验的候选**，仍未决定实施 |
| 增量采集经营为主 | 围绕重复采集、效率放大和资源回投设计；关卡/故事服务长期产出 | 是更大的类型变化，不能包装为小补丁，也不能沿用原关卡产能估计 |

建议验证的闭环：

> 飞出去，看见花源与路线 → 亲手选择飞法并带回少量收获 → 回巢交付/兑换 → 选择一次明确投入 → 新飞法或新通路可见 → 带着新目的再出发。

其中“售卖”的功能是把收获转成可自由分配的价值；未必需要独立经营小游戏。第一轮可直接用一种带回的花蜜存量作为投入资源，保留兑换表现但不另造第二套货币。若今后选择明确商店经济，再定义销售价格与购买货币；不能把花蜜、金币、好感都设成彼此兑换的同一计数。花蜜存量与飞行体力也应分开，避免“收集到的财富等于还能飞多久”的混乱。

成长有三种候选回报，但**第一轮只挑两个分支，不同时实现全套**：

- **探索能力：** 例如获得对某类风的控制方式，能去此前看得见的侧路；基础转向/冲刺手感在升级前就应合格。
- **采集选择：** 例如一次能兼顾两种花源，改变路线规划；不让初始采集故意迟钝，也不靠单纯增加悬停等待制造内容。
- **伙伴与路线：** 例如投入一处新落脚点，让伙伴可用、返程可改走；必须在世界中看见成果，不能只加列表图标。

具体能力、成本和回报尚未冻结。不预设所有关卡都要返回旧图或清光资源，也不能通过升级把雨路/风路等核心判断永久消解。

## 5. 真正值得做的最小验证

**提议：一关、一处归巢点、一种可带回资源、一次二选一成长，以及能看见差异的第二次出发。** 不是再做三关，也不先画几十个节点。第二次出发应出现新路径、新用途或明确不同的选择；重复同一路多跑几趟不能按新增内容计。

首轮只用现有飞行、叶棚和一处固定路线验证选择结果，不先做通用能力树或自由建造系统；具体可见障碍与第二趟变化留待原型规格明确。

第一次投入可以对照“学一种进入侧路的飞法”与“为另一条路线建设落脚点”：两者都改变下一次行动，暂不依赖纯数值优劣。主线基本完成能力不应被任意刷取费用卡住；回报与可选深入的关系需另行定义并验证。

| 待验证问题 | 应实际观察什么 | 失败信号与处理 |
| --- | --- | --- |
| 基础飞行是否独立成立 | 暂时不显示成长奖励时，玩家仍愿意主动尝试路线/动作 | 只有奖励数字引导才肯飞：回到关内体验，不继续扩树 |
| 是否理解这趟收获的用途 | 首次自然看到投入选择后，能说明想拿它做什么 | 只看见又一份配额：重做价值反馈与说明 |
| 升级是否改变下一趟 | 同一玩家再出发时出现新的路线/动作/投入计划 | 只有耗时更短或数字变大：不能宣称行动扩展已成立 |
| 是否形成自主再出发的理由 | 没有强制任务弹窗时，玩家提出具体的下一目标并愿意尝试 | 只是为了补齐树：检查目标与投入是否只剩清单 |
| 是否把现有体验拖成长工 | 重走路段有新观察/新用途，回巢操作短而清楚 | 原路刷取和菜单往返支配时间：削减循环摩擦，而非加更多节点 |

这些是后续原型的观察项，没有本轮真人结果、人数阈值或成功率，也不是新增硬门禁。归来后有明确终点与可退出状态仍须保留。

## 6. 两张截图所指的问题，也受同一原则约束

### 花蜡灯：先确定职责，再统一造型

[灯的原图](evidence/20261102-mvp-feedback/alan-wax-lamp.png)里，灯体是低对比彩格几何造型，而蜜蜂和叶片有更强描边、饱和度和手绘体积；悬挂彩球又容易让人预期舞厅灯效。当前源码在最后叶亭复用了`ColorMemory.draw_window`，颜色随段落状态变化；蜂舞则在蜡脾由另外的状态机触发。**当前不是响应舞步/节拍的灯球，也未实现舞池玩法。** [实际绘制](../../prototypes/swarm-flight/spring_journey_view.gd) · [提示/状态](../../prototypes/swarm-flight/spring_journey_model.gd)

建议先把它归为自然花蜡小灯，降低装饰竞争、统一笔触和材质。若选择将归巢交流处做成小聚场，灯光可以响应分享的开始与结束，但仍须明确为交流反馈；旋转闪耀球、节拍操作或音乐小游戏属于另一个机制提议，不因摆了彩球就自动加入。本轮不生成或替换素材。

### 返程过密：把挑战、休息与交流依次展开

[返程原图](evidence/20261102-mvp-feedback/alan-return-density.png)可同时看到牌架、三株高风花、左右叶亭、粗茎/横梁、花源、彩灯和邻居；可交互轮廓与粗支撑线互相抢位置。这些元素同时摆在一屏，没有清楚呈现更多有效选择，并有干扰主目标辨识的风险；实际影响待试玩核验。

重设计候选将重心依次展开：**开路动作完成 → 留出舒展飞行与清楚落点 → 花源/休息停留 → 最后蜂舞交流与归巢**。需要整体重排空间与视线；不是仅把每个坐标等距拉开。单屏优先读出一个主目标，次要发现可稍后显露；保留植物支撑和既有通行事实。实际宽度、镜头、同伴行走路径和小窗口可读性须在后续原生场景检验。本轮只提交方向，不能称截图问题已经修复。

## 7. 取舍、责任与下一检查点

本轮建议：把当前旅程视为“一关体量基准”；优先研究飞行冒险＋轻成长，先用两次有差异的出发验证循环。Mario提供关内变化，A Short Hike提供探索与移动目标，Shelldiver提供收益回投，Dave提供外出/归来的联系；跑酷作为局部段落参照。不能把每款游戏的一套系统都加入本作。

产品未决点是是否将经济/成长纳入主循环，及成长主要改变能力、路线还是采集效率。决策人Alan；Codex负责给出小范围原型规格与实现/验证成本后，再按确认方向执行。**本轮检查点为此分析交付，不自行开工、扩产或改正式商业范围。** 现行24关、200＋40小时、历史成本缺账、可靠剩余未知及PAUSED均保留；本轮采购0、图像生成0，未运行新游戏版本。
