# 《无名：成蜂》从可玩 Demo 到正式试玩版

基线：0.9.5-rc.1 私人 Web 构建（2026-08-20）

## 当前产品判断

当前版本是可完整运行的**垂直切片 Demo**：核心循环、四季机制、二十四节令、四位失律者、成长、失败与结算都可达，技术发布链路也已建立。它已经能回答“玩法能不能运行”，但尚未完成五名陌生玩家验证，视觉、音乐和首次理解成本也未达到公开试玩品质，因此不能称为 1.0 或正式 Demo。

## 完整流程审计

| 阶段 | 当前状态 | 主要风险 | 正式试玩目标 |
| --- | --- | --- | --- |
| Web 启动 | 能启动，无加载/失败反馈 | 玩家可能把等待误判为卡死 | 明确启动、加载、超时、重试与设备建议 |
| 首次教学 | 移动→采蜜→归巢的行为驱动教学已进入实现 | 仍需陌生玩家验证是否注意到情境卡片 | 完成一步才出现下一步，复杂动作在首次相关情境中解释 |
| 普通采集 | 核心贪撤成立 | 每个节令共享画面，差异感依赖数值 | 四季各有一项清晰机制与视听反馈 |
| 蜂巢成长 | 三选一有效 | 蜂巢成长仍像菜单增益 | 选择前后有蜂群变化与明确结果反馈 |
| 失律者 | 四种移动模式可达 | 登场、危险升级和归律演出不足 | 每位 Boss 有辨识动机、预告与结算节拍 |
| 失败/通关 | 路径完整 | 首局后是否愿意重开尚无数据 | 用真实试玩验证重开意愿，不靠加文案推测 |

## 音乐与声音策略

现有系统已经具备四季独立五声音阶旋律及采蜜、归巢、惊退、受伤、成长、调律、胜负提示音。下一阶段不为 24 个节气各写一首歌，而采用“季节主题 × 情境层”的结构：

| 层级 | 数量 | 用途 |
| --- | ---: | --- |
| 四季基础主题 | 4 | 保持季节连续性，普通采集低密度播放 |
| 蜂巢安全层 | 1 | 归巢、成长、分配时降低节奏与威胁 |
| 危险层 | 1 组动态声部 | 敌害靠近、体力告急时叠加，不切断基础主题 |
| 失律者动机 | 4 | 每位 Boss 使用独立节奏/音色动机，可基于季节主题变奏 |
| 转场短句 | 5～7 个 | 节令完成、Boss 登场、归律、失败、通关 |

正式作曲前需要确定乐器与审美方向；程序化音乐继续承担功能验证，不伪装成最终音乐。

## 美术与界面策略

正式试玩需要统一设计，但应先做视觉系统，再批量画资产。优先顺序：

1. 定义四季色彩、线条、材质、阴影、字体和动效规则；
2. 重做蜜蜂、花、蜂巢、五类敌害和四位失律者的轮廓语言；
3. 统一标题、HUD、节令过渡、成长、Boss 登场和结算页面；
4. 最后制作装饰背景、粒子和高成本插画。

正式资产清单至少包含：玩家 1 套、蜂巢 3 状态、四季花型 8～12 个、普通敌害 5 类、Boss 4 位、共鸣点 4 套、季节过渡 4 套、核心反馈特效 8 类、页面图标与光标 1 套。

## 实施优先级

### P0：进入外部试玩前必须完成

- Web 启动加载、失败和重试反馈；
- 首次教学按行为依次展示移动、采蜜、归巢三步；系统操作只在暂停层出现；
- 清理工程/MVP 语气，统一称“可玩垂直切片 / 私人试玩构建”；
- 完整人工流程一轮并填写耗时、阻塞点和明显误解；
- 为五名试玩建立不诱导的记录流程。

### P1：首轮试玩暴露问题后完成

- HUD 信息层级、危险反馈和节令转场正式设计；
- 音乐加入安全、危险和 Boss 情境层；
- 四季与四位失律者建立可辨识的美术轮廓；
- 调整重复节令与整局时长。

### P2：公开试玩前完成

- 最终/接近最终的角色、敌害、花与场景资产；
- 完整混音、音量设置和设备兼容；
- 首屏社交预览、公开发布文案、隐私与反馈入口；
- Windows 真机和至少五名外部试玩达到验收门槛。

## 需要用户参与的决策

当前开发不需要暂停。进入 P1 前只需要用户完成两类输入：

1. 从“东方版画 / 剪纸几何 / 自然手账 / 现代扁平”中确定一个主视觉方向，或提供 3～5 张参考图；
2. 提供 2～4 首音乐参考，分别代表希望的“安全、采集、危险、失律者”气质。

其余工程、测试、文档、构建和私有部署由开发流程继续完成。
